# protocol-timeline-assert — R3 cocotb auto-gen testbench

Auto-generate a cocotb testbench that deterministically catches half-duplex bus turnaround violations at simulation time. This is the highest-ROI prevention item (~95% confidence).

## Problem

A fresh agent generating RTL for a half-duplex protocol often omits the response delay state in the dispatcher FSM. The RTL passes lint, passes basic testbenches (which test RX-only or TX-only), and even passes synthesis. The bug only manifests on real hardware when the RX→TX transition overlaps with the delimiter assertion.

This skill generates a cocotb test that catches this at simulation time, eliminating the need for hardware to detect the bug.

## When to Use

1. **Automatically** after `spec-to-rtl` for any IC with half-duplex protocol
2. When user says "turnaround test", "timeline assert", "generate turnaround TB"
3. After a hardware FAIL diagnosed as turnaround violation — to prevent regression

## What It Generates

A cocotb test file (`test_turnaround_timeline.py`) that:

1. **Drives a complete inbound frame** using the project's protocol model from L1/L2
2. **Drives the trailing-delimiter** assertion with realistic typical duration from L2
3. **Records the timestamp** when the TX-start-class signal rises (or when the first device-driven assertion appears on the bus)
4. **Asserts turnaround timing**:
   ```
   tx_start_time - delimiter_release_time ∈ [t_turnaround_min, t_turnaround_max]
   ```

### Generated Test Structure

```python
# test_turnaround_timeline.py — auto-generated by protocol-timeline-assert
import cocotb
from cocotb.clock import Clock
from cocotb.triggers import RisingEdge, FallingEdge, Timer

@cocotb.test()
async def test_rx_tx_turnaround(dut):
    """Assert turnaround gap between RX frame end and TX response start."""
    clock = Clock(dut.clk, CLOCK_PERIOD_NS, units="ns")
    cocotb.start_soon(clock.start())

    # Reset
    dut.rst_n.value = 0
    await Timer(100, units="ns")
    dut.rst_n.value = 1
    await RisingEdge(dut.clk)

    # Drive inbound frame on bus
    # (generated from L1/L2 protocol model — frame bytes, timing, delimiter)
    await drive_inbound_frame(dut, CMD_BYTES, BIT_TIMING)

    # Drive trailing delimiter with realistic duration
    await drive_delimiter(dut, DELIMITER_TYPICAL_DURATION_NS)

    # Record delimiter release time
    delimiter_release_ns = cocotb.utils.get_sim_time(units="ns")

    # Wait for TX start (with timeout)
    tx_start_ns = await wait_for_tx_start(dut, TX_START_SIGNAL, TIMEOUT_NS)

    # Assert turnaround
    turnaround_ns = tx_start_ns - delimiter_release_ns
    assert T_TURNAROUND_MIN_NS <= turnaround_ns <= T_TURNAROUND_MAX_NS, \
        f"Turnaround = {turnaround_ns}ns, expected ∈ [{T_TURNAROUND_MIN_NS}, {T_TURNAROUND_MAX_NS}]ns " \
        f"(spec_ref: {SPEC_SECTION})"
```

### Required Constants (extracted from L2 timing JSON)

| Constant | L2 JSON Field | Description |
|----------|---------------|-------------|
| `CLOCK_PERIOD_NS` | `clock.period_ns` | Fabric clock period |
| `DELIMITER_TYPICAL_DURATION_NS` | `delimiter.typical_ns` or `break.typical_ns` | Typical delimiter width |
| `T_TURNAROUND_MIN_NS` | `turnaround.min_ns` or `tSRS.min_ns` | Minimum turnaround gap |
| `T_TURNAROUND_MAX_NS` | `turnaround.max_ns` or `tSRS.max_ns` | Maximum turnaround gap |
| `TX_START_SIGNAL` | Auto-detected from RTL | Signal name for TX start |
| `SPEC_SECTION` | L2 `spec_ref` field | Spec reference for error message |

## How to Use

### Step 1 — Locate L2 timing JSON

```bash
# Find L2 timing in the project
find . -name "L2_*.json" -o -name "L8_TIMING*.json"
```

### Step 2 — Extract turnaround parameters

The skill reads L2 JSON and extracts turnaround-class parameters by matching field names against:
```
/t.?(srs|response.?delay|turnaround|bus.?guard|reply.?gap)/i
```

### Step 3 — Generate cocotb test

The skill generates `sim/test_turnaround_timeline.py` with all constants filled from L2.

### Step 4 — Run

```bash
cd sim/
make SIM=icarus TOPLEVEL=<dtop> MODULE=test_turnaround_timeline
```

## Failure Message

When the turnaround is too short:
```
AssertionError: turnaround = 1200ns, expected ∈ [80000, 100000]ns (spec_ref: Section 8.3.2 Response Timing)
```

This message gives the agent everything needed to:
1. Know the turnaround is too short (1.2us vs 80-100us required)
2. Find the spec section to understand the requirement
3. Add a delay state in the dispatcher FSM

## Confidence

~95% — deterministic. Any RTL violating the turnaround budget fails this test in simulation, no hardware needed. The only miss case is if the bus model doesn't accurately represent the physical bus behavior (e.g., analog settling effects).

## Dependencies

- cocotb 1.8+
- Icarus Verilog or Verilator
- L2 timing JSON with turnaround parameters
- RTL with identifiable TX-start and RX-done signals
