## §1 — Genuine hallucinations (schema-independent, REAL)

These reproduce in the fresh v0.1.57 run and are the highest-value findings:

1. **`ic_name = "SUCH ARM TECHNOLOGY"` in all 14 L-docs.** Lifted from the license
   clause "…USE OR IMPLEMENTATION OF SUCH ARM TECHNOLOGY WILL NOT INFRINGE…".
   Correct: `AMBA AXI and ACE Protocol Specification`. The boilerplate name then
   propagates into every L-doc because they share the L1 `ic_name`.
2. **`opcode_hex = "0x16"` in L10_TEST_CASES** — a page-format number lifted as an
   8-bit opcode. AXI has zero 8-bit opcodes (it is a 5-channel concurrent
   valid/ready protocol). The OTP-centric L3/L10 schema *assumes* opcodes exist.

Both pass `--source` grounding (the strings physically exist in the PDF) yet are
semantically wrong — the classic "doc-grounded but mis-attributed" failure.

## §2 — Why "343 absent" overstates the gap: incompatible schemas

The runner and Claude emit **structurally different JSON**:

| | Program (runner) | Claude (Opus 4.7) |
|---|---|---|
| L3 top keys | `opcodes, crc_parameters, verdict_byte_hex, no_*_in_input …` (OTP/chip template) | `{doc_id, extraction_source, fields, evidence}` wrapper |
| AXI facts live in | (no home — schema has no burst/resp/handshake slot) | `fields.burst_type_encodings, fields.response_encodings, …` |

The comparator does a **top-level key-set diff**, so for the data-rich docs nearly
every Claude key registers as ABSENT: L3 55/55, L8_RTL_CONSTANTS 93/93, L8_TIMING
25/25, L6 20/20, L12 16/16 (absent == agent_keys exactly). This is **schema-shape
divergence**, not proof the facts were never extractable. Real fact-level loss
can't be measured until both sides share a schema.

The runner's L1-L13 schema is **OTP/chip-centric** (opcodes, CRC, verdict-byte,
trim) — a poor fit for a bus-protocol spec. That mismatch is the root cause behind
both the over-padding and the under-extraction below.

## §3 — L14-L23 are NOT runner output

The fresh v0.1.57 runner emits **L1-L13 + L8_TIMING_WAVEFORM only (14 docs)**.
The L14-L23 files in `generated_docs/` are **stale** (mtimes 05:04–05:41 vs L1 at
12:47, this run). So:

- **L14-L18** (PROTOCOL_VERSIONING / ENCODING_TABLES / COMPLIANCE_PROPERTIES /
  CHANNEL_SIGNAL_CATALOG / INTERCONNECT_TOPOLOGY) — the taxonomy extension proposed
  in `TAXONOMY_GAP_ANALYSIS.md` — **were never implemented in the runner**. Their
  low absent / nonzero value_mismatch counts come from a prior hand-built session,
  not from this run. The runner has **no extractor** for any AXI versioning,
  encoding-table, compliance-property, channel-catalog, or interconnect fact.
- **L19-L23** (CONSTRAINTS_PDK / DFT / POWER_INTENT / VERIFICATION_PLAN / SECURITY):
  program emits **200–550-byte stubs**; Claude correctly **omits them entirely**
  (agent_bytes = 0). For a protocol spec these L-docs are N/A — emitting a stub is
  the "hallucinate-a-stub-for-an-inapplicable-L-doc" failure the gap analysis flagged.

## §6 — Bottom line

The runner's v0.1.57 Phase-1 doc track is built around an **OTP/chip taxonomy** and
does **not** fit a bus-protocol spec:
- 2 confirmed hallucination classes (boilerplate ic_name, phantom opcode).
- No home for the genuine AXI facts (burst/resp/size encodings, channel catalog,
  4KB-boundary & VALID-stickiness compliance rules, AXI3/4/5 version deltas).
- Emits stub L-docs for inapplicable categories instead of marking them N/A.

The fixes are exactly the three items in `TAXONOMY_GAP_ANALYSIS.md` (still un-started
in v0.1.57): (1) `ic_class → applicable_L_docs` map, (2) L14-L18 schemas + extractors,
(3) `bus_interconnect_protocol` ic-class detector — plus a license-clause grounding
guard for the ic_name hallucination.
