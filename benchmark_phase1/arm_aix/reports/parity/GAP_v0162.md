### Why ABSENT_IN_PROGRAM went UP +18

This is exactly the limitation user flagged in GAP_v0157:

> "比對器做的是頂層 key 集合 diff，所以資料密集的 doc 幾乎每個 Claude
> 欄位都被算成 absent"

R14 adds 5 new program docs (L14-L18). Each docs has a different
top-level key schema than Claude's hand-extracted equivalent. Each Claude
key not present in the program's schema counts as +1 ABSENT. So 5 new
docs × ~5 schema-shape mismatches = +25 ABSENT. Offset by R13 dropping
~-7 ABSENT (clean na_stubs no longer fake-match Claude's per-doc keys).

The +25 is NOT a regression — it's the parity tool counting structural
schema differences that v0.1.62 made visible by populating the docs at
all. Before v0.1.62 those docs were empty stubs so Claude's keys still
counted as absent (because the program didn't have them either). Now
they're populated but with a different SHAPE.

**The honest fix for the metric is a schema-normalized parity diff** (R15
candidate, deferred): map equivalent fields across schemas before
counting key-set differences. Until that lands, `total findings` count
under-reports the v0.1.62 quality improvement.

## Doctrine notes

All three v0.1.62 captures share a pattern:

| Capture | Infrastructure age | Why was it dead? |
|---|---|---|
| R11 (v0.1.60) | scrubber existed since v0.1.51 | runner never called it |
| R12 | applicability map existed since v0.1.51 | no consumer (R13's job) |
| R13 | `is_applicable`/`na_stub` existed since v0.1.51 | no consumer |
| R14 | extractor existed since v0.1.51 | runner never called it |

Pattern: **v0.1.51 shipped 4 deterministic helpers but never wired them
into the runner pipeline**. v0.1.60-v0.1.62 closed the loop by adding
~30 lines of integration code per helper at the `_write_l_doc` chokepoint
+ main driver. The substantive content (regex catalogs, applicability
map, scrubber rules) already existed; only the call sites were missing.

Doctrine: when adding a new helper, ALWAYS land the call site in the same
release — otherwise the helper sits as dead code waiting for a future
parity run to discover the gap.
