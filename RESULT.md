## On "regenerate, don't type" — where that advice does not apply

The relay warned that a regenerated pin must be re-derivable, not typed. That is
right for the anchored figures and wrong for the tripwires, and the files say so
themselves:

> Pinned census of the yaml as measured on 2026-07-27. These are **TRIPWIRES,
> not the definition**: every structural assertion below derives its expectation
> live from the yaml. If the flow legitimately changes, these numbers change
> with it in ONE place and the reviewer is forced to look.

Deriving the tripwire from the same yaml the assertion reads makes the assertion
tautological and lets the ledger drift in silence — the disease these files were
written against. So:

* **anchored figures** (42 of them) — regenerated by the repo's own command,
  `tools/gen_matrix_63x8_census.py --fix-figures`. `--check-figures` now PASSES
  with 57 anchored figures re-derived.
* **tripwires and population tuples** — moved by hand in one place, each with the
  measured derivation recorded beside it. Where a file names its own derivation
  (`[k for k in step_ids() if len(required_outputs(k)) < 2]`) the tuple is
  RE-DERIVED and pasted whole, never appended to, because the file records that
  appending is how v1.10.38 shipped a 28-entry pin over a 27-step population.

## The three findings this branch reports rather than repairs

**1. `test_a_readable_artefact_that_is_wrong_...` — NEWLY BLIND `['1.6x']`.**
The test says in its own message that this "must be fixed, not pinned", and it
is right. Step 1.6x's ONLY declared `required_output` is
`reports/crosslayer/rewrite_equivalence_check.json` — the checker's own report —
so corrupting it cannot move a verdict the checker computes. The artefact the
gate actually reads, the producer's `rewrite_equivalence.json`, is not declared
and cannot simply be declared: the step is unconditional by design (its yaml
records that a `files_exist` condition was refused as *"a check disabled by
exactly the situation it was written for"*) and a design that ran no cross-layer
search produces no such report. Closing it needs the flow to express a
*conditionally-required* output, which it has no way to say today.

**This one red is load-bearing.** While any red sits outside the matrix cell
join the nested outcome run is NORECORD, which blocks the generated census block
and the four coverage IDs behind it. The blocker set went **8 -> 3 -> 1** across
this branch; that last one gates six of the seventeen.

**2. `test_d7_required_outputs_list_is_complete[step31]` — bucket B, one line.**
Step 31 declares seven outputs and not `reports/phase3/drc_signoff.json`, which
`drc_report_check` writes and `general_precheck` reads. The fix is to declare it.
NOT DONE HERE, deliberately: adding a `required_outputs` entry moves
`required_output_entries` 162 -> 163 and `FILE` 120 -> 121, which reddens the
ledger pins this branch just set, and may redden d3 for step 31 if no published
run carries the artefact. That is a measurable knock-on across the whole family
and it wants its own change with its own re-measurement, not a rider on this one.

**3. `1.6x/d3` and `0.5ic/d3` carry no measured mutation.** Both cells are
ENFORCED. `--replay D3-UNDECLARED-ARTEFACT --step 1.6x` is `NOT_REPLAYABLE` with
no corpus (the witness skips) and `ALREADY_RED` with one (`baseline_rc=1` — the
step's declared output exists in no published run). A mutation cannot be measured
on a cell that is red before the edit, and the ledger's own vocabulary says so.
Three mutation-ledger IDs count those two cells and stay red, named rather than
absorbed.

## The bucket-D entry, and why it is not "green when serial"

`test_live_collection_relays_finite_semantic_progress_past_old_bound` was the
one ID already green in the serial reproduction. It is timing-sensitive: it
sleeps 0.14 s seven times and asserts against a 0.3 s bound. Measured in
isolation it failed 2 of 3 runs at load average ~35, and passed 6 of 6 once the
host was quiet. So it is a harness/load artefact, but it is **not** the
xdist tree-mutation race the brief anticipated, and calling it "green serially"
would be wrong — it is nondeterministic. It is in neither the fixed nor the
unfixed count.
