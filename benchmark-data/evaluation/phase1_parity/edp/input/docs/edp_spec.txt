VESA Embedded DisplayPort (eDP) Standard
Embedded DisplayPort (eDP) — Internal Panel Digital Display Interface

Video Electronics Standards Association (VESA)
Embedded DisplayPort (eDP) Standard, Version 1.4b / 1.5 (consolidated
internal-panel digital-display interface reference, building on the VESA
DisplayPort base specification)

================================================================================
1. OVERVIEW
================================================================================

Embedded DisplayPort (eDP) is the VESA digital display interface for the
INTERNAL panel connection inside a notebook, tablet, all-in-one (AIO), or
embedded system. eDP connects an on-board display Source (the GPU / SoC display
controller) to the INTEGRATED panel (the eDP Sink / Timing Controller, TCON)
over a short internal flex cable, replacing the legacy internal LVDS panel
interface.

eDP is built on the VESA DisplayPort base specification and reuses the same
three functional channels:

  * Main Link  — a uni-directional, high-bandwidth, isochronous channel that
                 carries the video stream from the Source to the panel Sink.
                 The Main Link is made of 1, 2, or 4 lanes, each a self-clocked
                 AC-coupled differential pair, exactly as in DisplayPort.
  * AUX CH     — a bidirectional, half-duplex, low-bandwidth auxiliary channel
                 used for link management: reading and writing the panel's
                 DisplayPort Configuration Data (DPCD) register space, link
                 training control, EDID retrieval via I2C-over-AUX, AND — UNIQUE
                 to eDP — backlight brightness control over AUX and Panel Self
                 Refresh control.
  * HPD        — Hot Plug Detect, a sideband signal driven by the panel Sink to
                 inform the Source of presence and of interrupt events (IRQ_HPD)
                 such as link-status change or a Panel-Self-Refresh state change.

Because the panel is embedded (the Source and Sink are co-designed on one board,
connected by a known fixed flex cable), eDP DROPS the external-connector
features of DisplayPort — there is NO external connector, NO Multi-Stream
Transport (MST) / multi-monitor daisy chain, NO hot-pluggable cable orientation —
and ADDS a set of eDP-EXCLUSIVE power-saving and panel-control features that an
external DisplayPort link does not have:

  * Panel Self Refresh (PSR) and PSR2  — the panel keeps a local copy of the
    last frame in a Remote Frame Buffer (RFB) and refreshes the display from the
    RFB while the Source GPU and the Main Link sleep.
  * Backlight control over AUX  — panel backlight brightness is set through
    eDP backlight DPCD registers (PWM frequency/duty and AUX brightness), not a
    separate signal.
  * Fast Link Training (FLT)  — an abbreviated link-training sequence for an
    embedded panel whose channel is fixed and characterized.
  * ASSR (Alternate Scrambler Seed Reset)  — eDP's content-protection scrambler
    seed, used in place of the standard DisplayPort scrambler seed for embedded
    panels.

eDP is therefore the EMBEDDED variant of DisplayPort: the same Main Link / AUX /
DPCD / two-phase link-training base, PLUS PSR/PSR2 + RFB + backlight-over-AUX +
ASSR + Fast Link Training + an eDP-specific DPCD register block, MINUS the
external-connector / MST features.

================================================================================
2. MAIN LINK — LANES, RATES, AND CHANNEL CODING (shared with DisplayPort)
================================================================================

2.1 Lane count
The eDP Main Link is configurable to 1, 2, or 4 lanes. The negotiated lane count
is written to the LANE_COUNT_SET field of the DPCD. An embedded panel typically
uses 1, 2, or 4 lanes (ML_Lane0..ML_Lane3), each a differential pair
(ML_Lane0+/ML_Lane0- ... ML_Lane3+/ML_Lane3-) routed on the internal flex.

2.2 Link rates (link symbol rates per lane)
The Main Link operates at one of the standardized DisplayPort link rates. The
selected rate is written to the LINK_BW_SET field of the DPCD (or LINK_RATE_SET
for the higher rates):

  RBR  (Reduced Bit Rate) ........ 1.62 Gbps/lane   (8b/10b)
  HBR  (High Bit Rate) ........... 2.70 Gbps/lane   (8b/10b)
  HBR2 (High Bit Rate 2) ......... 5.40 Gbps/lane   (8b/10b)
  HBR3 (High Bit Rate 3) ......... 8.10 Gbps/lane   (8b/10b)

eDP also defines a set of intermediate eDP link rates for panel power
optimization, indexed through the eDP-specific supported-link-rates DPCD table,
but RBR/HBR/HBR2/HBR3 remain the canonical 8b/10b rates.

2.3 Channel coding
For RBR/HBR/HBR2/HBR3 the Main Link uses ANSI 8b/10b coding: each 8-bit
character is encoded into a 10-bit DC-balanced, transition-rich symbol so the
panel Sink can recover the embedded link clock. The effective data efficiency of
8b/10b is 80%. The data is scrambled with an LFSR; on an eDP link the scrambler
is reset using the ASSR (Alternate Scrambler Seed Reset) seed instead of the
standard DisplayPort seed when ASSR is enabled (eDP_CONFIGURATION_CAP).

2.4 Symbols and control characters
8b/10b control (K) symbols frame the stream: BS (Blanking Start), BE (Blanking
End), SR (Scrambler Reset), SS/SE (Secondary-data Start/End), FS/FE (Fill
Start/End), and the training pattern symbols. The blanking period between active
video lines carries the Main Stream Attributes (MSA) and secondary-data packets.

================================================================================
3. LINK TRAINING — FULL AND FAST LINK TRAINING
================================================================================

Before video can be transmitted the Source must train the Main Link so that the
panel Sink reliably recovers the data on every active lane. Link training is
performed over the AUX channel by writing the TRAINING_PATTERN_SET DPCD register
and reading back the LANE0_1_STATUS / LANE2_3_STATUS / LANE_ALIGN_STATUS_UPDATED
registers. Full link training proceeds in two phases (as in DisplayPort):

3.1 Clock Recovery (CR) phase
The Source transmits Training Pattern 1 (TPS1) on the Main Link and adjusts each
lane's transmit VOLTAGE SWING level and PRE-EMPHASIS level based on the
ADJUST_REQUEST values the Sink reports in DPCD. The phase succeeds when every
active lane reports CR_DONE (clock recovery locked). eDP defines 4 voltage-swing
levels (Level 0..3) and 4 pre-emphasis levels (Level 0..3), with bounded
swing+pre-emphasis combinations.

3.2 Channel Equalization (EQ) phase
The Source transmits Training Pattern 2/3/4 (TPS2/TPS3 for 8b/10b rates, TPS4
for HBR3) and the Sink reports CHANNEL_EQ_DONE, SYMBOL_LOCKED, and
INTERLANE_ALIGN_DONE. When all three are set on all active lanes, EQ succeeds and
the link is trained.

3.3 Fast Link Training (FLT)
Because an embedded panel's channel is fixed and characterized at design time,
eDP defines FAST LINK TRAINING: the Source skips the iterative CR/EQ adjustment
and directly applies a previously-stored set of drive settings (voltage swing /
pre-emphasis) and rate/lane configuration, sending the training patterns for a
short fixed interval. Fast Link Training is selected via the eDP DPCD
configuration (the eDP_CONFIGURATION_CAP / FAST_LINK_TRAINING capability). This
dramatically shortens panel power-on and PSR exit latency. If Fast Link Training
fails, the Source falls back to full CR/EQ link training, and on persistent
failure falls back to a lower link rate and/or fewer lanes.

================================================================================
4. AUX CHANNEL (shared base with DisplayPort)
================================================================================

4.1 Electrical and coding
The AUX channel is a single bidirectional, half-duplex differential pair
(AUX+/AUX-). It is AC-coupled and uses Manchester-II bi-phase encoding at a
nominal 1 Mbps. A request/reply transaction model is used: the Source (AUX
master) issues a request; the panel Sink (AUX slave) returns a reply. Each
transaction begins with a SYNC pattern (a preamble of consecutive zeros) and a
START/STOP condition delimiting the Manchester-coded payload.

4.2 Native AUX transactions
Native AUX transactions read or write the panel's DPCD address space. The request
carries:
  * a 4-bit command (AUX command): native Read (1001b) / native Write (1000b),
    and I2C-over-AUX Read/Write/MOT variants;
  * a 20-bit address into the DPCD / I2C address space;
  * a length field (number of bytes minus one, 0..15 -> 1..16 bytes per
    transaction).
The reply carries a 4-bit AUX reply command: ACK / NACK / DEFER (and the
I2C-over-AUX equivalents I2C_ACK / I2C_NACK / I2C_DEFER).

4.3 DPCD — DisplayPort Configuration Data (with eDP-specific block)
DPCD is the panel Sink's configuration/status register space, accessed by native
AUX read/write. Key DPCD regions reused from DisplayPort:
  * Receiver Capability field (base address 00000h): DPCD_REV, MAX_LINK_RATE,
    MAX_LANE_COUNT, MAX_DOWNSPREAD, supported training patterns, FEC/DSC caps.
  * Link Configuration field (base address 00100h): LINK_BW_SET, LANE_COUNT_SET,
    TRAINING_PATTERN_SET, TRAINING_LANE0_SET..LANE3_SET, DOWNSPREAD_CTRL.
  * Link/Sink Status field (base address 00200h): SINK_COUNT, LANE0_1_STATUS,
    LANE2_3_STATUS, LANE_ALIGN_STATUS_UPDATED, ADJUST_REQUEST_LANE0_1/2_3.

eDP adds an EMBEDDED-DISPLAYPORT-SPECIFIC DPCD register block (base address
00700h, the "eDP-specific DPCD" / eDP Configuration Capability region):
  * eDP_DPCD_REV — eDP revision (1.4 / 1.4b / 1.5).
  * eDP_CONFIGURATION_CAP — capability flags: ASSR support, Fast Link Training
    support, OUI support, alternate-scrambler-seed enable.
  * eDP_GENERAL_CAP — PSR / PSR2 capability, backlight-adjustment capability,
    frame-buffer capability.
  * eDP backlight registers — EDP_BACKLIGHT_MODE_SET, EDP_BACKLIGHT_BRIGHTNESS
    (MSB/LSB), EDP_PWMGEN_BIT_COUNT, EDP_BACKLIGHT_FREQ_SET, regional backlight.
  * PSR registers — PSR_ENABLE / PSR2_ENABLE, PSR_CONFIGURATION, PSR_STATUS,
    selective-update (SU) region, RFB (Remote Frame Buffer) control.

4.4 I2C-over-AUX and EDID
The panel's EDID (Extended Display Identification Data) is reached by tunneling
I2C transactions over AUX. The Source issues I2C-over-AUX read/write transactions
(with the MOT — Middle-Of-Transaction — bit to chain a multi-byte I2C burst)
addressed to the EDID I2C slave address (A0h/A1h). The 128-byte (or extended)
EDID block describes the panel's supported timings and capabilities.

================================================================================
5. PANEL SELF REFRESH (PSR / PSR2) AND THE REMOTE FRAME BUFFER (eDP-EXCLUSIVE)
================================================================================

5.1 The Remote Frame Buffer (RFB)
The DEFINING eDP power-saving feature is Panel Self Refresh (PSR). The panel
(eDP Sink / TCON) contains a local Remote Frame Buffer (RFB) that can store a
complete copy of the last transmitted video frame. When the displayed image is
static, the Source can stop transmitting on the Main Link and the panel refreshes
itself from the RFB. This lets the GPU display engine, the Main Link PHY, and
much of the Source clock tree power down for the duration that the screen is
static — a major battery saving for a notebook or tablet.

5.2 PSR entry and exit
  * PSR ENTRY: the Source writes PSR_ENABLE / PSR_CONFIGURATION in the eDP DPCD,
    transmits a final frame, asserts a PSR-entry indication, and then quiesces
    the Main Link. The panel latches the last frame into the RFB and begins
    self-refreshing from the RFB.
  * PSR ACTIVE: the Main Link is idle / electrically quiescent; the panel
    refreshes from its RFB; the Source GPU may sleep.
  * PSR EXIT: on a screen update (or an IRQ_HPD), the Source re-establishes the
    Main Link (using Fast Link Training where possible), re-transmits the updated
    frame, and the panel returns to live (externally-driven) refresh.
The panel reports its PSR state in the eDP PSR_STATUS DPCD register.

5.3 PSR2 and selective update
PSR2 extends PSR with SELECTIVE UPDATE: instead of re-transmitting the entire
frame on exit, the Source transmits only the changed rectangular region(s)
(Selective Update, SU region) into the RFB, further reducing Main Link activity
for small on-screen changes such as a blinking cursor or a clock. PSR2 also adds
frame-locking and early-transport options. PSR2 capability and configuration live
in the eDP DPCD (PSR2_ENABLE / PSR2 capability fields).

================================================================================
6. BACKLIGHT CONTROL OVER AUX (eDP-EXCLUSIVE)
================================================================================

eDP integrates panel BACKLIGHT control into the interface. Rather than a separate
backlight-control wire, the Source sets the panel backlight brightness through eDP
backlight DPCD registers over the AUX channel:

  * EDP_BACKLIGHT_MODE_SET selects the backlight control mode (PWM pin, AUX
    brightness via DPCD, or a combination).
  * EDP_BACKLIGHT_BRIGHTNESS_MSB / _LSB set the AUX-controlled brightness level.
  * EDP_PWMGEN_BIT_COUNT and EDP_BACKLIGHT_FREQ_SET configure the panel PWM
    generator frequency and resolution.
  * Regional / local backlight (e.g. for local-dimming HDR panels) is configured
    through additional eDP backlight registers.

The backlight PWM may be generated by the panel (TCON) under AUX/DPCD control, or
driven on a dedicated backlight PWM pin whose duty cycle the Source adjusts. This
AUX backlight control is UNIQUE to eDP — an external DisplayPort monitor manages
its own backlight internally and exposes no such interface.

================================================================================
7. ASSR — ALTERNATE SCRAMBLER SEED RESET (eDP-EXCLUSIVE CONTENT PROTECTION)
================================================================================

eDP defines ASSR (Alternate Scrambler Seed Reset) as a lightweight embedded-panel
content-protection / link-robustness mechanism. When ASSR is enabled (advertised
in eDP_CONFIGURATION_CAP and enabled in the eDP DPCD), the Main Link LFSR
scrambler is reset with an ALTERNATE seed value instead of the standard
DisplayPort scrambler seed. A panel that supports ASSR will only correctly
descramble a stream from a Source that uses the alternate seed, providing a
basic measure of content protection between the co-designed Source and embedded
panel without the full HDCP machinery. ASSR is negotiated during eDP link setup;
if the Sink does not support ASSR the Source uses the standard scrambler seed.

================================================================================
8. MAIN STREAM ATTRIBUTES, TRANSFER UNITS, AND THE MICRO-PACKET STREAM
================================================================================

8.1 Main Stream Attributes (MSA)
The MSA is a packet, transmitted once per video frame in the vertical blanking
interval, that describes the video stream: Mvid and Nvid (the time-stamp pair
used by asynchronous clocking to regenerate the pixel clock from the link clock),
Htotal/Vtotal, HSP/HSW, active width/height, MISC0/MISC1 (color format, bit
depth, dynamic range, colorimetry). eDP also supports a video-stream-clock mode
where the panel can run its own timing during PSR.

8.2 Transfer Units (TU)
The active video data of each scan line is packed into Transfer Units. A TU is a
fixed number of link symbols (typically 32 or 64 symbols per lane); within each
TU only as many symbols as required by the ratio of pixel rate to link rate are
filled with active data, and the remainder is stuffed (Fill).

8.3 Micro-packet framing
Active line data is delimited by BS (Blanking Start) and BE (Blanking End)
control symbols. Secondary-data packets (audio sample packets, MSA, VSC SDP /
extended InfoFrames, PSR setup packets) are carried in the blanking intervals
delimited by SS/SE.

================================================================================
9. PINS / INTERNAL FLEX CONNECTION
================================================================================

An eDP internal panel connection (flex cable / board-to-board connector)
exposes:
  * ML_Lane0(+/-), ML_Lane1(+/-), ML_Lane2(+/-), ML_Lane3(+/-) — up to four Main
    Link differential pairs (AC-coupled, self-clocked, embedded clock; 1/2/4
    used per panel).
  * AUX_CH(+/-) — one bidirectional half-duplex differential pair (Manchester-II,
    1 Mbps) for DPCD / link-training / I2C-over-AUX / backlight / PSR control.
  * HPD — Hot Plug Detect, a single-ended sideband input to the Source.
  * BL_PWM / BL_EN — optional backlight PWM and enable (when the backlight is not
    fully AUX-controlled).
  * VDD (panel logic), VBL (backlight), GND — panel and backlight power and
    ground.
There is NO external DisplayPort connector and NO cable-orientation / CONFIG
pins; the panel is a fixed internal device.

================================================================================
10. STATE / LINK-POLICY SUMMARY
================================================================================

The Source link-policy maker drives the embedded panel through:
  RESET/POWER_ON   -> HPD asserted by panel Sink
  CAPABILITY_READ  -> read DPCD Receiver Capability + eDP_CONFIGURATION_CAP
                      (ASSR / Fast Link Training / PSR caps)
  PANEL_POWER_ON   -> sequence panel VDD / backlight per panel power timing
  LINK_TRAINING    -> Fast Link Training (preferred) or full CR/EQ training
  ACTIVE           -> stream video as micro-packets / Transfer Units; MSA per
                      frame; set backlight brightness over AUX
  PSR_ACTIVE       -> on static screen, enter Panel Self Refresh: panel refreshes
                      from the RFB while the Main Link sleeps
  PSR_EXIT         -> on update / IRQ_HPD, re-train (Fast Link Training) and
                      re-transmit (full frame, or selective-update region for
                      PSR2)
  POWER_DOWN       -> SET_POWER DPCD to D3; Main Link idle; panel/backlight off

The panel Sink reports link status (CR_DONE, CHANNEL_EQ_DONE, SYMBOL_LOCKED,
INTERLANE_ALIGN_DONE) and PSR state (PSR_STATUS) in DPCD; the Source re-trains on
loss of lock.

eDP does NOT implement Multi-Stream Transport (MST): an embedded panel is a
single Sink, so there are no virtual channels, no MST time-slot table, and no
branch / daisy-chain devices.
