FlexRay Communications System
Protocol Specification

Version 2.1 Revision A
(Bosch FlexRay Protocol Specification v2.1A; subsequently standardized as
ISO 17458-1 .. ISO 17458-5)

Prepared by the FlexRay Consortium
(BMW, DaimlerChrysler, Freescale, NXP, Bosch, Volkswagen, General Motors)

================================================================================
1. SCOPE AND OVERVIEW
================================================================================

FlexRay is a deterministic, fault-tolerant, high-speed serial communication
system for advanced automotive in-vehicle networking. It was developed to meet
the bandwidth, determinism, and reliability needs of safety-critical
distributed control applications such as x-by-wire (brake-by-wire,
steer-by-wire), advanced powertrain, and chassis control, where the
event-triggered Controller Area Network (CAN) and the lower-speed Local
Interconnect Network (LIN) are insufficient.

Key headline properties of FlexRay:

  - Gross data rate up to 10 Mbit/s per channel.
  - Two independent communication channels (Channel A and Channel B) that may
    be used for redundancy (fault tolerance) or for doubled bandwidth (up to
    20 Mbit/s aggregate).
  - Time-triggered Time Division Multiple Access (TDMA) media access for the
    static segment, giving deterministic, collision-free, bounded-latency
    communication.
  - Flexible TDMA (FTDMA), also called minislotting, for the dynamic segment,
    giving event-triggered, priority-based bandwidth on demand.
  - A global, distributed, fault-tolerant clock synchronization mechanism so
    every node shares a common notion of time without a central master.
  - Bus or star (active/passive) physical topologies on each channel.

FlexRay is fundamentally different from CAN. CAN uses event-triggered,
CSMA/CR (carrier sense multiple access with collision resolution) bus
arbitration based on a message identifier and non-destructive bitwise
arbitration with bit stuffing. FlexRay instead uses a time-triggered TDMA
schedule with a globally synchronized time base, dual channels, and a static +
dynamic communication cycle. FlexRay does NOT use CAN-style identifier-based
arbitration, does NOT use bit stuffing on the payload, and is NOT a
single-channel event bus. Likewise FlexRay is not LIN: LIN is a single-wire,
low-cost, single-master/multiple-slave, polled (master sends header, slave
sends response) sub-bus at up to 20 kbit/s with no dual channel, no TDMA
static/dynamic segment, and no macrotick/microtick time hierarchy.

================================================================================
2. NETWORK ARCHITECTURE AND NODES
================================================================================

A FlexRay network is built from nodes (Electronic Control Units, ECUs)
connected by one or two channels. Each FlexRay node contains:

  - A host processor (the application CPU). The host runs the application and
    configures the communication controller; it is NOT part of the FlexRay
    protocol engine itself.

  - A Communication Controller (CC). The CC implements the FlexRay protocol:
    media access (TDMA static + FTDMA dynamic), frame and symbol coding and
    decoding, the communication cycle, clock synchronization (offset and rate
    correction), wakeup and startup, and the Protocol Operation Control (POC)
    state machine. The CC connects to the host via a Controller Host Interface
    (CHI) and to each Bus Driver via the digital signals TxD, TxEN, and RxD.

  - One Bus Driver (BD) per channel. The Bus Driver is the physical-layer
    transceiver. It converts the CC's digital TxD/TxEN into the differential
    bus signals on the wire pair (BP, Bus Plus and BM, Bus Minus) and converts
    the received differential signal back into the digital RxD for the CC. The
    BD also handles bus wakeup detection and the transmit enable (TxEN).

  - An optional Bus Guardian (BG). The Bus Guardian is an independent
    protection device that monitors the schedule and only permits the CC to
    transmit during its assigned slots, preventing a faulty (babbling-idiot)
    node from corrupting the bus outside its allotted time.

  - An optional power supply and, on some nodes, an active star coupler.

Because the schedule and the time base are distributed across all nodes,
FlexRay has no single bus master; every node independently derives the global
time and follows the statically configured TDMA schedule.

================================================================================
3. PHYSICAL LAYER, SIGNALS, AND PINS
================================================================================

Each channel is a differential pair:

  - BP  : Bus Plus  (differential bus line, positive)
  - BM  : Bus Minus (differential bus line, negative)

The bus uses differential, Non-Return-to-Zero (NRZ) signaling. The idle bus is
held in a recessive/idle differential state; an active driver forces the
Data_0 / Data_1 differential states. There is no separate clock wire; bit
timing is recovered from the bit stream and maintained by the synchronized
local clock.

Between the Communication Controller and each Bus Driver, the digital
interface signals are:

  - TxD  : Transmit Data    (CC -> BD)  serial data to be sent on the bus.
  - TxEN : Transmit Enable  (CC -> BD)  active-low/active enable that gates the
           BD's bus driver so the node only drives during its own slots.
  - RxD  : Receive Data     (BD -> CC)  serial data recovered from the bus.

The bit rate (gross) is selectable; the nominal high-speed configuration is
10 Mbit/s, giving a nominal bit time of 100 ns. Other configured rates such as
2.5 Mbit/s and 5 Mbit/s are also defined. Each bit on the wire is transmitted
as 8 samples (the sample clock runs at 8x the bit rate) and the receiver uses
majority voting over a sample window to determine the bit value and to perform
bit clock alignment (strobing) on recognized edges.

Physical topologies supported per channel:

  - Passive bus (linear multidrop).
  - Passive star.
  - Active star (one or more active star couplers regenerate the signal,
    extending reach and isolating branches). Cascaded active stars are
    permitted within timing limits.

A node may be connected to one channel only or to both channels.

================================================================================
4. THE COMMUNICATION CYCLE
================================================================================

FlexRay communication is organized into a periodic communication cycle. The
cycle repeats continuously while the cluster is in normal operation, and a
6-bit cycle counter counts cycles modulo 64 (0..63), wrapping back to 0. The
cycle counter enables cycle-multiplexed scheduling (a given slot can carry
different frames on different cycle counts).

Each communication cycle is divided, in time order, into up to four segments:

  1. Static Segment (mandatory)
     The static segment is a pure TDMA region divided into a configured number
     of equally sized static slots. Every static slot has the SAME, fixed
     duration (in macroticks) across the whole cluster. Each static slot is
     assigned (by static configuration) to at most one sending node on each
     channel; the node owning a slot transmits its frame in that slot, and the
     Frame ID of the frame equals the slot number. Because the assignment is
     fixed and the time base is global, transmissions never collide and the
     latency and jitter are bounded and deterministic. The static segment is
     used for periodic, safety-critical, deterministic data. The sync frames
     used for clock synchronization are always sent in the static segment.

  2. Dynamic Segment (optional)
     The dynamic segment uses Flexible TDMA (FTDMA), also called minislotting.
     The dynamic segment is divided into many small minislots. Each potential
     sender is associated with a minislot in priority order (lower Frame ID =
     higher priority = earlier minislot). If a node has data to send in its
     minislot it begins transmitting and the minislot counter pauses for the
     duration of that (variable-length) dynamic frame; if it has nothing to
     send, the minislot simply elapses and the minislot counter advances to the
     next potential sender. Thus bandwidth in the dynamic segment is granted on
     demand and prioritized, but a low-priority frame may not be sent in a
     given cycle if higher-priority traffic consumes the segment. The dynamic
     segment carries event-triggered, sporadic, or bursty data.

  3. Symbol Window (optional)
     A short segment in which network management symbols can be transmitted.
     The defined symbols are the Collision Avoidance Symbol (CAS), the Media
     access Test Symbol (MTS), the Wakeup Symbol (WUS) / Wakeup Pattern (WUP).

  4. Network Idle Time (NIT) (mandatory)
     A communication-free period at the end of every cycle. During the NIT the
     communication controller performs the clock-synchronization calculation
     and applies the offset correction for the next cycle; no frames are sent.

The boundaries of all segments are defined in macroticks and are identical and
statically configured across every node in the cluster.

================================================================================
5. TIMING HIERARCHY AND TIME REPRESENTATION
================================================================================

FlexRay defines a strict hierarchy of time units, from the finest to the
coarsest:

  - Microtick (uT): the smallest unit of time in a node, derived directly from
    the controller's local oscillator (sample clock). Microticks are a local,
    node-private unit and may differ slightly in absolute duration between
    nodes because of oscillator tolerance.

  - Macrotick (MT): the basic unit of the global (cluster-wide) time. A
    macrotick is an integer number of microticks, but the number of microticks
    per macrotick is adjusted by the clock-synchronization rate correction so
    that one macrotick has the same duration in every node. The macrotick is
    the common, synchronized timebase shared across the cluster (typically on
    the order of 1 microsecond).

  - Slot: a static slot or a minislot, measured as an integer number of
    macroticks.

  - Cycle: the whole communication cycle, an integer number of macroticks,
    counted by the 6-bit cycle counter (0..63).

The global time of a node is expressed as the pair {cycle counter, macrotick
counter within the cycle}. Clock synchronization keeps the {cycle, macrotick}
pair aligned across all nodes.

================================================================================
6. FRAME FORMAT
================================================================================

A FlexRay frame consists of three parts: a Header segment, a Payload segment,
and a Trailer segment.

Header segment (5 bytes = 40 bits):

  - Reserved bit (1 bit): reserved for future use, transmitted as 0.
  - Payload Preamble Indicator (1 bit): indicates that the first bytes of the
    payload contain a Network Management Vector (in the static segment) or a
    Message ID (in the dynamic segment).
  - Null Frame Indicator (1 bit): when this bit indicates a null frame, the
    payload contains no valid application data for this slot in this cycle (the
    slot owner had nothing to send but the slot is still transmitted).
  - Sync Frame Indicator (1 bit): when set, this frame is a sync frame and its
    timing is used by the clock-synchronization algorithm. Only nodes
    configured as sync nodes (coldstart/sync) set this bit; sync frames are
    sent only in the static segment.
  - Startup Frame Indicator (1 bit): when set, this frame is a startup frame
    used during the coldstart/startup procedure. A startup frame is always also
    a sync frame.
  - Frame ID (11 bits): identifies the frame and the slot in which it is sent.
    Valid Frame IDs are 1..2047 (0 is reserved). In the static segment the
    Frame ID equals the static slot number.
  - Payload Length (7 bits): the length of the payload in 16-bit words (0..127
    words), i.e. 0..254 bytes of payload.
  - Header CRC (11 bits): a cyclic redundancy check computed over the sync
    frame indicator, the startup frame indicator, the Frame ID, and the Payload
    Length. The Header CRC is computed by the host (configuration time) using
    generator polynomial of degree 11.
  - Cycle Count (6 bits): the value of the transmitting node's cycle counter
    (0..63) at the time of transmission.

Payload segment:

  - 0 to 254 bytes of data, always an even number of bytes (0..127 16-bit
    words). In the static segment all frames have the same configured payload
    length. In the dynamic segment frames may have different payload lengths.
    Optionally the first two payload bytes carry a Message ID (dynamic segment)
    or the payload preamble carries a Network Management Vector (static
    segment) as indicated by the Payload Preamble Indicator.

Trailer segment:

  - Frame CRC (24 bits): a cyclic redundancy check computed over the entire
    header and payload, protecting the whole frame. The 24-bit Frame CRC uses a
    degree-24 generator polynomial; the cluster may use channel-specific CRC
    initialization so that the two channels can be distinguished.

Frame coding on the wire adds frame framing around the bytes: a Transmission
Start Sequence (TSS), a Frame Start Sequence (FSS), and per-byte Byte Start
Sequences (BSS) precede the byte stream, and a Frame End Sequence (FES)
terminates the frame. Each byte is sent as a byte sequence of 8 data bits
framed by the BSS; FlexRay does NOT use CAN-style bit stuffing.

================================================================================
7. MEDIA ACCESS CONTROL
================================================================================

Static segment (TDMA):
  Media access is purely time-driven. Each static slot is owned by a configured
  node; that node transmits exactly when its slot's macrotick window arrives.
  No arbitration is needed because the schedule is collision-free by
  construction. The slot counter advances by one each static slot regardless of
  whether a frame was actually sent (a slot owner that has nothing to send may
  send a null frame).

Dynamic segment (FTDMA / minislotting):
  Media access is priority-driven within a flexible TDMA structure. The dynamic
  segment is divided into minislots. A minislot counter advances; the node
  whose dynamic Frame ID corresponds to the current minislot may start a
  transmission. While a dynamic frame is being transmitted, the minislot
  counter is held; after the frame completes (or the empty minislot elapses)
  the counter resumes. Lower Frame IDs have higher priority (earlier minislots)
  and are more likely to gain access in a busy cycle.

================================================================================
8. BIT TIMING, CODING, AND STROBING
================================================================================

FlexRay uses NRZ coding. The bit rate determines the nominal bit time (100 ns
at 10 Mbit/s). The receiver oversamples each bit by a factor of 8 (8 samples
per bit) using the controller sample clock; a majority vote over a 5-sample
voting window determines the received bit value and suppresses glitches. The
receiver resynchronizes its bit strobe on the falling edge at the start of each
Byte Start Sequence (BSS), so that the per-byte framing re-establishes bit
alignment and bounds the accumulated phase error over a frame. This per-byte
re-strobing is why FlexRay does not need (and does not use) bit stuffing.

================================================================================
9. CLOCK SYNCHRONIZATION
================================================================================

FlexRay maintains a global, distributed, fault-tolerant time base without a
central master. Each node measures the arrival timing of the sync frames it
receives on both channels during the static segment and computes corrections
in two dimensions:

  - Offset correction: corrects the PHASE of the local time (the position of
    the macrotick / cycle start). Offset correction is computed during the
    Network Idle Time (NIT) and applied at the end of the cycle so that the
    next cycle starts at the corrected instant.

  - Rate correction: corrects the RATE (frequency) of the local time, i.e. the
    number of microticks per cycle / per macrotick, so that the local macrotick
    duration matches the cluster. Rate correction is computed over two
    consecutive cycles (an even/odd cycle pair) and applied gradually.

Both corrections use the Fault-Tolerant Midpoint (FTM) algorithm. From the set
of measured deviations relative to the received sync frames, the FTM algorithm
discards the k largest and k smallest values (k depends on the number of
sync frames observed) and forms the midpoint of the remaining largest and
smallest values. This rejection of extremes makes the synchronization robust
against a bounded number of faulty (out-of-spec) sync sources. Only sync frames
(frames with the Sync Frame Indicator set), sent only in the static segment by
configured sync nodes, are used as timing references. The cluster requires at
least two sync nodes for synchronization to operate.

================================================================================
10. WAKEUP AND STARTUP
================================================================================

Wakeup:
  Before communication can start, all nodes (and both channels) must be awake.
  A node wakes a channel by transmitting a Wakeup Pattern (WUP) on that
  channel. The Wakeup Pattern is a configured number of repetitions of the
  Wakeup Symbol (WUS). The Bus Driver detects bus activity and signals the
  host/CC to wake. Wakeup is performed one channel at a time to avoid waking a
  partially-failed cluster incorrectly.

Startup (coldstart):
  After wakeup, the cluster must establish a common schedule and time base
  through the coldstart procedure. Certain nodes are configured as coldstart
  nodes (they are also sync nodes and send startup frames, which are sync
  frames with the Startup Frame Indicator set).

  - A leading coldstart node, after ensuring the channel is idle, transmits the
    Collision Avoidance Symbol (CAS) and then begins sending its startup frames,
    establishing the initial schedule (cycle 0, then 1, ...).
  - Following coldstart nodes and non-coldstart nodes listen, integrate to the
    schedule by observing startup/sync frames over several cycles, verify
    consistency, and then join (integration). At least two coldstart nodes must
    agree before normal communication begins.
  - Once integration and coldstart complete and clock synchronization is
    running, the nodes enter normal operation and begin the regular static +
    dynamic communication cycles.

================================================================================
11. PROTOCOL OPERATION CONTROL (POC) STATE MACHINE
================================================================================

The behavior of the Communication Controller is governed by the Protocol
Operation Control (POC) state machine. The principal POC states are:

  - DEFAULT_CONFIG : entered after reset/power-up; the CC is unconfigured.
  - CONFIG         : the host configures the CC (schedule, slot assignment,
                     timing parameters, sync/coldstart role, CRC init, ...).
  - READY          : configuration complete; the CC waits for a command to
                     start wakeup or startup.
  - WAKEUP         : the CC performs the wakeup procedure (transmit/detect the
                     Wakeup Pattern) to wake the channel(s).
  - STARTUP        : the CC runs the coldstart / integration procedure (CAS,
                     startup frames, schedule integration, initial clock sync).
  - NORMAL_ACTIVE  : fully operational; the node participates in the TDMA
                     schedule, sends/receives frames, and contributes to and
                     follows clock synchronization. This is the steady-state.
  - NORMAL_PASSIVE : the node still receives and keeps time but has degraded
                     synchronization status (e.g. too few sync frames); it does
                     not actively transmit into the schedule until it recovers.
  - HALT           : communication is stopped (e.g. after a fatal error or a
                     host halt command); the CC leaves the schedule.

Transitions are driven by host commands (via the CHI), by the success/failure
of wakeup, startup, and integration, and by the clock-synchronization error
status (degradation from NORMAL_ACTIVE to NORMAL_PASSIVE to HALT).

================================================================================
12. CONFIGURATION PARAMETERS AND REGISTER SET
================================================================================

The Communication Controller is configured (in the CONFIG state) through a set
of protocol configuration parameters held in CC registers, including (with the
canonical FlexRay parameter names):

  - gdCycle               : duration of the communication cycle (in us / MT).
  - gMacroPerCycle        : number of macroticks per cycle.
  - gdMacrotick           : duration of one macrotick (in us).
  - pMicroPerCycle        : number of microticks per cycle (node-local).
  - gNumberOfStaticSlots  : number of static slots in the static segment.
  - gdStaticSlot          : duration of one static slot (in macroticks).
  - gNumberOfMinislots    : number of minislots in the dynamic segment.
  - gdMinislot            : duration of one minislot (in macroticks).
  - gPayloadLengthStatic  : payload length of static frames (in words).
  - gdNIT                 : duration of the Network Idle Time (in macroticks).
  - gColdstartAttempts    : maximum number of coldstart attempts.
  - gdWakeupSymbolTxLow / gdWakeupSymbolTxIdle : wakeup symbol timing.
  - pKeySlotId            : the slot in which this node sends its sync/startup
                            (key) frame.
  - pKeySlotUsedForSync   : whether this node is a sync node.
  - pKeySlotUsedForStartup: whether this node is a coldstart node.
  - vCycleCounter         : the current cycle counter value (0..63), a status
                            variable.

These parameters are identical, cluster-wide, for all the cluster-global (g*)
values; node-local (p*) values may differ per node. Status variables (v*) are
read by the host to observe the protocol state.

================================================================================
13. ERROR HANDLING AND FAULT TOLERANCE
================================================================================

FlexRay error detection and fault-tolerance mechanisms:

  - Header CRC (11-bit) detects header corruption; Frame CRC (24-bit) detects
    whole-frame corruption. A frame failing CRC is discarded.
  - The Null Frame Indicator distinguishes a slot occupied by an
    application-empty frame from a missing frame.
  - The dual channel (A and B) allows redundant transmission; a receiver may
    use the frame from whichever channel is valid.
  - The Bus Guardian prevents a node from transmitting outside its slots
    (babbling-idiot protection).
  - The Fault-Tolerant Midpoint (FTM) clock-sync algorithm tolerates a bounded
    number of faulty sync sources.
  - Clock-synchronization status degrades the node from NORMAL_ACTIVE to
    NORMAL_PASSIVE (and ultimately HALT) when too few valid sync frames are
    received, preventing an unsynchronized node from disturbing the schedule.

================================================================================
14. SUMMARY OF DISTINGUISHING FEATURES
================================================================================

FlexRay is uniquely identified by the combination of: dual independent channels
(Channel A / Channel B); a time-triggered TDMA static segment plus an FTDMA
minislot-based dynamic segment within a periodic communication cycle counted by
a 6-bit cycle counter; the microtick/macrotick/slot/cycle timing hierarchy; a
distributed fault-tolerant clock synchronization using offset and rate
correction with the Fault-Tolerant Midpoint algorithm over sync frames; a 5-byte
header (Frame ID 11-bit, Payload Length 7-bit, Header CRC 11-bit, Cycle Count
6-bit, plus the reserved / payload-preamble / null / sync / startup indicator
bits), 0..254-byte payload, and 24-bit Frame CRC trailer; CAS-based coldstart
and WUP/WUS wakeup; the CC + Bus Driver + optional Bus Guardian node structure;
BP/BM differential signaling with TxD/TxEN/RxD between CC and BD; and the POC
state machine (DEFAULT_CONFIG, CONFIG, READY, WAKEUP, STARTUP, NORMAL_ACTIVE,
NORMAL_PASSIVE, HALT). 10 Mbit/s per channel. None of these (dual-channel TDMA
static/dynamic cycle, macrotick/microtick hierarchy, FTM sync) are present in
CAN or LIN.
