================================================================================
HyperBus Specification
Low-Pin-Count, High-Speed, Double-Data-Rate Memory Interface
(HyperRAM and HyperFlash)
Cypress Semiconductor / Infineon Technologies
Document: HyperBus Interface Specification
================================================================================

--------------------------------------------------------------------------------
1. OVERVIEW
--------------------------------------------------------------------------------

HyperBus is a low-pin-count, high-speed, double-data-rate (DDR) memory interface
defined by Cypress Semiconductor (now Infineon Technologies). It connects a host
controller (master) to one or more HyperBus memory devices (slaves) over a small
number of signals. Two families of memory device use the HyperBus interface:

  * HyperRAM  - a self-refresh pseudo-static RAM (pseudo-SRAM / DRAM core with an
                SRAM-like interface), used for expansion RAM in cost- and
                pin-sensitive embedded systems.
  * HyperFlash - a NOR flash memory presenting exactly the same HyperBus
                interface, used for code and data storage.

A defining property of HyperBus is its low pin count. A complete read/write
interface to a HyperBus device uses an 8-bit double-data-rate command/address/data
bus (DQ[7:0]), a differential clock (CK / CK#), a chip select per device (CS#),
and a Read-Write Data Strobe (RWDS). Optional RESET# and INT# signals complete
the device. Despite the small pin count, HyperBus achieves up to 333 MB/s of
data throughput at 166 MHz DDR with the 8-bit bus.

HyperBus transfers begin with a 48-bit Command-Address (CA) phase that is sent on
DQ[7:0] over three clock periods (six DDR bytes). The CA encodes whether the
transaction is a read or a write, whether it targets the memory array or the
register space, the burst type (linear or wrapped), and the target address.

--------------------------------------------------------------------------------
2. SIGNALS AND PINS
--------------------------------------------------------------------------------

The HyperBus signal list is:

  CK, CK#   Differential clock. The host drives the clock to the memory. CK# is
            the complement of CK. For 1.8 V operation a single-ended clock (CK
            only) option is allowed; for 3.0 V operation the differential pair
            CK / CK# is used. All command, address, and data are referenced to
            the clock edges (double data rate: data on both rising and falling
            edges of CK).

  CS#       Chip Select, active low. One CS# per HyperBus device. The host
            asserts CS# low to begin a transaction and holds it low for the
            duration of the transaction; multiple devices share CK/DQ/RWDS and
            are selected by their individual CS#.

  DQ[7:0]   8-bit double-data-rate command/address/data bus. During the
            Command-Address phase DQ[7:0] carries the 48-bit CA. During the data
            phase DQ[7:0] carries read or write data, one byte per clock edge.
            DQ is bidirectional (driven by the host on write, by the memory on
            read).

  RWDS      Read-Write Data Strobe. A bidirectional signal with two roles:
              - During the Command-Address phase, the memory drives RWDS to
                indicate whether an additional (variable) latency is required
                for this transaction (RWDS high = 2x latency, RWDS low = 1x
                latency) when the device is configured for variable latency.
              - During a READ data phase, the memory drives RWDS as the
                source-synchronous read data strobe, edge-aligned with read
                data on DQ[7:0], so the host can capture DDR read data.
              - During a WRITE data phase, the host drives RWDS as a data mask
                (byte-enable): RWDS high masks (does not write) the
                corresponding byte; RWDS low writes the byte.

  RESET#    Hardware reset, active low (optional). Resets the device to its
            default (power-up) configuration.

  INT#      Interrupt / status output (optional, device-dependent).

Power signals VCC and VCCQ and ground VSS complete the device. HyperRAM and
HyperFlash use the same pin-out so a single board footprint can accept either
device.

--------------------------------------------------------------------------------
3. THE 48-BIT COMMAND-ADDRESS (CA) TRANSACTION
--------------------------------------------------------------------------------

Every HyperBus transaction begins, after CS# goes low, with a 48-bit
Command-Address (CA) sequence transferred on DQ[7:0] across three clock cycles
(six DDR bytes: CA[47:40], CA[39:32], CA[31:24], CA[23:16], CA[15:8], CA[7:0]).

The 48 CA bits are defined as follows:

  CA[47]      R/W#  : 1 = Read transaction, 0 = Write transaction.
  CA[46]      Address Space (AS) : 0 = Memory array, 1 = Register space
                                   (the device's ID and Configuration
                                   registers).
  CA[45]      Burst Type : 0 = Wrapped burst, 1 = Linear burst.
  CA[44:16]   Row & Upper Column Address : the upper address bits selecting the
              row and the upper portion of the column.
  CA[15:3]    Reserved : transmitted as 0.
  CA[2:0]     Lower Column Address (byte address within the burst).

The combination CA[47] (R/W#) and CA[46] (Address Space) selects one of four
operations: memory read, memory write, register read, register write. The host
sends the CA most-significant byte first on the first rising clock edge after
CS# is asserted.

After the CA phase, the device inserts the configured initial latency (see
Section 4), then read or write data flows on DQ[7:0] at double data rate until
CS# is deasserted (returns high), which ends the transaction.

--------------------------------------------------------------------------------
4. LATENCY MODEL
--------------------------------------------------------------------------------

Between the Command-Address phase and the data phase the device requires an
initial access latency, expressed as a number of clock cycles. The latency
count is programmable in the Configuration Register (Configuration Register 0)
and is typically one of 3, 4, 5, 6, or 7 clocks, chosen to match the operating
frequency. Higher clock frequencies require larger latency counts.

HyperBus supports two latency models:

  * Fixed latency  : the device always inserts 2x the configured initial
                     latency (the maximum), regardless of the internal state.
                     Simpler for the host because the timing is deterministic.

  * Variable latency : the device inserts either 1x or 2x the configured initial
                     latency depending on whether an internal operation (such as
                     a HyperRAM distributed refresh) requires additional time.
                     The device signals which case applies by driving RWDS
                     during the Command-Address phase: RWDS asserted (high)
                     during CA = additional latency required (2x); RWDS low =
                     single latency (1x).

The latency model (fixed vs variable) and the initial latency count are both
selected through Configuration Register 0. For HyperRAM, variable latency lets
the device hide refresh-collision delays; for HyperFlash, the read latency
covers internal array access time.

--------------------------------------------------------------------------------
5. HyperRAM vs HyperFlash
--------------------------------------------------------------------------------

5.1 HyperRAM

HyperRAM is a self-refresh pseudo-static RAM. Internally it is a DRAM core but
it presents an SRAM-like interface: the host does not have to issue explicit
refresh commands because the device performs distributed (self) refresh of its
DRAM cells automatically. When a refresh operation collides with a host access,
the variable-latency mechanism (Section 4) inserts the extra latency so no data
is lost. HyperRAM supports a Deep Power Down (DPD) mode entered through the
Configuration Register for ultra-low standby current; exiting DPD requires a
wake-up time. Legacy and distributed refresh schemes keep the array contents
valid.

5.2 HyperFlash

HyperFlash is a NOR flash memory presenting the identical HyperBus interface.
Reads use the same CA + latency + DDR data flow as HyperRAM. Program and erase
operations are issued through command sequences written to the array (NOR-style
program/erase command set) and the device reports status. Because HyperFlash and
HyperRAM share the interface and pin-out, a system can mix or substitute the two
on the same bus.

--------------------------------------------------------------------------------
6. REGISTERS
--------------------------------------------------------------------------------

HyperBus devices expose a small register space, addressed by setting the Address
Space bit (CA[46] = 1) in the Command-Address. The registers are:

  Identification Register 0 (ID0) : read-only. Reports manufacturer and device
                                    identification, row/column address bit
                                    counts, and device-size information.

  Identification Register 1 (ID1) : read-only. Additional device identification.

  Configuration Register 0 (CR0)  : read/write. Controls the key operating
                                    parameters:
                                      - Deep Power Down enable (HyperRAM)
                                      - Drive Strength (output impedance of DQ
                                        and RWDS)
                                      - Initial Latency count (e.g. 3..7 clocks)
                                      - Fixed vs Variable Latency select
                                      - Burst Length (wrapped burst length:
                                        e.g. 16, 32, 64, 128 bytes) and
                                        Hybrid Burst enable
                                      - Burst Type (wrapped / linear default)

  Configuration Register 1 (CR1)  : read/write. Controls additional features
                                    such as the refresh interval / distributed
                                    refresh control (HyperRAM) and other
                                    device-specific options.

A register read is a transaction with R/W#=1 and Address Space=1; a register
write is R/W#=0 and Address Space=1. Register writes complete without a data
latency (the CA itself carries the register address and the following bytes
carry the value), per the device datasheet.

--------------------------------------------------------------------------------
7. TIMING, SPEED, AND VOLTAGE
--------------------------------------------------------------------------------

HyperBus is a double-data-rate interface: data is transferred on both the rising
and falling edges of CK. With an 8-bit DQ bus running at 166 MHz the peak
throughput is 2 x 166 MHz x 1 byte = 333 MB/s. Lower clock frequencies (with
correspondingly smaller initial latency counts) are also supported.

Two supply-voltage variants exist:

  * 1.8 V HyperBus : single-ended clock (CK) option permitted; lower-voltage
                     I/O.
  * 3.0 V HyperBus : differential clock (CK / CK#) used.

The read data strobe RWDS is edge-aligned (source-synchronous) with read data,
so the host captures DDR read data using RWDS rather than re-deriving timing
from CK. Drive strength of the DQ and RWDS outputs is programmable in CR0 to
tune signal integrity for the board.

--------------------------------------------------------------------------------
8. POWER MODES
--------------------------------------------------------------------------------

  * Active           : a transaction is in progress (CS# low).
  * Standby / Idle   : CS# high, clock may be stopped; the device retains data
                       (HyperRAM continues self-refresh).
  * Deep Power Down  : HyperRAM ultra-low-power state entered via CR0; array
                       contents are NOT retained (or retained per device
                       variant); exit requires a defined wake-up time.

A hardware RESET# (when present) returns the device to its power-up default
configuration (default initial latency, fixed/variable latency default, default
drive strength, default burst length).

--------------------------------------------------------------------------------
9. TRANSACTION FLOW SUMMARY
--------------------------------------------------------------------------------

A complete HyperBus read transaction:

  1. Host drives CS# low.
  2. Host drives the differential clock CK / CK#.
  3. Host sends the 48-bit Command-Address on DQ[7:0] over three clocks
     (R/W#=1 for read).
  4. (Variable latency) the memory drives RWDS during CA to signal 1x or 2x
     latency.
  5. Device inserts the initial latency (configured in CR0).
  6. Memory drives read data on DQ[7:0] at double data rate, with RWDS as the
     edge-aligned read strobe.
  7. Host captures DDR read data using RWDS until it has the burst it needs.
  8. Host drives CS# high to end the transaction.

A complete HyperBus write transaction:

  1. Host drives CS# low.
  2. Host sends the 48-bit Command-Address on DQ[7:0] (R/W#=0 for write).
  3. Device inserts the initial latency (for memory-array writes).
  4. Host drives write data on DQ[7:0] at double data rate; the host drives RWDS
     as a byte data mask (RWDS high = mask/skip the byte, RWDS low = write the
     byte).
  5. Host drives CS# high to end the transaction.

Wrapped bursts wrap within the configured burst length boundary (16/32/64/128
bytes); linear bursts increment the address linearly until CS# is deasserted.
The Hybrid Burst option begins as a wrapped burst and then continues as a linear
burst past the wrap boundary.

--------------------------------------------------------------------------------
10. INTEROPERABILITY AND COMPLIANCE
--------------------------------------------------------------------------------

A compliant HyperBus host must:

  * Drive CS# per device and the differential (or single-ended at 1.8 V) clock.
  * Issue the 48-bit Command-Address most-significant byte first over three
    clocks, with correct R/W#, Address Space, and Burst Type bits.
  * Honor the configured initial latency and (for variable latency) sample RWDS
    during the CA phase to decide 1x vs 2x latency.
  * Capture DDR read data using the memory-driven RWDS strobe.
  * Drive RWDS as the byte data mask during writes.
  * Program the Configuration Registers (CR0/CR1) to match the operating
    frequency (latency count) and desired burst length / drive strength.

A compliant HyperBus memory must present the ID and Configuration registers in
the register address space, perform self-refresh (HyperRAM) transparently using
the variable-latency RWDS-during-CA mechanism, and meet the DDR data and RWDS
strobe timing up to its rated frequency (e.g. 166 MHz, 333 MB/s).
