JESD204
Serial Interface for Data Converters
(JESD204B / JESD204C)

JEDEC Solid State Technology Association
JESD204B: July 2011 (with subsequent amendments)
JESD204C: December 2017

Document prepared by the JEDEC JC-16 Committee on Interface Technology.

--------------------------------------------------------------------------------
1. SCOPE AND OVERVIEW
--------------------------------------------------------------------------------

JESD204 defines a high-speed serial interface (link) between one or more data
converters (analog-to-digital converters, ADCs, and digital-to-analog
converters, DACs) and a logic device such as an FPGA or ASIC. The standard
replaces wide, parallel, source-synchronous LVDS/CMOS converter interfaces with
a small number of high-speed serialized differential lanes, dramatically
reducing pin count and simplifying PCB routing as converter resolution and
sample rate increase.

The interface is a point-to-point or point-to-multipoint SerDes link organized
around a Converter Device (the ADC/DAC) and a Logic Device (the receiver, e.g.
FPGA). Sample data from the converters is mapped into octets, optionally
scrambled, encoded for the lane, and serialized across L physical lanes. A
deterministic-latency option allows the exact latency from converter sample to
logic-device output (or vice versa) to be known and repeatable across power
cycles.

Three generations exist:
  - JESD204 (2006): single lane, up to 3.125 Gbps, no lane alignment.
  - JESD204A (2008): multiple lanes, up to 3.125 Gbps, multi-lane alignment.
  - JESD204B (2011): up to 12.5 Gbps per lane, 8b/10b line coding,
    deterministic latency (subclasses), SYSREF/SYNC.
  - JESD204C (2017): up to 32 Gbps per lane, 64b/66b and 64b/80b link layers,
    optional forward error correction (FEC), command channel.

This document describes the JESD204B and JESD204C link from the perspective of
an IC designer implementing the converter-side transmitter or the
logic-device-side receiver.

--------------------------------------------------------------------------------
2. CONVERTER-TO-LOGIC TOPOLOGY
--------------------------------------------------------------------------------

A JESD204 Link connects M converters in a Converter Device to a Logic Device
over L lanes. Key roles:

  - Converter Device: contains the data converters. On an ADC link it is the
    transmitter (TX); on a DAC link it is the receiver (RX).
  - Logic Device: the FPGA/ASIC. On an ADC link it is the receiver (RX); on a
    DAC link it is the transmitter (TX).

Both ends share a common Device Clock. In Subclass 1 they also share a SYSREF
signal; in Subclass 2 they use the SYNC~ interface for deterministic latency.

A single Converter Device may support multiple links; multiple converter devices
may be aligned to a single logic device. The lane data rate, the number of lanes
L, the number of converters M, and the framing parameters are negotiated/
configured out of band (typically over an SPI control bus) before the link is
brought up; the link parameters themselves are also transmitted in-band during
the Initial Lane Alignment Sequence (ILAS).

--------------------------------------------------------------------------------
3. PHYSICAL LAYER: LANES, RATES, AND LINE CODING
--------------------------------------------------------------------------------

3.1 Lanes
Each lane is a unidirectional differential serial pair (CML, AC-coupled). On an
ADC link the converter device drives the lanes toward the logic device; on a
DAC link the logic device drives the lanes toward the converter device. A link
uses L lanes, L in {1, 2, 4, 8} typically (the standard allows up to 32 lanes).

3.2 Lane rates
  - JESD204B: lane bit rate from 312.5 Mbps up to 12.5 Gbps. Three speed
    grades are defined for electrical compliance:
      Speed Grade 1: 312.5 Mbps to 6.375 Gbps
      Speed Grade 2: 6.375 Gbps to 8 Gbps
      Speed Grade 3: 8 Gbps to 12.5 Gbps
  - JESD204C: lane bit rate up to 32 Gbps.

3.3 Line coding
  - JESD204B uses 8b/10b encoding (the same DC-balanced, run-length-limited
    code used by PCIe/SATA/GbE). Control characters /K/ are used for code group
    synchronization and frame/multiframe alignment. The clock is embedded in the
    serial stream and recovered by the receiver CDR.
  - JESD204C adds a 64b/66b link layer (and an optional 64b/80b variant), which
    improves coding efficiency from 80% (8b/10b) to ~97% and supports higher
    lane rates. A sync header carries block alignment, and an optional Reed-
    Solomon forward error correction (FEC) protects the payload.

3.4 SerDes
Each lane is served by a serializer (TX) or deserializer with clock-data
recovery (RX). The recovered bit clock is divided down to the frame clock and
the local multiframe clock.

--------------------------------------------------------------------------------
4. THE L/M/F/S/N/N'/K PARAMETER SET (LINK CONFIGURATION)
--------------------------------------------------------------------------------

A JESD204 link is fully described by a set of configuration parameters, carried
in the ILAS link-configuration octets and (typically) mirrored in the converter's
control registers:

  L   - Number of lanes per converter device (per link).
  M   - Number of converters per device.
  F   - Number of octets per frame (per lane).
  S   - Number of samples per converter per frame.
  N   - Converter resolution in bits (e.g. 12, 14, 16).
  N'  - Total number of bits per sample (N plus control/tail bits; N' is a
        multiple of 4, e.g. 16). The sample word width on the lane.
  K   - Number of frames per multiframe (1..32; F*K must be 4..1024 octets and
        a multiple of 4).
  CS  - Number of control bits per sample.
  CF  - Number of control words per frame per link.
  HD  - High Density format flag (a sample may span lane boundaries).
  CONTROL/TAIL - control bits and tail/dummy bits pad N up to N'.
  SCR - Scrambling enable (1 = scrambling on).
  JESDV - JESD204 version (0 = 204A, 1 = 204B, 2 = 204C).
  SUBCLASSV - device subclass (0, 1, or 2).
  ADJCNT, ADJDIR, PHADJ - LMFC phase adjustment fields (Subclass 2).
  DID - Device identification number.
  BID - Bank identification number.
  LID - Lane identification number.
  FCHK - ILAS configuration checksum.

The aggregate link bit rate relates the parameters:
  lane_rate = (M * S * N' * (10/8) * f_s) / L      (8b/10b, JESD204B)
where f_s is the converter sample rate. For JESD204C the (10/8) factor becomes
(66/64) for the 64b/66b link layer.

--------------------------------------------------------------------------------
5. SUBCLASSES AND DETERMINISTIC LATENCY
--------------------------------------------------------------------------------

JESD204B defines three subclasses that trade off latency determinism:

  Subclass 0: No support for deterministic latency. Backward compatible with
    JESD204A multi-lane alignment. SYNC~ is used only to initiate the code group
    synchronization handshake; latency may vary across power cycles.

  Subclass 1: Deterministic latency using a SYSREF signal. SYSREF is a
    source-synchronous timing reference, distributed from a common clock device
    to all converters and the logic device, that aligns each device's Local
    MultiFrame Clock (LMFC). With aligned LMFCs the converter-to-logic latency is
    fixed and repeatable. SYSREF may be a single pulse, periodic, or gapped
    periodic.

  Subclass 2: Deterministic latency using the SYNC~ interface. The logic device's
    SYNC~ timing is used as the alignment reference for the LMFC, removing the
    need for a separately routed SYSREF at the expense of a SYNC~ timing
    constraint relative to the device clock. Used at lower lane rates.

In JESD204C deterministic latency is retained; SYSREF (Subclass 1 style) remains
the primary mechanism, and the synchronization moves into the link layer
(sync header / command channel) rather than the JESD204B SYNC~ handshake.

--------------------------------------------------------------------------------
6. SIGNALS
--------------------------------------------------------------------------------

  - Serial lane differential pairs (SERDIN/SERDOUT, L pairs): the high-speed
    payload, unidirectional, CML, AC-coupled.
  - Device Clock (DEVCLK): the master clock from which the frame clock and LMFC
    are derived; common to both ends of the link.
  - SYSREF: Subclass 1 deterministic-latency reference; aligns the LMFC at TX and
    RX. Single, periodic, or gapped-periodic. Sampled by the device clock.
  - SYNC~ (SYNC, active-low): in JESD204B, the RX-to-TX synchronization request.
    Asserted (low) by the receiver to request code group synchronization (CGS);
    de-asserted to indicate sync achieved and to start the ILAS. Also used to
    report errors. In JESD204C the SYNC function moves into the link's sync
    header / command channel.
  - In JESD204C an optional command channel rides the link for in-band control.

--------------------------------------------------------------------------------
7. LINK LAYER AND BRING-UP: CGS -> ILAS -> DATA
--------------------------------------------------------------------------------

A JESD204B link is brought up in three phases:

7.1 Code Group Synchronization (CGS)
The receiver asserts SYNC~ (low). The transmitter responds by transmitting a
continuous stream of /K28.5/ comma characters (the K28.5 control symbol). The
receiver's CDR locks, achieves byte/character alignment on the comma, and once
it has received the required number of consecutive /K/ characters on all lanes it
de-asserts SYNC~. CGS establishes character (code-group) boundaries.

7.2 Initial Lane Alignment Sequence (ILAS)
After SYNC~ de-asserts, the transmitter begins the ILAS on the first multiframe
boundary. The ILAS consists of (at least) four multiframes:
  Multiframe 1: starts with /R/ (K28.0), filled with the lane data, ends with
    /A/ (K28.3).
  Multiframe 2: starts with /R/ (K28.0), followed by /Q/ (K28.4), then the link
    configuration data (the L/M/F/S/N/N'/K/CS/CF/HD/SCR/... octets and FCHK
    checksum), ends with /A/ (K28.3).
  Multiframe 3: same content as multiframe 1.
  Multiframe 4: same content as multiframe 1.
The ILAS aligns all lanes to a common multiframe boundary and conveys the link
configuration to the receiver for verification against its own configuration.

7.3 Data Phase (User Data)
After ILAS, the transmitter sends user data (the converter samples mapped into
frames and multiframes), optionally scrambled. The /A/ (K28.3) and /F/ (K28.7)
control characters are inserted at multiframe and frame boundaries respectively
for alignment monitoring and lane realignment.

7.4 Local MultiFrame Clock (LMFC) and multiframe
The LMFC is a clock with a period of F*K frame clocks (one multiframe). All
devices align their LMFC to SYSREF (Subclass 1) or SYNC~ (Subclass 2). The
multiframe is the unit of lane alignment; the elastic buffer in the receiver
releases aligned data at the LMFC boundary to achieve deterministic latency.

--------------------------------------------------------------------------------
8. SCRAMBLING
--------------------------------------------------------------------------------

Scrambling is optional (SCR flag). When enabled, the payload octets are scrambled
with a self-synchronous scrambler using the polynomial 1 + x^14 + x^15 (the same
multiplicative scrambler structure used in other serial standards). Scrambling
spreads the spectrum and avoids spurs that could couple into the converter, and
removes data-dependent patterns. The scrambler is reset/seeded per the standard;
the descrambler at the receiver is self-synchronizing.

--------------------------------------------------------------------------------
9. CONTROL CHARACTERS (8b/10b, JESD204B)
--------------------------------------------------------------------------------

  /K/ = K28.5 : code group synchronization comma (CGS).
  /R/ = K28.0 : start of multiframe (ILAS) / start of multiframe in data.
  /A/ = K28.3 : end of multiframe / lane alignment character.
  /Q/ = K28.4 : start of link configuration data (in ILAS multiframe 2).
  /F/ = K28.7 : frame alignment character (inserted at frame boundary).
These control characters are inserted only by the 8b/10b link layer in
JESD204B/A. JESD204C's 64b/66b link layer uses sync-header-based block
alignment and a different multiblock/extended-multiblock alignment scheme
instead of /K/A/F/ characters.

--------------------------------------------------------------------------------
10. JESD204C DELTAS
--------------------------------------------------------------------------------

  - Lane rate raised to 32 Gbps.
  - 64b/66b link layer (and optional 64b/80b) replaces 8b/10b; coding overhead
    drops from 25% to ~3%, raising payload efficiency to ~97%.
  - Block alignment uses the 2-bit sync header; multiblocks (32 blocks) and an
    extended multiblock structure replace the multiframe-character scheme for
    alignment.
  - Optional forward error correction (FEC): a Reed-Solomon-based FEC protects
    the payload at the highest lane rates.
  - A command channel provides in-band control/status signaling.
  - Deterministic latency retained via SYSREF (Subclass 1).
  - Backward interoperability with JESD204B at 8b/10b is supported in
    dual-mode devices.

--------------------------------------------------------------------------------
11. ERROR DETECTION AND REPORTING
--------------------------------------------------------------------------------

JESD204B receivers monitor:
  - Disparity errors and not-in-table (invalid 8b/10b code) errors.
  - Unexpected control character errors (a /K/A/F/ where it should not be).
  - The ILAS configuration checksum (FCHK).
Errors may be reported by re-asserting SYNC~ (with defined error-reporting
timing). JESD204C uses CRC and the optional FEC for payload integrity, plus the
command channel for status.

--------------------------------------------------------------------------------
12. REGISTER MODEL (CONVERTER CONTROL)
--------------------------------------------------------------------------------

The JESD204 link parameters are typically programmed through the converter's
device control interface (commonly SPI). Representative configuration fields
mirror the ILAS link-configuration octets:
  DID, BID, LID, L, F, K, M, N, N', CS, CF, HD, SCR, JESDV, SUBCLASSV,
  ADJCNT, ADJDIR, PHADJ, FCHK.
The standard specifies the in-band ILAS link-configuration octet format; the
exact SPI register addresses are vendor-defined.

--------------------------------------------------------------------------------
13. APPLICATIONS
--------------------------------------------------------------------------------

  - High-speed/wideband ADCs for software-defined radio, 5G base stations,
    radar, and instrumentation feeding an FPGA.
  - High-speed DACs for direct RF synthesis driven by an FPGA.
  - Multi-converter, multi-lane systems requiring deterministic, repeatable
    latency for phased-array beamforming and synchronized data acquisition.
  - Replacing wide parallel LVDS converter buses to cut pin count and routing.
