Low Pin Count (LPC) Interface Specification
Revision 1.1, Intel Corporation, August 2002

1. Introduction
The Low Pin Count (LPC) Interface is a bus interface defined by Intel as a
low-pin-count replacement for the legacy ISA (Industry Standard Architecture)
expansion bus and the X-bus in PC platforms. LPC connects a host (the chipset
South Bridge / I/O Controller Hub) to one or more peripheral devices such as
Super-I/O controllers, embedded controllers, BIOS/firmware flash, and legacy
I/O. LPC reduces the wire count from the ~30 signals of the ISA bus down to a
minimum of 7 required signals by time-multiplexing address, data and control
information over a 4-bit bus and reusing the existing PCI clock. LPC is the
PARALLEL predecessor that the serial Enhanced Serial Peripheral Interface
(eSPI) later replaces.

2. Signal Definition
The LPC interface uses the following signals. Only the first four are required;
the rest are optional and device-dependent.

  Required signals:
  LAD[3:0]  - Multiplexed command, address, and data bus. 4 bits wide. Carries
              the START field, the CYCTYPE+DIR field, the address nibbles, the
              SYNC field, and the data nibbles, one nibble per LCLK cycle.
  LFRAME#   - Active-low frame signal driven by the host. A LOW on LFRAME#
              indicates the start of a new cycle (or an abort). Slaves monitor
              LFRAME# to detect the beginning and abnormal termination of cycles.
  LCLK      - Clock. This is the 33 MHz PCI clock. All LPC signals are driven
              and sampled relative to the rising edge of LCLK.
  LRESET#   - Active-low reset. This is the same signal as PCI RST#. It resets
              all LPC peripherals.

  Optional signals:
  LDRQ#     - Active-low encoded DMA / bus-master request, point-to-point from a
              peripheral to the host. Used to request 8237-compatible DMA service.
  SERIRQ    - Serialized IRQ. A single wire that serializes the legacy
              parallel interrupt request lines (IRQ0..IRQ15) in continuous or
              quiet mode.
  CLKRUN#   - Optional clock-run signal for mobile / clock-stopping platforms.
  PME#      - Optional Power Management Event signal for wakeup.
  LSMI#     - Optional System Management Interrupt request.

All required LPC signals share the 3.3 V signaling levels of PCI. LCLK runs at
33 MHz, the standard PCI clock frequency. There is no separate LPC clock — LPC
reuses the PCI clock so it adds no new clock pin to the platform.

3. Cycle Structure
Every LPC transaction is a sequence of fields driven nibble-by-nibble on the
4-bit LAD[3:0] bus, one nibble per LCLK clock. A cycle is framed by LFRAME#.
The general field order is:

  START -> CYCTYPE+DIR -> ADDR -> [TAR] -> SYNC -> DATA -> TAR

  START      The host drives LFRAME# low and places a 4-bit START value on
             LAD[3:0]. The START field selects the kind of cycle / which agent
             is being addressed.
  CYCTYPE+DIR The first field after START. It encodes the cycle type (I/O,
             Memory, DMA) and the transfer direction (read or write).
  ADDR       Address nibbles. The number of nibbles depends on the cycle type
             (16-bit I/O address = 4 nibbles, 32-bit memory address = 8 nibbles,
             28-bit firmware memory address = 7 nibbles).
  TAR        Turnaround. One or two LCLK cycles during which the LAD bus changes
             ownership between host and peripheral. The driver tri-states the
             bus and the new owner takes over.
  SYNC       The addressed peripheral drives the SYNC field to indicate it is
             ready, inserting wait states, signaling an error, or requesting
             more time.
  DATA       Data nibbles, driven least-significant nibble (LSN) first, then
             most-significant nibble (MSN). One byte = two LAD nibbles.

4. START Field Encoding (LAD[3:0] while LFRAME# is low)
  0000  Start of a target (memory/I/O) cycle
  0010  Grant for bus master 0 (first bus-master device)
  0011  Grant for bus master 1 (second bus-master device)
  1101  Firmware Memory Read cycle
  1110  Firmware Memory Write cycle / Stop-Abort indication on LFRAME#
  1111  Reserved / Firmware (legacy notation)

Note: The host signals an ABORT by driving LFRAME# low for at least 4 LCLK
clocks with LAD[3:0] = 1111 (the stop/abort code); all peripherals must then
tri-state the LAD bus and abandon the cycle.

5. Cycle Type and Direction Field (CYCTYPE+DIR, on LAD[3:0])
The CYCTYPE+DIR field is driven on LAD[3:1] for the cycle type and LAD[0] (or a
defined bit) for direction. The defined cycle types are:
  0000  I/O Read           (16-bit I/O address)
  0010  I/O Write          (16-bit I/O address)
  0100  Memory Read        (32-bit memory address)
  0110  Memory Write       (32-bit memory address)
  1000  DMA Read           (8237-compatible DMA transfer, host -> peripheral)
  1010  DMA Write          (8237-compatible DMA transfer, peripheral -> host)
Bit LAD[1] of this field encodes direction: 0 = Read, 1 = Write.

6. SYNC Field Encoding (driven by the peripheral on LAD[3:0])
  0000  READY            Data is ready (no wait); transfer this cycle.
  0101  SHORT WAIT       Short wait sync; peripheral needs a few more cycles.
  0110  LONG WAIT        Long wait sync; peripheral needs many more cycles.
  1001  READY-MORE       Ready, with more DMA data to follow (DMA cycles).
  1010  ERROR            Error sync; the cycle terminates abnormally.
The host samples SYNC each LCLK; it keeps clocking wait-sync cycles until it
sees READY (0000) or ERROR (1010).

7. Cycle Types in Detail
  7.1 I/O Cycles
      16-bit I/O address. One byte of data is transferred (8 bits = 2 nibbles).
      Used for legacy I/O port accesses (e.g., Super-I/O configuration, keyboard
      controller, serial/parallel ports). Field order: START(0000) -> CYCTYPE+DIR
      -> 4 ADDR nibbles -> TAR -> SYNC -> 2 DATA nibbles -> TAR.

  7.2 Memory Cycles
      32-bit memory address (8 nibbles). One byte of data. Used for memory-mapped
      peripherals.

  7.3 DMA Cycles
      8237-compatible DMA. A peripheral requests DMA service by driving its
      encoded LDRQ# message (the channel number and activation bit are serialized
      on LDRQ#). The host then runs a DMA cycle whose START is 0000 and CYCTYPE
      indicates DMA Read or DMA Write, with the DMA channel (0..7) and transfer
      size encoded in the cycle. Channels 0..3 are 8-bit; channels 5..7 are
      16-bit; channel 4 is the cascade channel.

  7.4 Bus Master Cycles
      A peripheral capable of bus mastering requests the bus; the host grants it
      with a START value of 0010 (bus master 0) or 0011 (bus master 1). The bus
      master then drives memory or I/O cycles to system memory.

  7.5 Firmware Memory Cycles
      Used to boot from the BIOS/firmware flash. Firmware cycles use a 28-bit
      memory address (7 nibbles) and an IDSEL (device select) nibble so multiple
      firmware devices can share the bus. START is 1101 (read) or 1110 (write).

8. DMA Request Encoding (LDRQ#)
LDRQ# is a point-to-point active-low serial message from a peripheral to the
host. Each LDRQ# message begins with a START bit (LDRQ# low for one clock),
followed by a 3-bit DMA channel number (MSB first), then an ACT bit (1 =
request active / 0 = deactivate), all sampled on the rising edge of LCLK.

9. Serialized IRQ (SERIRQ)
SERIRQ multiplexes the 16 legacy interrupt request lines onto a single wire as a
serial stream of IRQ slots. It operates in two modes: Continuous mode (the host
drives the START frame every cycle) and Quiet mode (a peripheral drives the
START frame only when it has a pending interrupt, to save power). Each SERIRQ
frame is START + IRQ0..IRQ15 + IRQ slots for SMI#, IOCHCK#, etc. + STOP.

10. Turnaround (TAR)
The TAR (turnaround) interval is 2 LCLK cycles. During the first TAR clock the
current driver drives LAD[3:0] = 1111 then tri-states; during the second TAR
clock the bus floats and the new owner prepares to drive. TAR occurs when bus
ownership passes from host to peripheral (after the address, before SYNC) and
back from peripheral to host (after the data).

11. Reset and Initialization
LRESET# (same as PCI RST#) resets all LPC peripherals. After reset the host
drives LFRAME# high (idle) and LAD[3:0] is not driven by any peripheral. LPC has
no configuration-negotiation protocol — devices are at fixed, platform-defined
I/O / memory addresses. The first activity is typically a firmware memory read
to fetch the boot vector.

12. Timing
  LCLK frequency            33 MHz (the PCI clock)
  Signaling voltage         3.3 V (PCI levels)
  Setup time tSU            7 ns (PCI input setup)
  Hold time tHO             0 ns (PCI input hold)
  Clock-to-out tVAL         max 11 ns (PCI Tval)
  Turnaround (TAR)          2 LCLK cycles
  Reset (LRESET#) min       1 ms asserted at power-up
  Abort (LFRAME# low)       minimum 4 LCLK cycles with LAD = 1111

13. Relationship to Other Buses
LPC replaces the ISA / X-bus with far fewer pins by multiplexing address and
data over LAD[3:0] and reusing the PCI clock. LPC is itself the PARALLEL
predecessor of the serial Enhanced Serial Peripheral Interface (eSPI); eSPI
later supersedes LPC. LPC has NO logical channels, NO command/response opcode
table, NO CRC, and NO GET/SET configuration negotiation — those are eSPI
concepts. LPC's model is the single multiplexed LAD[3:0] field stream framed by
LFRAME#, with the START / CYCTYPE / SYNC field encodings defined above.
