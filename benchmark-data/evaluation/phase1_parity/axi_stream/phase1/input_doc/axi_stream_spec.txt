AMBA AXI4-Stream Protocol Specification
ARM IHI 0051
Advanced Microcontroller Bus Architecture (AMBA)

================================================================================
1. OVERVIEW
================================================================================

The AMBA AXI4-Stream protocol is a single-channel, point-to-point, unidirectional
protocol for transporting a stream of data from a source (master / transmitter)
to a sink (slave / receiver). Unlike the AMBA AXI memory-mapped protocol, the
AXI4-Stream protocol has NO address phase and NO read/write transaction model:
there is exactly one stream channel that carries data in one direction only.

An AXI4-Stream interface connects a single master to a single slave. The master
is the source of the stream and drives the data and the qualifier signals; the
slave is the sink of the stream and signals when it is able to accept data. Data
flows only from the master to the slave. There is no return data path, no
response channel, and no address.

The AXI4-Stream protocol describes:

  - The TVALID / TREADY handshake that moves a single transfer across the
    interface in one ACLK cycle.
  - The payload and qualifier signals (TDATA, TSTRB, TKEEP, TLAST, TID, TDEST,
    TUSER) that describe the data and its routing.
  - The concepts of transfer, packet, frame, stream, and the byte types
    (data byte, position byte, null byte) used to interpret TDATA.

The AXI4-Stream protocol is used to connect components that exchange a continuous
or bursty stream of data, such as a video pipeline, a packet processor, a DMA
engine streaming to an accelerator, or a digital signal-processing data path. It
is the streaming companion to the memory-mapped AMBA AXI protocol, and the two
are frequently used together in the same system (a memory-mapped AXI interface
for control/configuration registers, an AXI4-Stream interface for the data
pipeline).

This protocol must NOT be confused with the memory-mapped AMBA AXI protocol.
The memory-mapped AXI protocol uses five independent address/data channels
(write address AW, write data W, write response B, read address AR, read data R)
with the ARVALID/AWVALID/RVALID/BVALID/WVALID handshakes, ARADDR/AWADDR address
buses, and INCR/WRAP/FIXED burst types. The AXI4-Stream protocol has none of
those: it is a single TVALID/TREADY stream channel with no address.

================================================================================
2. INTERFACE ROLES AND SIGNALS
================================================================================

2.1 Roles
---------

An AXI4-Stream interface has exactly two participants:

  - The MASTER (also called the source or transmitter): drives TVALID, TDATA,
    TSTRB, TKEEP, TLAST, TID, TDEST, and TUSER. The master is the producer of
    the stream.
  - The SLAVE (also called the sink or receiver): drives TREADY. The slave is
    the consumer of the stream.

The interface is unidirectional: data and qualifiers always flow from the master
to the slave. Only the TREADY backpressure signal flows from the slave back to
the master.

2.2 Global signals
-------------------

  - ACLK    : the single clock. All signals are sampled on the rising edge of
              ACLK. Both the master and the slave use the same ACLK.
  - ARESETn : the active-LOW reset. During reset (ARESETn LOW) the master must
              drive TVALID LOW. The earliest TVALID can be asserted is one ACLK
              rising edge after ARESETn is HIGH.

2.3 Stream signals
------------------

  TVALID  (master -> slave) : indicates that the master is driving a valid
                              transfer. A transfer takes place when both TVALID
                              and TREADY are asserted in the same ACLK cycle.
  TREADY  (slave -> master) : indicates that the slave can accept a transfer in
                              the current cycle.
  TDATA   (master -> slave) : the primary payload. TDATA is an integer number of
                              bytes wide (TDATA_WIDTH is a multiple of 8). The
                              data byte lanes are interpreted with TSTRB and
                              TKEEP.
  TSTRB   (master -> slave) : the byte qualifier that marks each associated byte
                              of TDATA as a DATA byte or a POSITION byte. One bit
                              per byte lane.
  TKEEP   (master -> slave) : the null-byte qualifier that marks each associated
                              byte of TDATA as either a content byte that must be
                              transmitted, or a NULL byte that can be removed from
                              the stream. One bit per byte lane.
  TLAST   (master -> slave) : the packet boundary. TLAST HIGH marks the last
                              transfer of a packet.
  TID     (master -> slave) : the data stream identifier. Used by interconnect to
                              route or to distinguish between different streams
                              sharing the same physical channel.
  TDEST   (master -> slave) : the routing destination. Provides routing
                              information for the stream through the interconnect.
  TUSER   (master -> slave) : the user-defined sideband. Carries user-defined
                              information alongside the data. Can be transferred
                              per transfer or associated with TDATA byte lanes.
  TWAKEUP (master -> slave) : (AXI4-Stream v2 / AMBA 5) wake-up signal indicating
                              the presence of activity associated with the
                              interface for low-power wake handshaking.

All payload and qualifier signals except TVALID and TREADY are optional. A
minimal AXI4-Stream interface is just ACLK, ARESETn, TVALID, TREADY, and TDATA;
the most minimal of all (a "TVALID/TREADY only" interface) carries no TDATA and
is used purely to convey TID/TDEST or count transfers.

================================================================================
3. THE HANDSHAKE
================================================================================

3.1 TVALID / TREADY
-------------------

Every transfer of payload across the AXI4-Stream interface uses the same
two-wire handshake:

  - The master asserts TVALID when it has valid payload (TDATA / TSTRB / TKEEP /
    TLAST / TID / TDEST / TUSER) to present.
  - The slave asserts TREADY when it is able to accept a transfer.
  - A transfer occurs on the rising edge of ACLK at which BOTH TVALID and TREADY
    are HIGH.

3.2 Handshake rules
-------------------

  - A master is NOT permitted to wait until TREADY is asserted before asserting
    TVALID. Once asserted, TVALID must remain asserted until the transfer
    completes (the cycle in which TREADY is also HIGH).
  - A slave IS permitted to wait for TVALID to be asserted before asserting
    TREADY. A slave may assert TREADY before TVALID; it may also deassert TREADY
    again if no transfer takes place.
  - The master must not change the payload while TVALID is asserted and TREADY is
    not yet asserted; the payload is held stable until the transfer completes.

These rules guarantee that no transfer is lost and that no deadlock occurs from
the master waiting on the slave and the slave waiting on the master.

3.3 Transfer
------------

A TRANSFER is the unit of data movement: one TVALID-and-TREADY cycle moves one
beat of TDATA (and its qualifiers) from the master to the slave.

================================================================================
4. DATA, PACKETS, FRAMES, AND STREAMS
================================================================================

4.1 Stream
----------

A STREAM is the entire sequence of transfers that pass across the interface,
from the source to the sink. A stream can be continuous (back-to-back transfers)
or sparse (transfers separated by idle cycles where TVALID or TREADY is LOW).

4.2 Packet
----------

A PACKET is a group of one or more transfers that are associated together. TLAST
marks the boundary of a packet: the transfer in which TLAST is HIGH is the last
transfer of that packet. A packet is the AXI4-Stream analog of a network frame
or a burst. When TLAST is not used, the stream is treated as a single
indefinitely long packet of unframed data.

4.3 Frame
---------

A FRAME is a higher-level grouping of one or more packets, used in applications
such as video, where a frame is built from many line packets. Framing above the
packet level is application-defined and conveyed through TUSER or TID/TDEST.

4.4 Byte types
--------------

Each byte lane of TDATA, qualified by TKEEP and TSTRB, is one of three BYTE TYPES:

  - DATA byte    : TKEEP = 1, TSTRB = 1. A normal content byte that carries data
                   and must be transmitted to the destination.
  - POSITION byte: TKEEP = 1, TSTRB = 0. A byte that occupies a position in the
                   stream (so the data layout / alignment is preserved) but whose
                   TDATA value carries no data. Used for sparse / aligned streams.
  - NULL byte    : TKEEP = 0, TSTRB = 0. A byte that has no meaning and can be
                   removed from the stream by the interconnect without changing
                   the data; used to pad partial beats.

The combination TKEEP = 0, TSTRB = 1 is not permitted.

A stream in which every byte is a data byte (TKEEP and TSTRB all HIGH) is a
continuous, fully-packed stream; a stream that uses position and null bytes is a
sparse or partially-packed stream.

================================================================================
5. ROUTING: TID AND TDEST
================================================================================

5.1 TID
-------

TID is the data stream identifier. An interconnect can use TID to distinguish
between multiple streams that share a single physical AXI4-Stream channel, and
to keep the transfers of one stream in order while interleaving with another.
The recommended maximum width of TID is 8 bits.

5.2 TDEST
---------

TDEST provides routing information for the data stream: it identifies the
destination to which the interconnect should route the packet. The recommended
maximum width of TDEST is 4 bits. TID and TDEST together let an AXI4-Stream
interconnect implement a routing fabric: a multiplexer / switch reads TDEST to
choose an output port and uses TID to preserve per-stream ordering.

5.3 Ordering
------------

Within a single stream (a single TID/TDEST value) transfers are delivered in
order. The protocol does not define ordering between transfers with different
TID or TDEST values.

================================================================================
6. RESET AND CLOCKING
================================================================================

  - All AXI4-Stream signals are sampled on the rising edge of ACLK.
  - During reset, while ARESETn is LOW, the master must drive TVALID LOW so that
    no transfer is interpreted as valid.
  - A master may only begin to assert TVALID on or after the first rising ACLK
    edge after ARESETn becomes HIGH.
  - There is no requirement on TREADY during reset, but a slave commonly drives
    TREADY LOW during reset.

================================================================================
7. SIGNAL WIDTHS AND PARAMETERS
================================================================================

  TDATA_WIDTH : width of TDATA in bits; an integer number of bytes (multiple of
                8). Common widths are 8, 16, 32, 64, 128, 256, 512, 1024.
  TID_WIDTH   : width of TID; recommended maximum 8 bits.
  TDEST_WIDTH : width of TDEST; recommended maximum 4 bits.
  TUSER_WIDTH : width of TUSER; application-defined. Often expressed as a number
                of user bits per byte lane.
  TSTRB / TKEEP width : TDATA_WIDTH / 8 bits, one bit per byte lane.

================================================================================
8. MUTUAL EXCLUSION FROM MEMORY-MAPPED AXI
================================================================================

The AXI4-Stream protocol is structurally distinct from the memory-mapped AMBA
AXI protocol. The two MUST NOT be conflated:

  - Memory-mapped AXI: five channels (AW write address, W write data, B write
    response, AR read address, R read data); ARVALID / AWVALID / RVALID / BVALID
    / WVALID handshakes; ARADDR / AWADDR address buses; AWLEN / ARLEN burst
    lengths; INCR / WRAP / FIXED burst types; read and write transactions to a
    memory address space.
  - AXI4-Stream: ONE unidirectional stream channel; TVALID / TREADY handshake;
    TDATA / TSTRB / TKEEP / TLAST / TID / TDEST / TUSER payload; NO address, NO
    read/write transaction, NO burst type.

A component that has both a memory-mapped AXI control interface and an
AXI4-Stream data interface keeps them strictly separate: the address channels
belong to the memory-mapped interface, the T-prefixed stream signals belong to
the AXI4-Stream interface.

================================================================================
9. RELATIONSHIP TO OTHER STREAMING INTERFACES
================================================================================

The AXI4-Stream protocol is one of several point-to-point streaming interfaces.
The closest analog is the Intel/Altera Avalon Streaming (Avalon-ST) interface,
which also uses a source/sink handshake with start-of-packet and end-of-packet
framing. The two differ in signal naming and framing: AXI4-Stream uses
TVALID/TREADY with TLAST packet boundaries and TKEEP/TSTRB byte qualifiers,
whereas the Avalon-ST family uses its own packet-framing qualifiers. Bridges
between the two map TLAST to the Avalon-ST end-of-packet qualifier and translate
the two handshakes to each other.

================================================================================
10. TYPICAL USE CASES
================================================================================

  - Video and image pipelines: pixels stream from a sensor or framebuffer reader
    to processing blocks; TLAST marks end-of-line, TUSER marks start-of-frame.
  - Packet processing: network packets stream through classification, filtering,
    and forwarding stages; TLAST marks end-of-packet, TDEST chooses an egress
    port.
  - DMA / accelerator data paths: a DMA engine streams data to and from an
    accelerator using AXI4-Stream while a memory-mapped AXI interface configures
    the accelerator's registers.
  - Digital signal processing: filters, FFTs, and other DSP blocks are chained
    with AXI4-Stream, each block consuming a stream and producing a stream.

================================================================================
11. SUMMARY OF KEY PROPERTIES
================================================================================

  - Single unidirectional point-to-point channel; master (source) to slave
    (sink); no address.
  - TVALID / TREADY handshake; transfer completes when both are HIGH on a rising
    ACLK edge.
  - Payload: TDATA with TSTRB (data vs position byte), TKEEP (null byte), TLAST
    (packet boundary), TID (stream id), TDEST (routing), TUSER (sideband),
    TWAKEUP (v2 wake).
  - Concepts: transfer, packet (TLAST-delimited), frame, stream; byte types
    data / position / null.
  - Interconnect routing via TID / TDEST.
  - Strictly distinct from memory-mapped AXI (no AR/AW/R/W/B channels, no
    ARADDR/AWADDR, no read/write transactions, no INCR/WRAP bursts).
