SpaceWire — Links, Nodes, Routers and Networks
ECSS-E-ST-50-12C (European Cooperation for Space Standardization)

ABSTRACT

SpaceWire is a spacecraft onboard data-handling network standard defined by
the European Cooperation for Space Standardization (ECSS) as ECSS-E-ST-50-12C.
SpaceWire provides high-speed (2 Mbps to over 200 Mbps), bidirectional,
full-duplex, point-to-point serial data links and the routing switches and
networks built from them. A SpaceWire link uses low-voltage differential
signalling (LVDS) and carries Data and Strobe signals (Data-Strobe, DS,
encoding) so that the clock can be recovered as the exclusive-OR (XOR) of the
Data and Strobe signals. SpaceWire is used to connect together the sensors,
processing units, mass-memory units, and downlink telemetry subsystems of a
spacecraft. The standard is based on parts of the IEEE 1355-1995 standard and
the ANSI/TIA/EIA-644 LVDS standard, and it has been developed for use onboard
spacecraft where reliability, fault tolerance, and high data throughput are
required.

1. OVERVIEW AND ARCHITECTURE

SpaceWire is organized as a layered set of protocol levels, in the manner of a
protocol stack. From the lowest to the highest, the levels are:

  - Physical level: connectors, cables, cable assemblies, and printed circuit
    board tracks.
  - Signal level: signal encoding, signal voltage levels, noise margins, and
    data signalling rates. SpaceWire uses LVDS and Data-Strobe (DS) encoding.
  - Character level: data characters and control characters that are passed
    along a link.
  - Exchange level: the protocol for link initialization, flow control, link
    error detection, and link error recovery. The exchange level holds the
    link state machine.
  - Packet level: how data is split up into packets for transfer from source
    to destination across a link or network.
  - Network level: the structure of a SpaceWire network and the way in which
    packets are transferred from a source node to a destination node across a
    network containing routing switches.

A SpaceWire link is a bidirectional, full-duplex, serial, point-to-point data
link connecting two nodes (or a node and a routing switch, or two routing
switches). Each direction of the link carries two signals — Data (D) and
Strobe (S) — so a complete bidirectional link uses four signal pairs. Because
each signal is differential (LVDS), the link comprises eight wires in total:
two differential pairs in each direction (D+ / D- and S+ / S- per direction).

2. SIGNAL LEVEL: LVDS AND DATA-STROBE (DS) ENCODING

SpaceWire uses Data-Strobe (DS) encoding to encode the transmit clock together
with the data into the Data and Strobe signals. The Data signal follows the
data bit stream. The Strobe signal changes state whenever the Data signal does
NOT change from one data bit period to the next. This guarantees that exactly
one of the two signals (Data or Strobe) changes state in each bit period. The
clock can then be recovered at the receiver simply by taking the
exclusive-OR (XOR) of the Data and Strobe signals:

    Clock = Data XOR Strobe

Because only one of the two signals changes per bit, DS encoding tolerates a
large skew between the Data and Strobe wires — up to almost one bit period —
which makes the link robust against cable and routing skew. This is a key
advantage of Data-Strobe encoding over a separately forwarded clock.

The Data and Strobe signals are transmitted using low-voltage differential
signalling (LVDS), to ANSI/TIA/EIA-644. LVDS provides high-speed signalling
with low power consumption, low electromagnetic emission, and good noise
immunity. Each of the Data and Strobe signals is a differential pair: D+ / D-
and S+ / S-. The nominal LVDS differential output voltage is about 350 mV
around a common-mode of about 1.2 V.

SpaceWire links operate at data signalling rates from 2 Mbps up to and beyond
200 Mbps. The initial (default) operating data signalling rate after a reset
is 10 Mbit/s; the link then negotiates up to its operating rate. A typical
operating rate is 200 Mbps.

3. CHARACTER LEVEL

There are two types of character in SpaceWire: data characters and control
characters.

A data character is ten bits long and contains:
  - a parity bit (odd parity, covering the previous parity and following bits),
  - a data-control flag bit (set to 0 to indicate a data character),
  - eight bits of data, transmitted least-significant bit first.

A control character is four bits long and contains:
  - a parity bit,
  - a data-control flag bit (set to 1 to indicate a control character),
  - two control bits that select one of four control codes.

The four control characters are:
  - FCT — Flow Control Token. Used for flow control; signals that the receiver
    has room for a further eight N-Chars (one credit unit of eight characters).
  - EOP — End of Packet (Normal end of packet). Marks the end of a packet.
  - EEP — Error End of Packet. Marks the premature end of a packet due to an
    error detected somewhere in the network.
  - ESC — Escape. Used to form longer control codes in combination with the
    next character.

Two control codes are formed using the ESC character:
  - NULL — formed from ESC followed by FCT (ESC + FCT). NULL characters are
    sent when a link has nothing else to send, to keep the link active and to
    allow the receiver to detect that the other end is still connected.
  - Time-Code — formed from ESC followed by a single data character (ESC +
    data character). Time-Codes distribute system time across a SpaceWire
    network; a Time-Code carries a six-bit time value plus two control flags.

The combination of data characters and control characters that are passed
along the link for flow control and packet framing are referred to as
N-Chars (normal characters: data characters, EOP, and EEP) and L-Chars (link
characters: FCT, ESC, NULL, and Time-Codes), where N-Chars are passed up to
the host and L-Chars are consumed by the link interface itself.

4. EXCHANGE LEVEL: LINK INITIALIZATION STATE MACHINE

The exchange level operates the link by means of a state machine. After reset,
the link interface state machine moves through the following states:

  - ErrorReset — entered after a reset or a link error. All transmit and
    receive activity is stopped; the transmitter and receiver are reset. The
    state machine remains here for 6.4 microseconds (the reset time) before
    moving to ErrorWait.
  - ErrorWait — the state machine waits for 12.8 microseconds while looking for
    received activity. If a disconnection or parity error or escape error is
    detected the state machine returns to ErrorReset; otherwise it moves to
    Ready.
  - Ready — the link is ready to start. The state machine waits in Ready until
    it is enabled to start (either Start or AutoStart is asserted), then it
    moves to Started.
  - Started — the transmitter is enabled and sends NULL characters. The state
    machine waits in Started for the receiver to receive a NULL (indicating the
    other end has also started); when a NULL is received it moves to Connecting.
    If a NULL is not received within 12.8 microseconds, it returns to
    ErrorReset.
  - Connecting — the transmitter is now enabled to send FCTs as well as NULLs.
    The state machine waits for the receiver to receive an FCT (indicating the
    other end has credit to give); when an FCT is received it moves to Run.
    If an FCT is not received within 12.8 microseconds, it returns to
    ErrorReset.
  - Run — the link is fully operational. The transmitter may now send NULLs,
    FCTs, Time-Codes, data characters, EOPs and EEPs. Normal data transfer with
    credit-based flow control takes place in the Run state. A disconnection,
    parity error, escape error, or credit error returns the state machine to
    ErrorReset.

The progression ErrorReset -> ErrorWait -> Ready -> Started -> Connecting ->
Run is the SpaceWire link initialization handshake. Both ends of a link run the
same state machine, and they synchronize by the exchange of NULLs (to confirm
the link is connected) and FCTs (to confirm credit before data flows).

5. EXCHANGE LEVEL: CREDIT-BASED FLOW CONTROL

SpaceWire uses credit-based flow control to prevent a receiver buffer from
overflowing. Each FCT (Flow Control Token) that a receiver sends to the
transmitter at the other end of the link grants permission to send eight
further N-Chars. The transmitter keeps a credit count: each received FCT adds
eight to the credit, and each N-Char transmitted subtracts one from the credit.
The transmitter may only send an N-Char when its credit count is greater than
zero. A maximum of seven outstanding FCTs may be sent (giving a maximum
outstanding credit of 56 N-Chars), bounded by the size of the receive buffer.
If the transmitter sends an N-Char with no credit, a credit error occurs and
the link is reset (the state machine returns to ErrorReset).

6. EXCHANGE LEVEL: LINK ERROR DETECTION AND RECOVERY

The following link errors are detected at the exchange level:
  - Disconnect error — the gap between transitions on the receive Data/Strobe
    pair exceeds the disconnect timeout (about 850 nanoseconds), indicating the
    other end has stopped transmitting.
  - Parity error — the odd parity covering each character fails.
  - Escape error — an ESC character is followed by another ESC or by an EOP/EEP
    (an invalid escape sequence).
  - Credit error — an N-Char arrives when the receiver has granted no credit, or
    the transmitter attempts to send with no credit.

When any of these errors is detected, the link interface goes to ErrorReset,
silences its transmitter, and re-runs the link initialization handshake
(ErrorReset -> ErrorWait -> Ready -> Started -> Connecting -> Run). This
exchange-of-silence recovery resynchronizes both ends of the link.

7. PACKET LEVEL

Data is transferred across a SpaceWire link or network in packets. A SpaceWire
packet has the form:

    <Destination Address> <Cargo> <End of Packet Marker>

  - Destination Address — zero or more data characters at the start of the
    packet that determine the route the packet takes to its destination. The
    address may be a path address (a sequence of output port numbers, each
    consumed by a router as the packet passes through), a logical address (a
    single byte identifying the destination node, used with routing tables), or
    a combination (regional logical addressing).
  - Cargo — the data to be transferred (any number of data characters).
  - End of Packet Marker — EOP for a normal end of packet, or EEP for an error
    end of packet.

Packets may be of arbitrary length; there is no maximum packet size defined by
the standard. The EOP (or EEP) delimits one packet from the next.

8. NETWORK LEVEL: ROUTERS, WORMHOLE ROUTING, ADDRESSING

A SpaceWire network is built from nodes and routing switches (routers)
connected by SpaceWire links. A routing switch has a number of SpaceWire link
ports plus an internal configuration port (port 0). The router transfers a
packet from an input port to an output port using wormhole routing: as soon as
the header (destination address) of a packet has been received and the output
port determined, the packet begins to be forwarded out of that output port,
without waiting for the whole packet to arrive. The packet "worms" through the
router; the router holds only the head of the packet at any instant.

Three addressing methods are supported:
  - Path addressing — the leading data character of the packet is an output
    port number (1 to 31). The router uses it to select the output port and
    then deletes that leading character (so the next router sees the next port
    number). Path addresses are consumed hop by hop.
  - Logical addressing — the leading data character is a logical address (32 to
    255) that identifies the destination node. Each router contains a routing
    table that maps the logical address to an output port. The logical address
    is NOT deleted, so every router uses the same logical address.
  - Regional logical addressing — a combination of path and logical addressing
    used to route within and between regions of a large network.

Group adaptive routing allows a logical address to map to a group of output
ports, any of which may be used to reach the destination; the router picks a
free port from the group, providing load sharing and redundancy.

The configuration port (port 0) of a router gives access to the router's
configuration registers (routing table, port control and status, error and
status registers) by means of Remote Memory Access Protocol (RMAP) commands or
SpaceWire packets addressed to port 0.

9. TIME-CODES (SYSTEM TIME DISTRIBUTION)

SpaceWire distributes system time using Time-Codes. A Time-Code is sent as an
ESC character followed by a single data character. The data character carries a
six-bit time value (the time counter, 0 to 63) and two control flags. A time
master broadcasts Time-Codes across the network; each node and router that
receives a Time-Code checks that the new time value is one greater (modulo 64)
than the last value it received, and if so it forwards the Time-Code out of all
of its other link ports and signals the new time value (a "tick") to its host.
This distributes a synchronized system time across the whole network with low
latency and jitter.

10. RMAP (REMOTE MEMORY ACCESS PROTOCOL) OVERVIEW

The Remote Memory Access Protocol (RMAP, ECSS-E-ST-50-52C) is a higher-level
protocol that runs over SpaceWire. RMAP allows one node (an initiator) to read
from, write to, and read-modify-write the memory and registers of another node
(a target) across the SpaceWire network, without any software running on the
target. RMAP commands (write, read, read-modify-write) are carried in SpaceWire
packets; the target executes the memory access and returns a reply packet.
RMAP includes a header CRC and a data CRC for integrity, and a logical address,
key, and transaction identifier for addressing and matching replies to
commands. RMAP is widely used to configure SpaceWire routers (through the
configuration port) and to access remote memory and registers.

11. PHYSICAL LEVEL: CONNECTOR AND CABLE

The standard SpaceWire connector is a 9-pin micro-miniature D-type connector.
The eight signal wires (Data and Strobe differential pairs in each direction)
plus the inner shield are carried on the connector; the cable consists of four
twisted shielded pairs with an overall shield. The signal pairs are:

  - Din+  / Din-   : Data,   inbound  direction (received Data signal)
  - Sin+  / Sin-   : Strobe, inbound  direction (received Strobe signal)
  - Dout+ / Dout-  : Data,   outbound direction (transmitted Data signal)
  - Sout+ / Sout-  : Strobe, outbound direction (transmitted Strobe signal)

Each pair is a differential LVDS pair. There is no separately forwarded clock
wire — the clock is recovered from the Data and Strobe signals by the
exclusive-OR relationship described in section 2.

12. KEY PARAMETERS SUMMARY

  - Standard:                ECSS-E-ST-50-12C (SpaceWire — Links, Nodes,
                             Routers and Networks)
  - Signalling:              LVDS (ANSI/TIA/EIA-644), differential
  - Encoding:                Data-Strobe (DS); Clock = Data XOR Strobe
  - Signals per direction:   2 (Data and Strobe), each a differential pair
  - Differential pairs:      4 per bidirectional link (8 wires)
  - Duplex:                  full-duplex, bidirectional, point-to-point
  - Data signalling rate:    2 Mbps to 200+ Mbps (default 10 Mbit/s at reset)
  - Data character:          10 bits (parity + data-control flag + 8 data bits)
  - Control character:       4 bits (parity + data-control flag + 2 control bits)
  - Control characters:      FCT, EOP, EEP, ESC
  - Composite codes:         NULL (ESC+FCT), Time-Code (ESC + data character)
  - Exchange state machine:  ErrorReset, ErrorWait, Ready, Started, Connecting,
                             Run
  - Flow control:            credit-based; one FCT grants 8 N-Chars; max 56
                             outstanding (7 FCTs)
  - Time distribution:       Time-Codes (6-bit time value)
  - Routing:                 wormhole routing through routers; path, logical,
                             and regional logical addressing; group adaptive
                             routing; configuration port (port 0)
  - Higher-level protocol:   RMAP (ECSS-E-ST-50-52C) for remote memory access
  - Disconnect timeout:      about 850 ns
  - Heritage:                based on IEEE 1355-1995 and ANSI/TIA/EIA-644 LVDS
