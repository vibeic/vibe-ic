Fibre Channel — Information Technology Standard
INCITS T11 Fibre Channel Framing and Signaling (FC-FS) / Physical and Signaling Interface (FC-PH)

ABSTRACT

Fibre Channel is a high-speed serial storage and networking interconnect for
Storage Area Networks (SAN). It is standardized by the INCITS T11 technical
committee (FC-PH, FC-FS, FC-FS-2 ... FC-FS-5). Fibre Channel defines a layered
architecture (FC-0 through FC-4): the FC-0 physical layer, the FC-1 transmission
layer (8b/10b or 64b/66b encoding and ordered sets), the FC-2 framing and
signaling layer (the frame, sequence, and exchange constructs plus flow control),
the FC-3 common services layer, and the FC-4 upper-level-protocol mapping layer
(for example FCP, which carries SCSI commands over Fibre Channel). Fibre Channel
connects N_Ports (node ports), F_Ports (fabric ports), and E_Ports (expansion
ports between switches) using three topologies: point-to-point, arbitrated loop
(FC-AL), and switched fabric. End devices acquire a 24-bit Fibre Channel address
identifier at login and are uniquely identified by a 64-bit World Wide Name
(WWN). Frames are delimited by Start-of-Frame (SOF) and End-of-Frame (EOF)
ordered sets, carry a 24-byte frame header and a payload of up to 2112 bytes,
and are protected by a 32-bit CRC. Flow control uses buffer-to-buffer credit
(BB_Credit) and end-to-end credit (EE_Credit). Login is performed with FLOGI
(fabric login), PLOGI (port login), and PRLI (process login). Fibre Channel
over Ethernet (FCoE) extends Fibre Channel framing across lossless Ethernet.

1. OVERVIEW

Fibre Channel (FC) is a gigabit-speed, serial, full-duplex interconnect designed
to transport storage traffic (most commonly SCSI through the FCP mapping) with
low latency and high reliability. A Fibre Channel link is a pair of
unidirectional fibres (or copper differential pairs): one transmit and one
receive. Fibre Channel is organized as five functional levels, FC-0 through
FC-4:

  - FC-0 Physical layer: the media, transmitters and receivers, connectors, and
    electrical/optical characteristics. Defines the gigabaud signaling rates.
  - FC-1 Transmission layer: byte encoding and decoding. 8b/10b encoding is used
    at 1/2/4/8 GFC; 64b/66b encoding is used at 16 GFC and above. Ordered sets
    (special transmission words built from K28.5 and other special characters)
    provide frame delimiters, primitive signals, and primitive sequences.
  - FC-2 Framing and Signaling layer: the heart of Fibre Channel. Defines the
    frame, the sequence (a set of related frames), and the exchange (a set of
    related sequences), plus flow control (BB_Credit and EE_Credit), classes of
    service, and the login/logout protocols.
  - FC-3 Common Services layer: services that span multiple ports of a node,
    such as striping, hunt groups, and multicast.
  - FC-4 Upper Level Protocol (ULP) mapping layer: maps an upper-level protocol
    onto Fibre Channel. The dominant mapping is FCP (Fibre Channel Protocol for
    SCSI), which carries SCSI commands, data, and status. Other mappings include
    FC-NVMe, IP over Fibre Channel, and FICON.

2. PORTS AND TOPOLOGIES

Fibre Channel defines several port types according to their role:

  - N_Port (Node Port): a port on an end node (host bus adapter or storage
    target) used in point-to-point or switched-fabric topologies.
  - F_Port (Fabric Port): a port on a fabric switch that attaches to an N_Port.
  - E_Port (Expansion Port): an inter-switch port that links two switches to
    build a multi-switch fabric (the link between two E_Ports is an Inter-Switch
    Link, ISL).
  - NL_Port (Node Loop Port): an N_Port capable of arbitrated-loop operation.
  - FL_Port (Fabric Loop Port): an F_Port that attaches an arbitrated loop to a
    fabric.
  - G_Port: a generic switch port that becomes an F_Port or E_Port after it
    determines what is attached.

Three topologies are supported:

  - Point-to-point: a direct N_Port-to-N_Port link between exactly two devices;
    the full link bandwidth is dedicated to the pair.
  - Arbitrated loop (FC-AL): up to 126 NL_Ports (plus one optional FL_Port)
    share a loop. A port arbitrates for the loop using the ARB ordered set,
    wins access, opens a connection (OPN) to a destination, transfers frames,
    and closes (CLS). Loop initialization assigns each port an 8-bit Arbitrated
    Loop Physical Address (AL_PA).
  - Switched fabric: one or more switches interconnect N_Ports through F_Ports;
    the fabric routes frames by destination address. Fabrics scale to millions
    of addressable ports and provide fabric services (Name Server, Fabric
    Controller, Management Server).

3. ADDRESSING AND NAMING

Every Fibre Channel port and node carries a 64-bit World Wide Name (WWN), a
globally unique identifier assigned by the manufacturer. A node has a World Wide
Node Name (WWNN) and each port has a World Wide Port Name (WWPN). The WWN is
analogous to a burned-in MAC address: it is permanent and used for naming, zoning,
and authentication.

For routing, a port uses a 24-bit Fibre Channel address identifier (also called
the Port_ID or N_Port_ID). In a switched fabric this 24-bit address is assigned
by the fabric during FLOGI and is structured as three 8-bit fields:

  - Domain_ID (bits 23..16): identifies the switch (domain) within the fabric.
  - Area_ID (bits 15..8): identifies a group of ports within a domain.
  - Port_ID (bits 7..0): identifies the individual port within the area.

Well-known fabric service addresses occupy the reserved range 0xFFFFF0..0xFFFFFE.
Examples: Fabric F_Port 0xFFFFFE, Fabric Controller 0xFFFFFD, Name Server
0xFFFFFC, Time Server 0xFFFFFB, Management Server 0xFFFFFA, Broadcast 0xFFFFFF.

4. FC-2 FRAME FORMAT

The fundamental unit of transfer at FC-2 is the frame. A frame is bounded by an
SOF ordered set at the start and an EOF ordered set at the end, with a 24-byte
frame header, an optional set of optional headers, a data field (payload), and a
4-byte (32-bit) CRC, in this order:

  SOF | Frame Header (24 bytes) | Data Field (0..2112 bytes) | CRC (4 bytes) | EOF

The 24-byte frame header contains the following fields:

  - R_CTL  (Routing Control, 1 byte): frame category (e.g. FC-4 device data,
    link control, extended/basic link service) and information category.
  - D_ID   (Destination address identifier, 3 bytes / 24 bits): the 24-bit FC
    address of the destination port.
  - CS_CTL/Priority (1 byte): class-specific control or priority.
  - S_ID   (Source address identifier, 3 bytes / 24 bits): the 24-bit FC address
    of the source port.
  - TYPE   (1 byte): the FC-4 upper-level protocol type (e.g. 0x08 = FCP,
    0x05 = IP over FC, 0x20 = FC-CT).
  - F_CTL  (Frame Control, 3 bytes): control bits — first/last sequence,
    exchange originator/responder context, sequence initiative, relative offset
    present, end-of-sequence, abort sequence condition.
  - SEQ_ID (Sequence Identifier, 1 byte): identifies the sequence to which this
    frame belongs.
  - DF_CTL (Data Field Control, 1 byte): which optional headers are present.
  - SEQ_CNT (Sequence Count, 2 bytes): the sequential count of the frame within
    its sequence.
  - OX_ID  (Originator Exchange Identifier, 2 bytes): the exchange ID assigned by
    the originator.
  - RX_ID  (Responder Exchange Identifier, 2 bytes): the exchange ID assigned by
    the responder.
  - Parameter (4 bytes): relative offset of the payload, or link-control
    parameter, depending on frame type.

The maximum payload (Data Field) is 2112 bytes. Frames are protected by a 32-bit
CRC computed over the frame header and data field.

5. SEQUENCES AND EXCHANGES

Fibre Channel structures information transfer hierarchically:

  - Frame: the smallest indivisible unit (header + payload + CRC), tagged with
    SEQ_ID and SEQ_CNT.
  - Sequence: one or more related frames flowing in the same direction, all
    carrying the same SEQ_ID, ordered by SEQ_CNT. A sequence is the unit of error
    recovery; the recipient validates the sequence and acknowledges (in
    acknowledged classes) per frame or per sequence.
  - Exchange: one or more nonconcurrent sequences for a single operation,
    identified by the OX_ID/RX_ID pair. The exchange originator allocates the
    OX_ID; the responder allocates the RX_ID. An exchange maps to one ULP
    operation (for example one SCSI command in FCP).

Sequence initiative governs which side may transmit the next sequence within an
exchange; it is passed via F_CTL.

6. CLASSES OF SERVICE

Fibre Channel defines several classes of service that trade off connection,
acknowledgement, and bandwidth guarantees:

  - Class 1: a dedicated connection between two N_Ports with confirmed delivery
    (acknowledged); the full bandwidth of the path is reserved for the duration.
  - Class 2: connectionless, frame-switched, acknowledged delivery; each frame is
    acknowledged (ACK) and uses end-to-end credit; frames may take different
    routes.
  - Class 3: connectionless, frame-switched, unacknowledged ("datagram")
    delivery; no ACK and only buffer-to-buffer credit. Class 3 is the most widely
    deployed class for SCSI/FCP traffic.
  - Class F: used only between switches (E_Port to E_Port) to carry internal
    fabric control, routing, and management traffic; connectionless and
    acknowledged.

7. FLOW CONTROL

Fibre Channel uses credit-based flow control to prevent receiver buffer overflow:

  - Buffer-to-Buffer credit (BB_Credit): managed link-by-link between two
    directly attached ports. The receiver advertises the number of buffers
    (BB_Credit) it has during login; the transmitter may send that many frames
    before it must wait. The receiver returns an R_RDY primitive signal for each
    buffer it frees. BB_Credit is essential over long-distance links.
  - End-to-End credit (EE_Credit): managed between the two communicating N_Ports
    (source and destination) for the acknowledged classes (Class 1 and Class 2).
    The destination returns an ACK frame, which replenishes EE_Credit. Class 3
    uses only BB_Credit (no EE_Credit, no ACK).

8. LOGIN AND SERVICES

Before data transfer a port performs a login sequence using Extended Link
Services (ELS):

  - FLOGI (Fabric Login): an N_Port logs in to the fabric (the F_Port at address
    0xFFFFFE). The fabric assigns the N_Port its 24-bit FC address identifier and
    exchanges service parameters (BB_Credit, supported classes, maximum frame
    size). In point-to-point or loop without a fabric, FLOGI is not used (or is
    rejected) and the ports negotiate directly.
  - PLOGI (Port Login): an N_Port logs in to another N_Port (or to a well-known
    service such as the Name Server at 0xFFFFFC) to exchange service parameters
    (WWN, EE_Credit, supported classes, maximum payload) and establish an
    end-to-end session.
  - PRLI (Process Login): establishes the FC-4 (ULP) session between two ports —
    for FCP it negotiates initiator/target roles and FCP service parameters.
  - LOGO (Logout): tears down a login.

Fabric services live at well-known addresses: the Name Server (0xFFFFFC) provides
device discovery and name-to-address resolution; the Fabric Controller (0xFFFFFD)
manages State Change Notifications (RSCN); the Management Server (0xFFFFFA)
provides management.

9. FC-4 MAPPING: FCP (SCSI OVER FIBRE CHANNEL)

FCP is the FC-4 mapping that carries SCSI over Fibre Channel. An FCP I/O
operation is a single Fibre Channel exchange consisting of the following
information units (IUs):

  - FCP_CMND: carries the SCSI Command Descriptor Block (CDB), the logical unit
    number (LUN), and task attributes (initiator -> target).
  - FCP_XFER_RDY: the target tells the initiator it is ready to receive (or send)
    a specified amount of write/read data (target -> initiator).
  - FCP_DATA: carries the SCSI data (one or more sequences in either direction).
  - FCP_RSP: carries SCSI status, sense data, and residual counts at completion
    (target -> initiator).

Each FCP IU is carried in a Fibre Channel sequence; the whole I/O is one
exchange (OX_ID/RX_ID). The TYPE field in the frame header is set to 0x08 to
identify FCP.

10. SIGNALING RATES

Fibre Channel signaling rates are expressed in GFC (gigabaud Fibre Channel) and
have approximately doubled each generation:

  - 1GFC  : ~1.0625 Gbaud, 8b/10b
  - 2GFC  : ~2.125  Gbaud, 8b/10b
  - 4GFC  : ~4.25   Gbaud, 8b/10b
  - 8GFC  : ~8.5    Gbaud, 8b/10b
  - 16GFC : ~14.025 Gbaud, 64b/66b
  - 32GFC : ~28.05  Gbaud, 64b/66b
  - 64GFC : ~56.1   Gbaud, 64b/66b (PAM-4)
  - 128GFC: 4-lane aggregation of 32GFC lanes

A device negotiates the highest mutually supported rate during speed
negotiation; backward compatibility to lower rates is required.

11. ORDERED SETS AND PRIMITIVES (FC-1/FC-2)

Ordered sets are 4-byte transmission words beginning with the K28.5 special
character. Three kinds exist:

  - Frame delimiters: SOF (Start of Frame, several variants by class —
    SOFi1/SOFn1/SOFi2/SOFn2/SOFi3/SOFn3/SOFf) and EOF (End of Frame —
    EOFn/EOFt/EOFa, etc.) that bound each frame.
  - Primitive signals: ordered sets that have a meaning by themselves, such as
    IDLE (sent when no frames are flowing) and R_RDY (returns a BB_Credit
    buffer).
  - Primitive sequences: repeated ordered sets that signal a link condition,
    such as NOS (Not Operational), OLS (Offline), LR (Link Reset), and LRR (Link
    Reset Response), used to bring the link up and to recover it.

12. LINK INITIALIZATION AND ERROR RECOVERY

A Fibre Channel point-to-point or fabric link is brought up through the primitive
sequence protocol: a port that is not operational transmits NOS; the partner
responds with OLS, then LR, then LRR, until both ends reach the Active state and
exchange IDLEs. Loop initialization (LIP) is used on FC-AL to reset the loop and
assign AL_PAs.

Error recovery operates at the sequence and exchange level. A missing or corrupt
frame (bad CRC, lost frame, timeout) causes the sequence to be aborted; the
exchange originator may issue ABTS (Abort Sequence) to abort the sequence or
exchange and the recipient responds. Higher-level recovery (Exchange-level error
recovery, FCP retry) is provided by the FC-4 ULP.

13. FIBRE CHANNEL OVER ETHERNET (FCoE)

FCoE encapsulates complete Fibre Channel frames inside Ethernet frames (EtherType
0x8906) so that Fibre Channel can run over a lossless (priority-flow-control)
Ethernet data-center network, converging SAN and LAN onto one fabric. The FCoE
Initialization Protocol (FIP, EtherType 0x8914) handles discovery and login
(FLOGI/FDISC) over Ethernet. FCoE preserves the FC-2 frame, sequence, exchange,
and login model unchanged; only FC-0/FC-1 are replaced by Ethernet.

14. COMPLIANCE AND INTEROPERABILITY

A conformant Fibre Channel implementation must: implement the FC-0..FC-2 levels
(at minimum) with at least one FC-4 mapping (typically FCP); support the frame
format with the 24-byte header (R_CTL/D_ID/S_ID/TYPE/F_CTL/SEQ_ID/SEQ_CNT/
OX_ID/RX_ID) and 32-bit CRC; support sequences and exchanges; implement
buffer-to-buffer credit flow control (and end-to-end credit for the acknowledged
classes); support the login protocol (FLOGI/PLOGI/PRLI) and well-known fabric
service addresses; and negotiate signaling rate and service parameters. The
INCITS T11 family (FC-FS, FC-LS for link services, FC-SW for switch fabric,
FC-GS for generic services, FCP for the SCSI mapping) defines the full
conformance surface.
