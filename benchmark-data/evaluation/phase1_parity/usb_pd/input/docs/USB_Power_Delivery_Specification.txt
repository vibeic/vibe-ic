USB Power Delivery Specification
Revision 3.1, Version 1.8, USB Implementers Forum (USB-IF)

1. Introduction
The USB Power Delivery (USB-PD) Specification defines power and data role
negotiation conducted over the USB Type-C Configuration Channel (CC) wire.
USB-PD is DISTINCT from USB 2.0 data transfer (which uses the D+/D- pair, NRZI
line coding, packet IDs and endpoints) and from USB4 (which tunnels USB 3.x,
DisplayPort and PCI Express at 20/40/80 Gbps over routers). USB-PD instead runs
a low-speed signalling channel on CC to negotiate the power contract between a
Source and a Sink and to swap power, data, and VCONN roles. The maximum
negotiated power in Revision 3.1 is 240 W (Extended Power Range, 48 V at 5 A).

2. Signal Definition
The USB-PD physical interface uses the USB Type-C wires:
  CC1, CC2  - Configuration Channel. PD communication is carried on whichever CC
              wire is connected through the cable (the other is used for VCONN or
              cable orientation). Single-ended, referenced to GND.
  VBUS      - Bus power. The Source supplies VBUS; the negotiated contract sets
              its voltage (5 V default, up to 48 V) and current.
  VCONN     - Powers the electronically marked cable (eMarker) and is supplied on
              the CC pin not used for communication.
  GND       - Ground return.
The Port Partner that currently sources VBUS is the Source; the partner that
sinks VBUS is the Sink. The DFP (Downstream Facing Port) and UFP (Upstream
Facing Port) define the initial data role.

3. Line Coding (Physical Layer)
USB-PD uses Biphase Mark Coding (BMC) on the CC wire at a nominal 300 kbaud.
BMC guarantees at least one transition per bit (a transition at every bit
boundary, plus a mid-bit transition for a logic 1) so the receiver recovers
clock from the data. The unit interval (UI) is nominally 3.33 us. BMC replaces
the BFSK coding used by the earlier PD 1.0 over VBUS.

4. Packet Framing
A PD packet on CC is framed as:
  Preamble        - 64-bit alternating 0/1 pattern for receiver synchronization.
  SOP* ordered set- 4 K-codes identifying the packet target:
                      SOP   = Sync-1 Sync-1 Sync-1 Sync-2   (port-to-port message)
                      SOP'  = Sync-1 Sync-1 Sync-3 Sync-3   (to the near-end cable plug)
                      SOP'' = Sync-1 Sync-3 Sync-1 Sync-3   (to the far-end cable plug)
                      Hard Reset  = RST-1 RST-1 RST-1 RST-2
                      Cable Reset = RST-1 Sync-1 RST-1 Sync-3
  Message Header  - 16 bits (see Section 6).
  Data Objects    - 0 to 7 32-bit data objects (only in Data and Extended msgs).
  CRC-32          - 32-bit CRC over the header and data objects (polynomial
                    0x04C11DB7, the IEEE 802.3 CRC-32).
  EOP             - End Of Packet K-code marks the end of the frame.
Each 8-bit data is line-coded with the 4b5b table; K-codes are the non-data 5b
symbols (Sync-1/Sync-2/Sync-3, RST-1/RST-2, EOP).

5. Roles and Role Swaps
USB-PD defines orthogonal roles that can be swapped after a contract exists:
  Power Role  - Source (supplies VBUS) or Sink (consumes VBUS). Swapped with
                PR_Swap.
  Data Role   - DFP or UFP (host/device). Swapped with DR_Swap.
  VCONN Role  - which partner supplies VCONN. Swapped with VCONN_Swap.
The Source is the default initiator of the power contract.

6. Message Header (16 bits)
  Bits 3:0    Message Type (selects the control or data message)
  Bit 4       Port Data Role (0=UFP, 1=DFP)
  Bits 6:5    Specification Revision (00=Rev1.0, 01=Rev2.0, 10=Rev3.0/3.1)
  Bit 7       Port Power Role / Cable Plug
  Bits 10:8   Message ID (rolling counter for retransmission detection)
  Bits 14:11  Number of Data Objects (0 = Control message, 1-7 = Data message)
  Bit 15      Extended (1 = Extended message with an Extended Message Header)

7. Message Classes and Message Types
Control Messages (Number of Data Objects = 0):
  0x01  GoodCRC          Acknowledges error-free receipt of the previous message
  0x02  GotoMin          Sink must drop to its minimum operating current
  0x03  Accept           Request / swap accepted
  0x04  Reject           Request / swap rejected
  0x05  Ping             Source keep-alive
  0x06  PS_RDY           Power Supply ready at the new contract voltage
  0x07  Get_Source_Cap   Ask the partner to send its Source_Capabilities
  0x08  Get_Sink_Cap     Ask the partner to send its Sink_Capabilities
  0x09  DR_Swap          Request a Data Role swap
  0x0A  PR_Swap          Request a Power Role swap
  0x0B  VCONN_Swap       Request a VCONN Source swap
  0x0C  Wait             Defer the request, try again later
  0x0D  Soft_Reset       Reset protocol layer (MessageID) without removing VBUS
Data Messages (Number of Data Objects >= 1):
  0x01  Source_Capabilities  Source advertises its list of PDOs
  0x02  Request              Sink requests one PDO via an RDO
  0x03  BIST                 Built-In Self Test
  0x04  Sink_Capabilities    Sink advertises its list of Sink PDOs
  0x0F  Vendor_Defined       Vendor Defined Message (VDM), e.g. Alternate Mode
Extended Messages set Header bit 15 and add an Extended Message Header for
chunked payloads (e.g. Source_Capabilities_Extended, Battery_Status).

8. Power Data Objects (PDO) - advertised by the Source
Each PDO is a 32-bit object. Bits 31:30 select the PDO type:
  0b00  Fixed Supply                - fixed voltage (50 mV units), max current (10 mA units)
  0b01  Battery                     - min/max voltage and max power
  0b10  Variable Supply (non-batt)  - min/max voltage and max current
  0b11  Augmented PDO (APDO)        - Programmable Power Supply (PPS): a
                                      programmable voltage range in 20 mV steps
                                      and current limit in 50 mA steps
The first PDO of a Source is always the 5 V Fixed Supply (vSafe5V). PDOs are
advertised in increasing voltage order.

9. Request Data Object (RDO) - issued by the Sink
The Sink picks one advertised PDO and replies with a 32-bit RDO:
  Bits 30:28  Object Position (1-based index of the selected PDO)
  Bit 27      GiveBack Flag
  Bit 26      Capability Mismatch (Sink needs more than offered)
  Bit 25      USB Communications Capable
  Bits 19:10  Operating Current (10 mA units)
  Bits 9:0    Maximum Operating Current (10 mA units)
For an APDO the RDO carries the programmed Output Voltage (20 mV units) instead.

10. Contract Negotiation (the Explicit Contract handshake)
  1. Source sends Source_Capabilities (its PDO list) on SOP.
  2. Sink replies with Request carrying an RDO selecting one PDO.
  3. Source replies Accept (or Reject / Wait).
  4. Source transitions VBUS to the new voltage, then sends PS_RDY.
  5. The Explicit Contract is now in place; either partner may later issue
     PR_Swap, DR_Swap or VCONN_Swap.
Every received message is acknowledged with GoodCRC before the next message.

11. Reset Mechanisms
  Soft Reset  - Soft_Reset message resets the MessageID counters and protocol
                layer; VBUS and the contract are preserved.
  Hard Reset  - Hard Reset ordered set forces VBUS to vSafe0V (or vSafe5V if the
                Source must keep USB alive), tears down the contract and returns
                both partners to their default power roles.
  Cable Reset - Cable Reset ordered set resets the cable plug (SOP'/SOP'')
                without disturbing the port-to-port contract.

12. Timing
  UI (BMC unit interval)        3.33 us nominal (300 kbaud)
  tReceive (inter-frame gap)    min 0.75 ms, max 1.0 ms
  tTransmit                     max 195 us between messages of a burst
  CRCReceiveTimer               min 0.9 ms, max 1.1 ms (GoodCRC must arrive)
  tSenderResponse               min 24 ms, max 30 ms (Accept/Reject latency)
  PSTransitionTimer             min 450 ms, max 550 ms (VBUS to new contract)
  tHardReset complete           max 5 ms

13. Built-In Self Test (BIST)
The BIST data message places the partner into a test mode: BIST Carrier Mode
transmits a continuous carrier on CC for eye-diagram measurement; BIST Test Data
exercises the receiver with a known pattern.
