MIPI Alliance Specification for Camera Serial Interface 2 (CSI-2)

MIPI CSI-2 — Camera Serial Interface 2
Version 2.0 / 3.0 family (D-PHY and C-PHY physical layer options)
Copyright (c) MIPI Alliance, Inc.

================================================================================
1. SCOPE AND OVERVIEW
================================================================================

The MIPI Camera Serial Interface 2 (CSI-2) specification defines a high-speed
serial interface between a peripheral device — an image sensor (the CSI-2
transmitter) — and a host processor / application processor (the CSI-2
receiver). CSI-2 carries pixel image data and embedded data from the camera
sensor to the host in a unidirectional, high-bandwidth point-to-point link.

CSI-2 is the camera (image capture) counterpart to MIPI DSI (Display Serial
Interface). Where DSI streams pixels from the host to a display panel, CSI-2
streams pixels from an image sensor up to the host. CSI-2 is NOT a display
interface and does NOT define a Display Command Set (DCS), Video Mode /
Command Mode display operation, or a panel/host display link. CSI-2 is the
camera/image-sensor data path.

CSI-2 is built as a layered protocol:
  - Physical Layer (PHY): either MIPI D-PHY (clock lane + 1 to 4 or more data
    lanes, source-synchronous, HS and LP signaling) or MIPI C-PHY (three-wire
    trios / lanes using a 3-phase symbol encoding). The data path is the same
    Low Level Protocol regardless of PHY choice.
  - Lane Management Layer: lane distribution (Tx) and lane merging (Rx) spread
    the byte stream across the active data lanes and reassemble it.
  - Low Level Protocol (LLP): Short Packets and Long Packets, packet header,
    Error Correction Code (ECC), packet footer checksum (CRC).
  - Pixel-to-Byte Packing Layer: maps image pixels of a given Data Type
    (RAW8, RAW10, YUV422, RGB888, etc.) onto the byte stream.
  - Application Layer: the image data formats and embedded data.

A separate sideband control channel, the Camera Control Interface (CCI), is an
I2C-based (or I3C-based) two-wire bus used by the host to configure the image
sensor (resolution, frame rate, exposure, gain, register writes). CCI is
DISTINCT from the high-speed CSI-2 data path: CCI carries control/register
traffic, the CSI-2 lanes carry image pixel data.

================================================================================
2. PHYSICAL LAYER
================================================================================

2.1 D-PHY option

When CSI-2 uses D-PHY, the link consists of:
  - One Clock Lane (a differential source-synchronous clock from the sensor to
    the host; double-data-rate, so each clock edge clocks a bit on the data
    lanes).
  - One to N Data Lanes (typically 1, 2, 4; higher lane counts are allowed).
    Each data lane is a differential pair (Dp / Dn).

Each D-PHY lane operates in two signaling modes:
  - High-Speed (HS) mode: low-swing differential signaling for the burst
    transfer of image data at high bit rates (hundreds of Mbps to multiple
    Gbps per lane).
  - Low-Power (LP) mode: large-swing single-ended signaling used between HS
    bursts for control, line/frame turnaround, and low-power state escape.

The transmitter places lanes into HS mode for the duration of a packet burst
(HS-Entry, HS data, HS-Trail, HS-Exit), and returns to LP-11 stop state
between bursts.

2.2 C-PHY option

When CSI-2 uses C-PHY, each lane is a three-wire trio (A / B / C). C-PHY uses a
3-phase symbol encoding; the clock is embedded in the symbol transitions
(no separate clock lane). C-PHY encodes ~2.28 bits per symbol (16 bits per
7 symbols) and is used to reach higher throughput on fewer wires. The Low
Level Protocol (Short / Long Packets, Data Identifier, Word Count, ECC,
checksum) is identical on C-PHY; only the PHY symbol mapping differs.

2.3 Lane distribution and merging

On the transmitter side the Lane Distribution function byte-interleaves the
packet byte stream across the active data lanes (lane 0 gets byte 0, lane 1
gets byte 1, ... round-robin). On the receiver side the Lane Merging function
reassembles the original byte stream. Both ends must be configured with the
same number of active lanes. Each lane carries SoT (Start of Transmission) and
EoT (End of Transmission) sync sequences at the PHY level around each HS burst.

================================================================================
3. LOW LEVEL PROTOCOL — PACKETS
================================================================================

The CSI-2 Low Level Protocol defines two packet kinds: Short Packets and Long
Packets. All multi-byte fields are transmitted least-significant-byte first.

3.1 Short Packet

A Short Packet is a 4-byte packet (no payload, no footer) used for frame and
line synchronization. Its structure is:

  Byte 0      : Data Identifier (DI) = Virtual Channel (VC, 2 bits) +
                Data Type (DT, 6 bits)
  Byte 1, 2   : Short Packet Data Field (16-bit), interpreted per Data Type:
                * For Frame Start / Frame End: the 16-bit Frame Number.
                * For Line Start / Line End : the 16-bit Line Number.
  Byte 3      : Error Correction Code (ECC) computed over the Data Identifier
                and Short Packet Data Field bytes.

Synchronization Short Packet Data Types:
  - Frame Start (FS) code  : DT = 0x00. Marks the start of a frame; carries the
    Frame Number.
  - Frame End (FE) code    : DT = 0x01. Marks the end of a frame; carries the
    Frame Number.
  - Line Start (LS) code   : DT = 0x02. Optional. Marks the start of a line;
    carries the Line Number.
  - Line End (LE) code     : DT = 0x03. Optional. Marks the end of a line;
    carries the Line Number.
  - Generic Short Packet codes 0x08..0x0F : user-defined sync events.

Every frame is delimited by an FS Short Packet at the start and an FE Short
Packet at the end. Line Start / Line End are optional and bracket each line of
active pixel data when used. This frame/line synchronization lets the receiver
reconstruct frame and line boundaries without a separate VSYNC/HSYNC wire.

3.2 Long Packet

A Long Packet carries the actual image (or embedded) data. Its structure is:

  Packet Header (PH) — 4 bytes:
    Byte 0    : Data Identifier (DI) = Virtual Channel (2 bits) +
                Data Type (6 bits)
    Byte 1, 2 : Word Count (WC), 16-bit — the number of DATA BYTES in the
                packet payload (footer not included).
    Byte 3    : Error Correction Code (ECC) over the Data Identifier + Word
                Count (the first 3 header bytes). The ECC can correct
                1-bit and detect 2-bit errors in the packet header.

  Data Payload : Word Count bytes of pixel / embedded data, packed per the
                 Data Type's pixel-to-byte mapping.

  Packet Footer (PF) — 2 bytes:
    16-bit Checksum / CRC computed over the payload data bytes. The CRC uses
    the generator polynomial x^16 + x^12 + x^5 + 1 (CRC-16-CCITT).

The receiver reads the header, validates ECC, reads exactly Word Count payload
bytes, then reads and checks the 16-bit CRC footer.

3.3 Data Identifier, Virtual Channel, Data Type

The Data Identifier (DI) byte is present in both Short and Long Packets:
  - Virtual Channel (VC): the upper 2 bits of the DI byte select one of 4
    logical streams (VC0..VC3) multiplexed over the same physical link. The
    Virtual Channel mechanism lets one sensor (or multiple sensors aggregated)
    interleave several independent image streams. A Virtual Channel Extension
    (extended VC, using bits from the Data Type field / Short Packet) raises
    the count to up to 16 or 32 virtual channels in later CSI-2 versions.
  - Data Type (DT): the lower 6 bits identify the payload format. Packets of
    different Data Types and different Virtual Channels may be interleaved
    within a frame (Data Type interleaving and Virtual Channel interleaving).

================================================================================
4. DATA TYPES
================================================================================

The 6-bit Data Type field selects the payload format. CSI-2 defines:

4.1 Synchronization Short Packet Data Types (0x00..0x07)
  0x00 Frame Start
  0x01 Frame End
  0x02 Line Start
  0x03 Line End
  0x04..0x07 Reserved

4.2 Generic Short Packet Data Types (0x08..0x0F)
  0x08..0x0F Generic Short Packet Codes 1..8 (user-defined synchronization).

4.3 Generic Long Packet Data Types (0x10..0x17)
  0x10 Null
  0x11 Blanking Data
  0x12 Embedded 8-bit non-image Data (embedded data lines: register settings,
       statistics, exposure/gain metadata carried as 8-bit bytes ahead of or
       after the active pixel lines)
  0x13..0x17 Reserved

4.4 YUV Image Data Types (0x18..0x1F)
  0x18 YUV420 8-bit (legacy)
  0x19 YUV420 10-bit (legacy)
  0x1A YUV420 8-bit (Chroma Shifted Pixel Sampling)
  0x1C YUV420 8-bit CSPS
  0x1D YUV420 10-bit CSPS
  0x1E YUV422 8-bit
  0x1F YUV422 10-bit

4.5 RGB Image Data Types (0x20..0x27)
  0x20 RGB444
  0x21 RGB555
  0x22 RGB565
  0x23 RGB666
  0x24 RGB888

4.6 RAW Image Data Types (0x28..0x2F)
  0x28 RAW6
  0x29 RAW7
  0x2A RAW8
  0x2B RAW10
  0x2C RAW12
  0x2D RAW14
  0x2E RAW16 (later versions)
  0x2F RAW20 (later versions)
  RAW data is the unprocessed Bayer-pattern output of the image sensor pixel
  array; the host's image signal processor (ISP) demosaics it. RAW8 / RAW10 /
  RAW12 are the most common camera-sensor output formats.

4.7 User-Defined Data Types (0x30..0x37)
  0x30..0x37 User Defined Byte-based Data (e.g. JPEG / compressed payloads,
  user-defined formats negotiated out of band).

================================================================================
5. PIXEL-TO-BYTE PACKING
================================================================================

Each image Data Type defines how pixels pack into the Long Packet payload
bytes. Examples:
  - RAW8 : 1 pixel per byte.
  - RAW10: 4 pixels packed into 5 bytes (4 high bytes + 1 byte holding the 4
    least-significant 2-bit groups).
  - RAW12: 2 pixels packed into 3 bytes.
  - RGB888: 3 bytes per pixel (R, G, B).
  - YUV422 8-bit: 2 bytes per pixel (interleaved Y/U/Y/V).
The Word Count in the Long Packet header equals the number of payload bytes
after packing, which for a line equals (active pixels x bytes-per-packing-unit
/ pixels-per-packing-unit).

Optional DATA COMPRESSION: CSI-2 defines an optional image data compression
scheme (predictive DPCM-style compression, e.g. 12-to-8 / 10-to-8 / 10-to-6)
applied to RAW data before packing, to reduce link bandwidth.

================================================================================
6. FRAME STRUCTURE AND INTERLEAVING
================================================================================

A complete frame transmitted over CSI-2 looks like:

  FS (Frame Start Short Packet, VC, Frame Number)
    [optional Embedded Data Long Packets, DT 0x12]
    [LS] Long Packet (line 1 pixel data, e.g. RAW10) [LE]
    [LS] Long Packet (line 2 pixel data) [LE]
    ...
    [LS] Long Packet (line H pixel data) [LE]
    [optional Embedded Data Long Packets, DT 0x12]
  FE (Frame End Short Packet, VC, Frame Number)

Data Type interleaving: within one Virtual Channel, packets of different Data
Types (e.g. interleaved RAW and embedded data, or scaled/cropped sub-images)
may be transmitted. Virtual Channel interleaving: packets of different Virtual
Channels may be interleaved (e.g. multiple sensors, or full-frame + region of
interest streams) and are demultiplexed at the receiver by the VC field.

Frame and Line synchronization is conveyed entirely in-band via the FS / FE /
LS / LE Short Packets — there is no separate frame-valid or line-valid wire on
the CSI-2 high-speed link.

================================================================================
7. CAMERA CONTROL INTERFACE (CCI)
================================================================================

The Camera Control Interface (CCI) is the sideband control channel used by the
host to program the image sensor. CCI is a two-wire bus:
  - SCL (serial clock)
  - SDA (serial data)
It is electrically and protocol-wise an I2C subset (Standard-mode 100 kHz and
Fast-mode 400 kHz; CCI extension can use I3C). The host is the CCI master and
the sensor is the CCI slave at a 7-bit device address. CCI uses 16-bit
register addresses and 8-bit register data by default. CCI is used to set the
sensor resolution, frame rate, exposure time, analog/digital gain, test
patterns, and to start/stop streaming.

CCI is the CONTROL path and is completely separate from the CSI-2 data path:
no image pixel data flows over CCI, and no register/control traffic flows over
the CSI-2 D-PHY/C-PHY lanes. This camera-control sideband distinguishes a
camera (CSI-2) link from a display (DSI) link.

================================================================================
8. ERROR DETECTION AND RECOVERY
================================================================================

  - Packet Header ECC: a Hamming-code ECC byte over the Data Identifier +
    Word Count corrects single-bit errors and detects double-bit errors in
    every Long Packet header and Short Packet.
  - Packet Footer CRC: a 16-bit checksum (CRC-16-CCITT, polynomial
    x^16 + x^12 + x^5 + 1) over the Long Packet payload detects payload
    corruption.
  - PHY-level errors (SoT error, SoT sync error, control error, escape-mode
    entry error) are reported by the receiver.
  - Frame-level error checking: an FS without matching FE (or vice versa)
    flags a frame synchronization error.

================================================================================
9. RECEIVER PROCESSING MODEL
================================================================================

The CSI-2 receiver (in the host application processor):
  1. PHY (D-PHY or C-PHY) recovers the per-lane byte stream from HS bursts.
  2. Lane Merging reassembles the single byte stream from the active lanes.
  3. The LLP parser detects packet boundaries, reads each Packet Header,
     checks ECC, and classifies Short vs Long Packets by Data Type.
  4. For Long Packets it reads Word Count payload bytes and verifies the CRC
     footer.
  5. It routes packets by Virtual Channel to the correct stream and by Data
     Type to the correct unpacking/ISP path.
  6. FS / FE / LS / LE Short Packets drive the frame/line state machine that
     reconstructs the image raster for the ISP.

================================================================================
10. KEY DISTINCTIONS (CAMERA vs DISPLAY)
================================================================================

CSI-2 is the CAMERA / image-sensor interface: data flows sensor -> host, the
payload is RAW / YUV / RGB image pixel data plus embedded data, frame/line
sync is via FS/FE/LS/LE Short Packets, streams are tagged with Virtual Channel,
each Long Packet carries Data Identifier + Word Count + ECC + CRC, and the
sensor is configured over the CCI (I2C) sideband.

This is structurally distinct from MIPI DSI (Display Serial Interface), which
is a DISPLAY interface: data flows host -> display panel, it uses the Display
Command Set (DCS), it operates in Video Mode or Command Mode to drive a panel,
and it has no image-sensor / RAW-Bayer / Camera Control Interface concept.
Although both DSI and CSI-2 share the MIPI D-PHY physical layer, they are
different application protocols: CSI-2 is camera capture, DSI is display drive.

================================================================================
11. ELECTRICAL / TIMING SUMMARY (D-PHY)
================================================================================

  - HS data rate per lane    : up to 2.5 Gbps (D-PHY v1.2) and higher in later
                                D-PHY versions; aggregate bandwidth scales with
                                lane count.
  - LP signaling             : single-ended, ~1.2 V swing, used for stop state
                                (LP-11) and escape sequences.
  - HS signaling             : differential, ~200 mV swing around a ~200 mV
                                common-mode.
  - Clock                    : forwarded DDR clock on the dedicated Clock Lane
                                (D-PHY); embedded in symbols (C-PHY).
  - SoT / EoT sequences      : delimit each HS burst per lane.

================================================================================
12. APPLICATIONS
================================================================================

  - Smartphone and tablet rear/front camera sensors to the application
    processor.
  - Automotive ADAS / surround-view camera modules (often with multiple
    Virtual Channels aggregated by a serializer/deserializer).
  - Machine-vision and security camera sensors.
  - Multi-camera systems where several image streams are multiplexed by
    Virtual Channel over one CSI-2 link.
