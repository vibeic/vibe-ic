--------------------------------------------------------------------------------
1. ABSTRACT / OVERVIEW
--------------------------------------------------------------------------------

The Expanded Serial Peripheral Interface (xSPI), standardized by JEDEC as
JESD251, defines an EXPANSION of the classic Serial Peripheral Interface (SPI)
for high-throughput access to serial NOR flash, serial NAND, and PSRAM memory
devices. Where classic single-IO SPI uses a bare four-wire full-duplex shift
register (SCLK, single MOSI output, single MISO input, and a chip-select CS#),
xSPI / Quad SPI (QSPI) / Octal SPI (OSPI) widen the data path to MULTIPLE
bidirectional data lines and add a structured command protocol: an instruction
phase, an address phase, optional mode/alternate bits, programmable DUMMY
CYCLES, and a data phase. This is the key structural difference from plain
single-IO SPI: QSPI/OSPI is a multi-IO, command-address-dummy-data memory
protocol, not a simple full-duplex byte shifter.

The data lines are named IO0, IO1, IO2, IO3 (Quad) and extended to IO0..IO7
(Octal, also called "x8"). For octal DDR devices an optional Data Strobe (DQS)
output accompanies the read data, and a RESET# pin is defined. The data lines
DQ0..DQ7 are an equivalent naming used by some octal device vendors. Each
command phase may run over 1, 2, 4, or 8 data lines, giving the protocol-mode
notation 1-1-1, 1-1-2, 1-1-4, 1-2-2, 1-4-4, 4-4-4, 1-1-8, 1-8-8, 8-8-8, and the
double-data-rate octal mode 8D-8D-8D.

xSPI supports both Single Data Rate (SDR) and Double Data Rate (DDR, also called
DTR — Double Transfer Rate) signaling. In DDR/DTR mode data is launched and
captured on BOTH edges of SCLK, doubling effective throughput; the read data is
edge-aligned to the Data Strobe (DQS) in octal DDR devices.

--------------------------------------------------------------------------------
2. KEY FEATURES
--------------------------------------------------------------------------------

- Expansion of classic SPI for NOR flash / NAND / PSRAM (JEDEC xSPI / JESD251).
- Multi-IO data path: Single (IO0=MOSI / IO1=MISO), Dual (IO0-IO1), Quad
  (IO0-IO3), Octal (IO0-IO7 / DQ0-DQ7, "x8").
- In Quad mode, the classic /WP (write-protect) pin is repurposed as IO2 and the
  classic /HOLD (or /RESET) pin is repurposed as IO3.
- Structured command protocol: instruction phase -> address phase -> mode /
  alternate bits -> programmable DUMMY CYCLES -> data phase.
- Protocol-mode notation S-A-D, e.g. 1-1-1, 1-1-4, 1-4-4, 4-4-4, 8-8-8,
  8D-8D-8D (lanes used for instruction / address / data respectively).
- SDR and DDR (DTR) signaling; data on one edge (SDR) or both edges (DDR).
- Optional Data Strobe (DQS) output in octal DDR for source-synchronous read
  capture; RESET# pin defined in xSPI.
- Command extension byte in xSPI octal mode (repeated or inverted instruction).
- 3-byte and 4-byte addressing (16 MB vs >16 MB address reach); 4-byte address
  enable command (0xB7) and exit (0xE9).
- Standard JEDEC flash command set (Write Enable 0x06, Read Status Register
  0x05, Fast Read 0x0B, Quad I/O Fast Read 0xEB, Quad Output Fast Read 0x6B,
  Quad Page Program 0x32, Sector Erase 0x20, Block Erase 0x D8, Read JEDEC ID
  0x9F, Read SFDP 0x5A).
- Serial Flash Discoverable Parameters (SFDP, JESD216) for self-describing
  capability tables read with command 0x5A.
- Continuous Read Mode (mode / alternate bits) and eXecute-In-Place (XIP).
- Clock frequencies up to 133 MHz typical SDR, 166-200+ MHz on faster devices,
  with higher effective throughput in DDR / octal.
- Volatile and non-volatile configuration / status register interface (xSPI).

--------------------------------------------------------------------------------
3. PIN / SIGNAL DESCRIPTION
--------------------------------------------------------------------------------

  SCLK   - Serial clock, driven by the controller (master). Up to 133-200+ MHz.
  CS#    - Active-low chip select (slave select). Frames each command;
           transaction is bounded by CS# falling then rising.
  IO0    - Data line 0. In single mode this is MOSI (controller output).
  IO1    - Data line 1. In single mode this is MISO (controller input).
  IO2    - Data line 2 (Quad/Octal). Repurposed from the classic /WP pin.
  IO3    - Data line 3 (Quad/Octal). Repurposed from the classic /HOLD or
           /RESET pin.
  IO4..IO7 (or DQ4..DQ7) - Data lines 4-7 (Octal "x8" only).
  DQS    - Data strobe (optional, octal DDR). Source-synchronous read strobe,
           edge-aligned to read data.
  RESET# - Hardware reset (xSPI). Active-low.

  Note: the data lines IO0..IO7 are BIDIRECTIONAL and tri-stated; their
  direction is set per command phase. This is distinct from plain single-IO SPI,
  in which MOSI is a dedicated output and MISO a dedicated input
  (separate unidirectional lines, full-duplex).

--------------------------------------------------------------------------------
4. PROTOCOL STRUCTURE — COMMAND / ADDRESS / DUMMY / DATA PHASES
--------------------------------------------------------------------------------

Every xSPI / QSPI / OSPI transaction is a sequence of phases, each of which may
use a different number of data lines (1, 2, 4 or 8) and run SDR or DDR:

  1. INSTRUCTION phase : 8-bit (or 16-bit extended in octal) command opcode.
  2. ADDRESS phase     : 3 bytes (24-bit) or 4 bytes (32-bit) memory address.
  3. MODE / ALTERNATE  : optional mode bits (continuous-read / XIP hint).
  4. DUMMY CYCLES      : a programmable number of clock cycles with no data,
                         used to absorb the device read latency before data is
                         driven. The dummy-cycle count is device- and
                         frequency-dependent and is often configurable.
  5. DATA phase        : one or more data bytes, read or written.

Protocol-mode notation is written as <instr>-<addr>-<data> lanes:

  1-1-1   : single-IO SPI-compatible (instruction, address, data all 1 lane).
  1-1-2   : Dual Output Fast Read (data on 2 lanes).
  1-2-2   : Dual I/O Fast Read (address and data on 2 lanes).
  1-1-4   : Quad Output Fast Read 0x6B (data on 4 lanes).
  1-4-4   : Quad I/O Fast Read 0xEB (address and data on 4 lanes).
  4-4-4   : QPI mode (instruction, address and data all on 4 lanes).
  1-1-8   : Octal Output Read (data on 8 lanes).
  1-8-8   : Octal I/O Read (address and data on 8 lanes).
  8-8-8   : Octal mode (all phases on 8 lanes), SDR.
  8D-8D-8D: Octal DDR mode (all phases on 8 lanes, both clock edges).

In xSPI octal mode a Command Extension byte follows the instruction (repeated
or inverted, per device), so the controller transmits a 16-bit instruction
field in 8D-8D-8D operation.

--------------------------------------------------------------------------------
5. STANDARD FLASH COMMAND SET (JEDEC conventions)
--------------------------------------------------------------------------------

  Opcode  Name                         Mode      Notes
  ------  --------------------------    --------  ----------------------------
  0x06    Write Enable (WREN)          1-0-0     Sets the Write Enable Latch.
  0x04    Write Disable (WRDI)         1-0-0     Clears the Write Enable Latch.
  0x05    Read Status Register-1       1-0-1     Returns WIP/WEL/BP bits.
  0x35    Read Status Register-2       1-0-1
  0x01    Write Status Register        1-0-1
  0x03    Read Data                    1-1-1     Single, low-frequency.
  0x0B    Fast Read                    1-1-1     With dummy cycles.
  0x3B    Dual Output Fast Read        1-1-2
  0xBB    Dual I/O Fast Read           1-2-2
  0x6B    Quad Output Fast Read        1-1-4
  0xEB    Quad I/O Fast Read           1-4-4     With mode bits + dummy cycles.
  0x0C    Fast Read (4-byte address)   1-1-1
  0xEC    Quad I/O Fast Read (4-byte)  1-4-4
  0x02    Page Program                 1-1-1     Up to 256 bytes per page.
  0x32    Quad Page Program            1-1-4
  0x20    Sector Erase (4 KB)          1-1-0
  0x52    Block Erase (32 KB)          1-1-0
  0xD8    Block Erase (64 KB)          1-1-0
  0xC7    Chip Erase                   1-0-0
  0x9F    Read JEDEC ID                1-0-1     Manufacturer + device ID.
  0x5A    Read SFDP                    1-1-1     Serial Flash Discoverable
                                                  Parameters (JESD216).
  0xB7    Enter 4-Byte Address Mode    1-0-0
  0xE9    Exit 4-Byte Address Mode     1-0-0
  0x66    Enable Reset                 1-0-0
  0x99    Reset Device                 1-0-0
  0xB1    Enter QPI / Octal mode       1-0-0     Device-specific enable.

The Read Status Register command returns the Write In Progress (WIP) bit, which
the controller polls during Page Program and Erase to detect completion, and the
Write Enable Latch (WEL) bit, which must be set (via 0x06) before any program or
erase.

--------------------------------------------------------------------------------
6. SFDP — SERIAL FLASH DISCOVERABLE PARAMETERS (JESD216)
--------------------------------------------------------------------------------

SFDP is a standardized, self-describing parameter table inside the flash device,
read with command 0x5A (Read SFDP) at a 24-bit address with 8 dummy cycles in
1-1-1 mode. The SFDP structure begins with a signature ("SFDP", 0x50444653) and
a set of Parameter Headers pointing at Parameter Tables. The Basic Flash
Parameter Table (BFPT) describes density, supported read modes (1-1-4 / 1-4-4 /
1-1-8 / 8-8-8), dummy-cycle counts and mode-bit counts per read, supported erase
types and opcodes, address bytes (3 / 4), and timing. SFDP lets a generic
controller auto-configure dummy cycles and the optimal multi-IO read command
without device-specific firmware.

--------------------------------------------------------------------------------
7. CONTINUOUS READ MODE / XIP
--------------------------------------------------------------------------------

In a Quad/Octal I/O Read (e.g. 0xEB, 1-4-4) the controller can set the MODE bits
(alternate bits) after the address so that the NEXT read transaction may skip
the instruction phase entirely — the device stays in "continuous read" and
expects only address + dummy + data. This supports eXecute-In-Place (XIP), where
a CPU fetches code directly from the flash through the QSPI/OSPI controller's
memory-mapped window without explicit command overhead per access.

--------------------------------------------------------------------------------
8. SDR vs DDR (DTR) SIGNALING
--------------------------------------------------------------------------------

  SDR (Single Data Rate) : one bit per data line per SCLK cycle, captured on a
                           single edge (typically rising).
  DDR / DTR (Double Data : one bit per data line per SCLK edge (both rising and
  Rate / Double Transfer   falling), doubling the data rate at a given SCLK
  Rate)                    frequency. Applies to instruction, address and data
                           phases in 8D-8D-8D octal DDR.

In octal DDR (8D-8D-8D) the device drives the Data Strobe (DQS) edge-aligned
with the read data so the controller can capture data source-synchronously,
which is essential at high SCLK frequencies.

--------------------------------------------------------------------------------
9. ADDRESSING (3-BYTE / 4-BYTE)
--------------------------------------------------------------------------------

3-byte (24-bit) addressing reaches 16 MB. Devices larger than 16 MB use 4-byte
(32-bit) addressing, entered with command 0xB7 (Enter 4-Byte Address Mode) and
exited with 0xE9, or accessed with dedicated 4-byte-address opcodes (0x0C Fast
Read, 0xEC Quad I/O Fast Read, 0x12 Page Program 4-byte, 0xDC Block Erase
4-byte). xSPI octal devices default to 4-byte addressing.

--------------------------------------------------------------------------------
10. CONFIGURATION / STATUS REGISTERS (xSPI)
--------------------------------------------------------------------------------

xSPI defines a register interface with both volatile and non-volatile
configuration registers in addition to the legacy status registers. Registers
configure dummy-cycle latency, drive strength, the protocol mode (SPI / QPI /
octal SDR / octal DDR), DQS enable, and address-byte count. The Read Status
Register-1 (0x05) WIP/WEL bits remain the primary program/erase handshake.

--------------------------------------------------------------------------------
11. ELECTRICAL / TIMING
--------------------------------------------------------------------------------

  SCLK frequency : up to 133 MHz typical (SDR), 166-200+ MHz on fast devices.
  Mode           : SPI Mode 0 (CPOL=0, CPHA=0) and Mode 3 (CPOL=1, CPHA=1) for
                   single-IO compatibility; multi-IO phases capture per the
                   device dummy-cycle and DQS configuration.
  Signaling      : single-ended CMOS/LVCMOS; push-pull on actively-driven lines.
  CS# setup/hold : device-specific; CS# must remain low for the whole command.
  Bit order      : MSB-first on each data line.

--------------------------------------------------------------------------------
12. PROTOCOL MODES SUMMARY (S-A-D notation)
--------------------------------------------------------------------------------

  Single   : 1-1-1
  Dual     : 1-1-2, 1-2-2
  Quad     : 1-1-4, 1-4-4, 4-4-4 (QPI)
  Octal    : 1-1-8, 1-8-8, 8-8-8 (SDR), 8D-8D-8D (DDR)

--------------------------------------------------------------------------------
13. RELATIONSHIP TO CLASSIC SPI (DISTINGUISHER)
--------------------------------------------------------------------------------

QSPI/OSPI EXTENDS classic SPI: it shares SCLK and CS# and is single-IO
SPI-Mode-0/Mode-3 compatible in its 1-1-1 commands. However, QSPI/OSPI is
distinguished from plain single-IO SPI by ALL of the following structure that a
bare full-duplex SPI shift register does NOT have:

  - Multiple bidirectional data lines IO0..IO3 (Quad) / IO0..IO7 (Octal),
    versus a single dedicated MOSI output + single MISO input in plain SPI.
  - A command-address-dummy-data phase structure with programmable DUMMY
    CYCLES, versus plain SPI's continuous full-duplex shift with no command
    framing.
  - A standard JEDEC flash command set (0x06 / 0x0B / 0xEB / 0x9F / 0x5A ...)
    and SFDP self-description.
  - Protocol-mode notation (1-1-4 / 1-4-4 / 4-4-4 / 8-8-8 / 8D-8D-8D).
  - SDR and DDR (DTR) signaling with an optional DQS data strobe.
  - 3-byte / 4-byte addressing and continuous-read / XIP.
  - The JEDEC xSPI / JESD251 register and command-extension framework.

A plain SPI device (e.g. the Motorola/Freescale SPI block) has only SCLK, MOSI,
MISO, SS#, CPOL/CPHA, and a shift register — NONE of the multi-IO data lines,
dummy cycles, flash command set, SFDP, protocol-mode notation, or xSPI/JESD251
register framework above.

--------------------------------------------------------------------------------
14. ERROR / ROBUSTNESS
--------------------------------------------------------------------------------

  - WIP (Write In Progress) polling detects program/erase completion.
  - WEL must be set before program/erase; otherwise the operation is ignored.
  - Block / sector protection bits (BP) guard regions from accidental erase.
  - Wrong dummy-cycle configuration corrupts high-frequency multi-IO reads
    (the most common QSPI/OSPI bring-up error).
  - CRC / ECC is device-specific (some xSPI NOR add internal ECC); the bus
    protocol itself has no transaction CRC (unlike SMBus PEC).

16. USE CASES
--------------------------------------------------------------------------------

  - Code-shadow / XIP boot from serial NOR flash for MCUs and SoCs.
  - High-bandwidth firmware and look-up-table storage via octal DDR.
  - PSRAM expansion memory over the same QSPI/OSPI controller.
  - FPGA configuration flash.
  - Automotive / industrial code storage with SFDP auto-configuration.
