### Symptom 2 — `opcode_hex = "0x16"` (page-number → opcode misclassification)

Pre-v0.1.60: `L10.test_cases[*].opcode_hex = ['0x16', '0x16', '0x48', '0x48']`.
Post-v0.1.60: all 4 occurrences = `<HALLUCINATION_SCRUBBED>` via the
`opcode_from_two_digit_decimal_page_number` rule (catches `0x16 / 0x17 /
0x23 / 0x24 / 0x47 / 0x48 / 0x55 / 0x56` — the byte-position-figure pattern
common to AMBA AXI §A3.4.4 narrow-transfer tables).

AXI is valid/ready handshake, not opcode-driven; the rule auto-scrubs at
emit, no downstream consumer can mistake the page numbers for protocol
encoding.

## What this run did NOT touch (still backlog per user's report)

The 421 remaining findings break down into the three engineering items
GAP_v0157 already named:

1. **`ic_class → applicable_L_docs` map** — drops the 110 `N/A` stub
   findings in L19-L23 (PDK / DFT / Power / Security) which a
   bus-interconnect protocol doesn't legitimately have.
2. **L14-L18 schema + extractors** — currently the runner emits skeleton
   stubs with no AXI version-table / encoding-table / compliance-rule
   / channel-catalog / interconnect-rule extraction. The `ABSENT_IN_PROGRAM`
   bucket of 343 won't move without these.
3. **`bus_interconnect_protocol` IC class detector** — the current
   `digital_arithmetic_primitive` mis-classification routes through the
   OTP / chip taxonomy and is the upstream cause of the over-fill on
   L1/L2/L11 (the user noted: L1 program 101 KB vs Claude 7 KB, L2 116 KB
   vs 12 KB).

Each is real engineering, not a single-point fix — they're queued for
future capture cycles, not bundled into R11.

## Doctrine notes

- **Scrubber existed since v0.1.51** — the regex catalog was complete,
  the wiring was missing. R11 is a 20-line `_write_l_doc` patch, not a
  new rule. The right unit of change was the integration point, not the
  policy.
- **Audit trail is mandatory** — every scrub attaches its before/after/why
  to the L doc. Future parity runs can see exactly what the runner
  changed; no silent re-writing.
- **Fail-open contract** — if the scrubber crashes, emission still
  proceeds with an error stamp in `extraction_strategy
  .hallucination_scrub_error_v0_1_60`. No new failure modes introduced.
- **Anti-false-positive pytest** — 6 real IC names pinned to pass through
  untouched (`AMBA AXI`, `TPM-2.0`, `AT-cmd-driven IC`, `RISC-V Core`,
  `SHA-256 Engine`, `u_hawaii_adc`). Regex matches license-boilerplate
  SHAPE, not the AMBA brand specifically.
