JEDEC STANDARD
Embedded MultiMediaCard (eMMC)
Electrical Standard (5.1)
JESD84-B51
February 2015

JEDEC Solid State Technology Association

==============================================================================
1. SCOPE
==============================================================================

This standard defines the Embedded MultiMediaCard (eMMC) electrical interface,
its environment and handling. The eMMC is an embedded, managed-NAND flash
storage device intended to be permanently soldered onto a host system board.
Unlike a removable SD/MMC card, an eMMC device has NO card slot, NO card-detect
mechanism, NO mechanical write-protect switch and NO card-insertion / removal
sequence. There is no SDIO function. The device is identified by the host at
boot time and managed in-system for the life of the product.

An eMMC device integrates a NAND flash array together with an on-die flash
controller (the "device" / "managed NAND") that hides the raw NAND behaviour:
wear leveling, bad-block management, error-correction (ECC), and address
translation are all performed inside the device. The host sees a clean,
block-addressable storage device with a fixed command/response/data protocol
derived from the MultiMediaCard (MMC) protocol.

This document covers: the bus signals and electrical interface, the device
register set (OCR, CID, CSD and the 512-byte Extended CSD), the command set
and device state machine, the partitioning model (Boot Area Partitions, RPMB,
General Purpose Partitions, User Data Area), the boot operation, the speed
modes (backward-compatible, high speed, HS200, HS400), and the managed-NAND
feature set (HPI, Background Operations, Cache, Sanitize/TRIM/Discard, Secure
Erase, Field Firmware Update, Packed commands, Command Queuing).

==============================================================================
2. BUS SIGNALS AND ELECTRICAL INTERFACE
==============================================================================

The eMMC bus is a synchronous, clocked bus between a single host and a single
embedded device. The bus uses the following signals:

  CLK    : Clock. Each cycle of CLK transfers one bit on the command and on
           each of the active data lines. The host drives CLK. In Double Data
           Rate (DDR) and HS400 modes, data is transferred on both edges of CLK.

  CMD    : Command/response line. Bidirectional, push-pull. Carries host
           commands to the device and device responses back to the host.
           Start bit, transmission bit, content, CRC7 and end bit.

  DAT[7:0] : Data bus. Up to EIGHT bidirectional data lines (8-bit bus width),
           selectable as 1-bit (DAT0), 4-bit (DAT[3:0]) or 8-bit (DAT[7:0]).
           The 8-bit data bus is a key differentiator from the SD card (which
           is limited to a 4-bit DAT bus). Bus width is configured through the
           BUS_WIDTH field of the Extended CSD via the SWITCH command (CMD6).

  DS     : Data Strobe. An additional device-sourced strobe signal used ONLY in
           HS400 mode. In HS400 the device returns DS as a read-data strobe so
           the host can latch DDR read data reliably at 400 MB/s. DS is unique
           to eMMC; the SD card has no Data Strobe.

  RST_n  : Hardware Reset. An active-low device reset input. Because the eMMC
           is soldered and cannot be power-cycled by removal, RST_n provides a
           hardware reset of the device without removing power. RST_n behaviour
           is enabled/disabled through the RST_n_FUNCTION field of the Extended
           CSD. The SD card has no hardware reset pin.

  VCC    : NAND flash core / memory supply (e.g. 3.3 V or 1.8 V class).
  VCCQ   : I/O and controller supply (e.g. 1.8 V or 1.2 V class).
  VSS / VSSQ : Ground references.

Signaling: the I/O voltage is selectable (3.3 V, 1.8 V, or 1.2 V class)
depending on the speed mode. HS200 and HS400 require 1.8 V or 1.2 V I/O.

Because the device is embedded there is NO card-detect line, NO write-protect
mechanical switch and NO card-present pull-up of the SD style. The host always
knows the device is present.

==============================================================================
3. DEVICE REGISTERS
==============================================================================

The eMMC device exposes the following registers:

  OCR  (Operation Conditions Register, 32 bits)
       Reports the supported VCC voltage window and the device busy bit. The
       host polls SEND_OP_COND (CMD1) until the device leaves the busy state.
       The access-mode bits indicate byte vs sector addressing (>2 GB devices
       use sector addressing).

  CID  (Card/Device Identification, 128 bits)
       Manufacturer ID (MID), OEM/Application ID, product name, product
       revision, product serial number and manufacturing date. Read with
       ALL_SEND_CID (CMD2) and SEND_CID (CMD10).

  CSD  (Card/Device-Specific Data, 128 bits)
       Device-specific operating parameters and legacy capacity information,
       access timing (TAAC/NSAC), maximum data rate, supported command classes
       (CCC), block lengths. Read with SEND_CSD (CMD9). For devices larger than
       2 GB the legacy C_SIZE is frozen and the true capacity is reported by
       the Extended CSD SEC_COUNT field.

  EXT_CSD (Extended CSD, 512 bytes)
       The Extended CSD is a 512-byte register read with SEND_EXT_CSD (CMD8)
       and written field-by-field with SWITCH (CMD6). It is the central
       configuration and capability register of the eMMC and has no analogue
       on the SD card. It is split into a Properties segment (read-only device
       capabilities) and a Modes segment (host-writable configuration). Key
       fields include:

         SEC_COUNT          : device capacity in 512-byte sectors.
         BUS_WIDTH          : 1/4/8-bit, SDR or DDR.
         HS_TIMING          : selects backward / high-speed / HS200 / HS400.
         PARTITION_CONFIG   : selects the partition that User-area access and
                              boot are directed to (partition switching).
         BOOT_CONFIG / BOOT_BUS_CONDITIONS : boot partition + boot bus setup.
         PARTITIONING_SUPPORT, PARTITIONS_ATTRIBUTE, GP_SIZE_MULT,
         ENH_SIZE_MULT     : General Purpose / enhanced partition definition.
         RPMB_SIZE_MULT     : size of the Replay Protected Memory Block.
         RST_n_FUNCTION     : enable/disable the hardware reset pin.
         CACHE_CTRL, CACHE_SIZE : device cache control.
         BKOPS_EN, BKOPS_START : background operations control.
         SANITIZE_START     : trigger a Sanitize operation.
         SEC_FEATURE_SUPPORT, SEC_ERASE_MULT : secure erase / TRIM support.
         FFU_STATUS, MODE_CONFIG, MODE_OPERATION_CODES : Field Firmware Update.
         CMDQ_MODE_EN, CMDQ_DEPTH : Command Queuing enable and queue depth.

  RCA  (Relative Device Address, 16 bits)
       Assigned by the host with SET_RELATIVE_ADDR (CMD3); used to address the
       device in the addressed states.

  DSR  (Driver Stage Register, 16 bits, optional)
       Optional output drive configuration.

==============================================================================
4. PARTITIONING MODEL
==============================================================================

An eMMC device presents several independently addressable hardware partitions.
The active partition is selected by the PARTITION_ACCESS bits of
PARTITION_CONFIG (partition switching via SWITCH / CMD6):

  User Data Area
       The main bulk storage area. Block-addressable, the default partition
       after power-up.

  Boot Area Partition 1 and Boot Area Partition 2
       Two dedicated boot partitions whose size is fixed in multiples of 128
       kB (BOOT_SIZE_MULT). Code stored here can be read by the host during the
       boot operation (see Section 6) before the User Area is even selected.

  Replay Protected Memory Block (RPMB)
       A security partition that supports authenticated, replay-protected
       reads and writes using a one-time-programmable secret key and a
       monotonic write counter. Each RPMB access is an authenticated data
       packet protected by an HMAC-SHA256 MAC computed over the data plus a
       nonce plus the write counter, defeating replay attacks. The RPMB is
       sized by RPMB_SIZE_MULT and accessed with a dedicated reliable-write
       packet protocol (CMD23 + CMD25/CMD18 around the RPMB data frame).

  General Purpose Partitions (GPP 1..4)
       Up to four host-defined General Purpose Partitions, each optionally
       flagged as enhanced or as an extended-attribute (e.g. reliable-write,
       pseudo-SLC) area. They are defined once, irreversibly, by writing
       GP_SIZE_MULT and PARTITIONS_ATTRIBUTE and then setting the
       PARTITION_SETTING_COMPLETED bit.

Partition definition (GP sizes, enhanced areas) is a ONE-TIME, irreversible
configuration committed by setting PARTITION_SETTING_COMPLETED.

==============================================================================
5. COMMAND SET AND DEVICE STATE MACHINE
==============================================================================

Commands are 48-bit tokens on the CMD line: start bit, transmission bit, a
6-bit command index (CMD0..CMD63), a 32-bit argument, a 7-bit CRC and an end
bit. Responses are R1/R1b/R2/R3/R4/R5 formats. Commands are grouped into
command classes (CCC). Representative commands:

  CMD0   GO_IDLE_STATE         : reset device to Idle. With argument
                                 0xF0F0F0F0 / 0xFFFFFFFA triggers boot modes.
  CMD1   SEND_OP_COND          : send/poll OCR (voltage + busy + access mode).
  CMD2   ALL_SEND_CID          : device returns its 128-bit CID.
  CMD3   SET_RELATIVE_ADDR     : host assigns the 16-bit RCA.
  CMD6   SWITCH                : write one Extended CSD byte (the central
                                 configuration command: bus width, HS_TIMING,
                                 PARTITION_CONFIG, etc).
  CMD7   SELECT/DESELECT_CARD  : select (stby->tran) or deselect the device.
  CMD8   SEND_EXT_CSD          : read the 512-byte Extended CSD as one data
                                 block (eMMC redefinition of CMD8; on SD CMD8
                                 is SEND_IF_COND).
  CMD9   SEND_CSD              : read the 128-bit CSD.
  CMD10  SEND_CID              : read the 128-bit CID.
  CMD12  STOP_TRANSMISSION     : stop an open-ended multiple-block transfer.
  CMD13  SEND_STATUS           : read the 32-bit device status (and queue
                                 status in Command Queuing mode).
  CMD16  SET_BLOCKLEN          : set the block length (default 512 bytes).
  CMD17  READ_SINGLE_BLOCK
  CMD18  READ_MULTIPLE_BLOCK
  CMD23  SET_BLOCK_COUNT       : predefined block count + Reliable Write +
                                 Context ID + Forced Programming + Packed flag.
  CMD24  WRITE_BLOCK
  CMD25  WRITE_MULTIPLE_BLOCK
  CMD35/36 ERASE_GROUP_START / ERASE_GROUP_END
  CMD38  ERASE                 : erase / TRIM / Discard / Secure Erase /
                                 Sanitize, qualified by the argument.
  CMD44/45/46/47 (Command Queuing) QUEUED_TASK_PARAMS / QUEUED_TASK_ADDRESS /
                                 EXECUTE_READ_TASK / EXECUTE_WRITE_TASK.
  CMD48  CMDQ_TASK_MGMT        : discard a queued task / the whole queue.

Device states (the eMMC device state machine, addressed via the CMD line):

  Inactive  : device not responding (e.g. unsupported voltage).
  Idle      : after power-up / CMD0 / RST_n.
  Ready     : OCR valid, busy cleared (after CMD1 completes).
  Identification (Ident) : during CID / RCA assignment (CMD2, CMD3).
  Stand-by (Stby) : device addressed, not selected.
  Transfer (Tran) : device selected, ready for data commands.
  Sending-data (Data) : streaming read data to the host.
  Receive-data (Rcv)  : receiving write data from the host.
  Programming (Prg)   : committing written data to NAND (device busy).
  Disconnect (Dis)    : programming while deselected.

The host moves the device through these states using CMD0/CMD1/CMD2/CMD3 in the
device-identification phase, then CMD7 to select (Stby->Tran), then read/write
data commands cycling Tran<->Data/Rcv<->Prg.

==============================================================================
6. BOOT OPERATION
==============================================================================

Because the eMMC is the boot medium of an embedded system, it supports a BOOT
OPERATION that lets the host fetch boot code from a Boot Area Partition BEFORE
the normal device-identification sequence:

  Boot mode (original boot)
       After power-up or RST_n, if the host holds CMD low for at least 74 CLK
       cycles (or asserts the boot acknowledge sequence), the device begins
       streaming the contents of the boot partition selected by BOOT_CONFIG on
       the data lines, with the boot bus width/timing taken from
       BOOT_BUS_CONDITIONS. No command/response handshake is needed.

  Alternative boot mode
       The host issues CMD0 with argument 0xFFFFFFFA to start the boot stream;
       otherwise identical to boot mode. Preferred for new designs.

  Boot acknowledge
       Optionally the device sends a "010" boot acknowledge pattern on DAT0 so
       the host can confirm a boot-capable device is present.

Boot is terminated by the host (CMD line / CMD0 / reset), after which the
normal device-identification sequence (CMD1/CMD2/CMD3) runs.

==============================================================================
7. SPEED MODES AND BUS TIMING
==============================================================================

eMMC supports a backward-compatible ladder of speed modes, selected through the
HS_TIMING and BUS_WIDTH fields of the Extended CSD with SWITCH (CMD6):

  Backward compatible : up to 26 MHz, SDR, 1/4/8-bit, 3.3 V I/O. Up to
                        26 MB/s at 8-bit.
  High Speed SDR      : up to 52 MHz, SDR, 1/4/8-bit. Up to 52 MB/s at 8-bit.
  High Speed DDR      : 52 MHz, Dual Data Rate on 4/8-bit, 1.8 V/3.3 V.
                        Up to 104 MB/s at 8-bit DDR.
  HS200               : up to 200 MHz, SDR, 8-bit, 1.8 V or 1.2 V I/O.
                        Up to 200 MB/s. Single-ended (like SD's SDR104), uses
                        a tuning sequence (SEND_TUNING_BLOCK, CMD21) to centre
                        the read sampling point.
  HS400               : 200 MHz clock, Dual Data Rate on the 8-bit bus, with
                        the device-sourced Data Strobe (DS) returning a read
                        strobe. Up to 400 MB/s. 1.8 V or 1.2 V I/O. HS400 is
                        entered from HS200 (HS200 tuning first, then switch to
                        HS400). The DS strobe is the defining eMMC feature: it
                        decouples read-data timing from the forwarded clock so
                        DDR data can be latched reliably at 400 MB/s.

DDR mode doubles throughput by transferring data on both CLK edges. HS400 is
the highest-performance legacy-parallel eMMC mode.

==============================================================================
8. MANAGED-NAND FEATURE SET
==============================================================================

The eMMC controller hides raw NAND behaviour and adds storage-management
features that a raw flash or a plain SD card does not have:

  Wear leveling and Bad-Block Management
       The controller distributes writes across physical blocks (wear
       leveling) and transparently retires worn/factory-bad blocks (bad-block
       management) using spare blocks, so the host never sees raw NAND defects.

  ECC
       On-die error-correction protects stored data; corrected/uncorrectable
       status is reported through the device status.

  High Priority Interrupt (HPI)
       HPI (CMD12 or CMD13 with the HPI bit) lets the host interrupt a
       long-running, already-issued busy operation (e.g. a long write or
       background operation) to service a higher-priority request, then resume.

  Background Operations (BKOPS)
       The device can defer housekeeping (garbage collection, wear leveling)
       and perform it as Background Operations when the host grants idle time
       via BKOPS_START. The device reports its background-ops urgency in the
       EXT_CSD BKOPS_STATUS field; the host can also enable automatic BKOPS.

  Cache
       An optional volatile device Cache (enabled via CACHE_CTRL) accelerates
       small writes; the host commits cached data to non-volatile storage with
       a FLUSH_CACHE operation to guarantee persistence.

  Sanitize, TRIM and Discard
       TRIM and Discard (CMD38 variants) mark logical sectors as unneeded so
       the controller can reclaim them. SANITIZE (SANITIZE_START) physically
       purges all previously unmapped/trimmed data from the device, providing
       a strong erase for security.

  Secure Erase / Secure TRIM
       Secure Erase and Secure TRIM (qualified by the CMD38 argument and
       SEC_FEATURE_SUPPORT) guarantee the actual erasure of the targeted data.

  Field Firmware Update (FFU)
       FFU lets the host download a new device firmware image (using
       MODE_CONFIG = FFU mode, the MODE_OPERATION_CODES handshake and ordinary
       block writes) and install it in the field; FFU_STATUS reports success.

  Packed Commands
       Multiple read OR multiple write commands can be packed into a single
       transfer (a packed-command header block + the data) to amortise command
       overhead.

  Command Queuing (CMDQ)
       eMMC 5.1 adds Command Queuing: the host enqueues up to 32 tasks
       (CMDQ_DEPTH) with QUEUED_TASK_PARAMS (CMD44) + QUEUED_TASK_ADDRESS
       (CMD45), the device executes them out of order, signals readiness in the
       Queue Status (CMD13), and the host issues EXECUTE_READ_TASK (CMD46) /
       EXECUTE_WRITE_TASK (CMD47) to transfer the data. CMDQ_TASK_MGMT (CMD48)
       discards a task or the whole queue. CMDQ is enabled by CMDQ_MODE_EN.

==============================================================================
9. DIFFERENCES FROM SD / REMOVABLE MMC CARD (NORMATIVE SUMMARY)
==============================================================================

Although the eMMC command/response/data protocol derives from MultiMediaCard,
an eMMC device is NOT an SD card and NOT a removable card. The defining
embedded-managed-NAND differences are:

  * 8-bit DAT bus (DAT[7:0]) versus the SD card's 4-bit DAT bus.
  * Data Strobe (DS) for HS400 read timing; no SD equivalent.
  * Hardware Reset pin RST_n; no SD equivalent.
  * Embedded: soldered down, NO card-detect, NO mechanical write-protect
    switch, NO card insertion/removal sequence, NO SDIO function.
  * 512-byte Extended CSD (EXT_CSD) configuration register; no SD equivalent.
  * Hardware partitions: Boot Area Partition 1/2, RPMB, General Purpose
    Partitions, selected by PARTITION_CONFIG.
  * Boot operation (boot mode / alternative boot) directly from a boot
    partition.
  * HS200 and HS400 high-speed modes (200 / 400 MB/s).
  * Managed-NAND features: HPI, Background Operations, Cache, Sanitize/TRIM/
    Discard, Secure Erase, Field Firmware Update, Packed commands, Command
    Queuing (CMDQ).

These eMMC-specific structures distinguish an eMMC device from a removable SD
card or a removable MultiMediaCard.

==============================================================================
10. ENVIRONMENT, RELIABILITY AND COMPLIANCE
==============================================================================

The device shall meet the JEDEC operating temperature, ESD and reliability
requirements for embedded storage. Data integrity on the bus is protected by
CRC7 on the CMD line and CRC16 per data line. The RPMB partition provides
authenticated, replay-protected storage with an HMAC-SHA256 MAC and a
monotonic write counter for security-sensitive data (e.g. secure boot
measurements, DRM state). Conformance is to JEDEC JESD84-B51 (eMMC 5.1).
