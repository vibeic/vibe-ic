PROFIBUS — Process Field Bus
Specification per IEC 61158 (Type 3) and IEC 61784-1 (CPF 3)
PROFIBUS-DP (Decentralized Periphery) Communication Profile

1 Scope and Introduction
========================
PROFIBUS (Process Field Bus) is an open industrial fieldbus standard for
distributed automation. It is standardized internationally in IEC 61158
(the Type 3 fieldbus, defining the physical layer, data-link layer and
application layer services) and IEC 61784-1 (Communication Profile Family
3, CPF 3, which selects the protocol subsets for the real communication
profiles). PROFIBUS was originally specified as the German national
standard DIN 19245 and the European standard EN 50170, and is maintained
by PROFIBUS & PROFINET International (PI), formerly the PROFIBUS Nutzer
Organisation (PNO).

PROFIBUS comes in two principal communication profiles plus a legacy
profile:

  * PROFIBUS-DP (Decentralized Periphery) — the dominant profile. A fast,
    cyclic master-slave protocol used to connect a central programmable
    controller (the DP master, Class 1) to distributed field I/O devices
    (DP slaves) over an RS-485 (or fiber) line. DP is optimized for high
    speed and low protocol overhead.
  * PROFIBUS-PA (Process Automation) — the process-industry profile. It
    uses the same DP protocol on the data-link layer but a different
    physical layer (MBP, IEC 61158-2 Manchester Bus Powered) that is
    bus-powered and intrinsically safe for hazardous (Ex) areas.
  * PROFIBUS-FMS (Fieldbus Message Specification) — a legacy peer-to-peer
    profile for general-purpose communication between programmable
    controllers; largely superseded by DP and retained only for backward
    compatibility.

This document specifies the PROFIBUS-DP communication profile and its
physical layers (RS-485 and MBP/IEC 61158-2), the hybrid medium-access
control, the telegram (frame) formats, the DP service levels DPV0/DPV1/
DPV2, the GSD device-description mechanism, diagnostics, baud rates, and
station addressing.

2 Architecture and Layering
===========================
PROFIBUS follows a reduced OSI layering model. Only three layers are
implemented for DP:

  Layer 1 — Physical Layer (PHY): RS-485 (IEC 61158-2 Type 3 / EIA-485)
            for DP, or MBP (Manchester Bus Powered, IEC 61158-2) for PA.
  Layer 2 — Data-Link Layer: the Fieldbus Data Link (FDL), which provides
            the hybrid token-passing + master-slave Medium Access Control
            (MAC) and the telegram framing, addressing and checksum.
  Layer 7 — Application Layer: the DP services (DPV0 cyclic data exchange,
            DPV1 acyclic read/write and alarms, DPV2 isochronous and
            slave-to-slave) and the Direct Data Link Mapper (DDLM) /
            User Interface that the field-device application sees.

Layers 3-6 are empty (not used). The application program accesses the FDL
through the DDLM and the DP User Interface.

3 Physical Layer
================
3.1 RS-485 Transmission (PROFIBUS-DP, the H2 / electrical PHY)
-------------------------------------------------------------
The DP physical layer is a balanced (differential) two-wire RS-485 line,
designated the A-line and B-line, in a linear bus (daisy-chain) topology
with active bus termination at both ends. Key parameters:

  * Medium: shielded twisted-pair copper cable (PROFIBUS cable type A).
  * Signaling: differential NRZ, half-duplex, balanced per EIA/RS-485.
  * Connector: 9-pin D-sub (DB9) or M12; pin 3 = B-line (RxD/TxD-P),
    pin 8 = A-line (RxD/TxD-N).
  * Bus termination: 220 ohm pull termination network with 390 ohm
    pull-up to +5 V (VP, pin 6) and 390 ohm pull-down to DGND (pin 5),
    enabled at the two physical ends of the segment.
  * Baud rate (data rate): selectable 9.6 kbit/s, 19.2 kbit/s, 45.45
    kbit/s, 93.75 kbit/s, 187.5 kbit/s, 500 kbit/s, 1.5 Mbit/s, 3 Mbit/s,
    6 Mbit/s and 12 Mbit/s. The maximum is 12 Mbit/s.
  * Segment length depends on baud rate: up to 1200 m at 9.6-187.5
    kbit/s, down to 100 m at 12 Mbit/s; repeaters extend the network and
    each repeater counts as a station load.
  * Up to 32 stations per segment without a repeater; up to 126 active
    stations (addresses 0-125) on the whole network with repeaters.
  * Character format (UART frame): 11 bits per character — 1 start bit,
    8 data bits, 1 even parity bit, 1 stop bit (per IEC 61158 the FDL
    uses even parity).

3.2 MBP / IEC 61158-2 Transmission (PROFIBUS-PA)
------------------------------------------------
PROFIBUS-PA uses the MBP (Manchester Bus Powered) physical layer per
IEC 61158-2:

  * Signaling: Manchester-encoded, synchronous, fixed 31.25 kbit/s.
  * Bus-powered: the same two wires carry both the data signal and the DC
    supply for the field devices (current-modulation signaling, +-9 mA
    around the DC base current).
  * Intrinsic safety: designed for hazardous (Ex ia/ib) areas; the
    available power is limited (FISCO model) so it cannot ignite an
    explosive atmosphere.
  * Topology: trunk-and-spur, tree or star with a segment coupler / DP-PA
    link bridging PA segments onto the DP backbone.

A DP/PA coupler or link transparently couples the 31.25 kbit/s PA segment
to the high-speed RS-485 DP backbone, so PA devices appear to the DP
master as ordinary DP slaves.

4 Medium Access Control (Data-Link Layer / FDL)
===============================================
PROFIBUS uses a HYBRID medium-access method that combines token passing
between the active stations (masters) with master-slave polling of the
passive stations (slaves). This supports multi-master operation.

4.1 Token passing (between masters)
-----------------------------------
The active stations (DP masters) form a logical token ring ordered by
station address. A station may transmit only while it holds the token.
The token is passed in ascending station-address order with the Token
telegram (SD4); the highest-addressed master passes the token back to the
lowest-addressed master, closing the logical ring. The Target Rotation
Time (TTR) bounds how long one token rotation may take; each master is
allowed to initiate message cycles until its token-hold time expires,
then it must forward the token. The MAC also runs the Live List / GAP
maintenance procedure (each master periodically polls the GAP — the
address range up to its successor — to detect newly added or removed
stations and to admit new masters into the ring).

4.2 Master-slave (token holder polls slaves)
---------------------------------------------
While a master holds the token it polls its assigned slaves. The master
sends a request telegram addressed to a slave; the slave must answer
within the slot time with a response telegram or a short acknowledgement.
Passive slaves never initiate a transmission on their own; they only
respond when polled. A DP Class-1 master (DPM1) performs the cyclic data
exchange with its slaves; a DP Class-2 master (DPM2) is an engineering /
diagnostic / configuration device.

4.3 Timers
----------
  * TSL — Slot Time: the maximum time the sender waits for the start of
    the addressed station's response before assuming no answer.
  * TID1/TID2 — Idle Times after a transaction.
  * TTR — Target Rotation Time (token-ring budget).
  * TSDR — Station Delay of Responder (min/max time a responder waits
    before it may send its reply).

5 Telegram (Frame) Formats
==========================
PROFIBUS data-link telegrams are byte-oriented. Each telegram begins with
a Start Delimiter (SD) byte that selects the telegram format, and (for
the variable/fixed data telegrams) ends with a Frame Check Sequence (FCS)
and an End Delimiter (ED = 0x16).

5.1 Start Delimiters (SD)
-------------------------
  * SD1 = 0x10 — fixed-length telegram with NO data field (used for poll,
    diagnostic request, FDL status). Format:
        SD1 | DA | SA | FC | FCS | ED
  * SD2 = 0x68 — variable-length telegram WITH data field (the normal
    data telegram, e.g. cyclic I/O). Format:
        SD2 | LE | LEr | SD2 | DA | SA | FC | DSAP | SSAP | DU... | FCS | ED
    LE is the length byte (count of DA+SA+FC+data), repeated as LEr for
    redundancy; the second SD2 (0x68) re-confirms the start.
  * SD3 = 0xA2 — fixed-length telegram WITH 8 octets of data field.
        SD3 | DA | SA | FC | DU(8) | FCS | ED
  * SD4 = 0xDC — Token telegram (token-pass between masters). Format:
        SD4 | DA | SA   (no FC, no FCS, no ED)
  * SC  = 0xE5 — Short Acknowledgement (single byte), used as a positive
    short ACK with no data.

5.2 Telegram fields
-------------------
  * DA  — Destination Address (1 octet; station address 0-127, bit 7 is
    the EXT bit indicating that a DSAP/SSAP service-access-point byte
    follows in the data unit).
  * SA  — Source Address (1 octet; with EXT bit for SSAP presence).
  * FC  — Frame Control (1 octet): encodes the frame type (Send/Request
    SRD or SDN, Request-FDL-Status, Token), the Frame Count Bit (FCB) and
    Frame-Count-Bit-Valid (FCV) for duplicate/lost-frame detection, and
    the station type (master/slave) and FDL state.
  * DSAP — Destination Service Access Point (selects the DP service at the
    receiver; present when DA.EXT = 1).
  * SSAP — Source Service Access Point (selects the service at the sender;
    present when SA.EXT = 1). Default SAP (no DSAP/SSAP byte) is used for
    the cyclic Data_Exchange service.
  * DU   — Data Unit (the L7 payload / PDU, 0..246 octets).
  * FCS  — Frame Check Sequence: an 8-bit arithmetic checksum (modulo 256
    sum of DA+SA+FC+data), NOT a CRC.
  * ED   — End Delimiter = 0x16.

5.3 SAP (Service Access Point) numbers
---------------------------------------
DP uses fixed SAP numbers for its services, e.g.:
  SAP 54 — Master-to-Master (DPM2)         SAP 55 — Set_Slave_Address
  SAP 56 — Read_Inputs                     SAP 57 — Read_Outputs
  SAP 58 — Global_Control (Sync/Freeze)    SAP 59 — Get_Configuration
  SAP 60 — Slave_Diagnosis (Get_Diag)      SAP 61 — Set_Parameters (Set_Prm)
  SAP 62 — Check_Configuration (Chk_Cfg)   Default SAP — Data_Exchange (cyclic)

6 PROFIBUS-DP Service Levels (Application Layer)
===============================================
DP is layered into three service levels, all backward compatible:

6.1 DPV0 — Cyclic Data Exchange (base level)
--------------------------------------------
DPV0 is the basic, deterministic cyclic exchange of process I/O between
the DPM1 master and its slaves:
  * Parameterization (Set_Prm), Configuration check (Chk_Cfg), then the
    Data_Exchange cyclic loop in which the master writes outputs to and
    reads inputs from each slave every bus cycle.
  * Standard diagnostics (Slave_Diag) reporting station/module/channel
    status.
  * Global_Control broadcast for SYNC (freeze outputs) and FREEZE (freeze
    inputs) synchronization of slave groups.

6.2 DPV1 — Acyclic Data Exchange and Alarms
-------------------------------------------
DPV1 extends DP with acyclic services that run in the gaps of the cyclic
cycle:
  * Acyclic READ and WRITE to slave data records addressed by Slot and
    Index (MSAC_C1 from the Class-1 master, MSAC_C2 from a Class-2 master
    via an explicit connection: Initiate / Data_Transport / Abort).
  * Alarm handling (process, diagnostic, pull/plug, status, update
    alarms) with acknowledged alarm transport.
  * Extended diagnostics.

6.3 DPV2 — Isochronous and Slave-to-Slave
-----------------------------------------
DPV2 adds:
  * Isochronous Mode (Isochronous): clock-synchronous operation in which
    all slaves sample inputs and apply outputs synchronized to an
    equidistant, isochronous bus cycle (Global_Control clock).
  * DXB — Data Exchange Broadcast (Slave-to-slave / publisher-subscriber):
    a slave publishes its inputs directly to other slaves without going
    through the master, reducing latency.
  * Up/download, time stamping and redundancy services.

7 GSD — General Station Description
==================================
Every DP slave (and DP master) is described by a GSD file (General Station
Description, also called Device Database File). The GSD is an ASCII text
device-description file supplied by the device manufacturer that the
engineering tool reads to configure the device WITHOUT a device-specific
driver. It declares:
  * Vendor / model / Ident_Number (a PI-assigned 16-bit device identity).
  * Supported baud rates and the corresponding bus timing constants.
  * The module list and the configuration (Cfg) identifier bytes that
    describe each module's input/output data length and consistency.
  * User parameter bytes (Set_Prm data), DPV1/DPV2 capability flags, and
    diagnostic text references.
The DPM2 engineering tool merges the slaves' GSD files into the master's
parameter and configuration set, which the DPM1 then downloads via
Set_Prm / Chk_Cfg at startup.

8 Diagnostics
=============
DP provides a standardized, layered diagnostic mechanism. A slave returns
diagnostic information in response to the Slave_Diag (Get_Diag) service:
  * Station-related diagnostics (6 mandatory bytes): station status 1/2/3,
    master address (the address of the master that parameterized the
    slave) and the Ident_Number.
  * Module-related (identifier) diagnostics — a bit per configured module
    indicating which module raised a diagnosis.
  * Channel-related diagnostics — per-channel error type (e.g. short
    circuit, under/over-voltage, overtemperature, line break).
  * Device/extended (manufacturer) diagnostics — vendor-specific.
A slave signals "new diagnostics available" via the response so the master
re-reads the full diagnostic frame.

9 State Machine (Slave)
=======================
A DP slave traverses a defined startup state machine driven by the master:
  POWER_ON -> Wait_Prm (waiting for Set_Parameters) -> Wait_Cfg (waiting
  for Check_Configuration) -> Data_Exchange (cyclic I/O running). At any
  point a parameterization or configuration mismatch, a watchdog timeout
  (the slave's watchdog supervises the master's cyclic access), or a
  Global_Control CLEAR forces the slave back toward a safe / cleared
  output state.

10 Addressing
=============
  * Station addresses are 0 to 126 (7 bits in DA/SA; address 127 = 0x7F
    is reserved as the broadcast/global address). Address 126 is the
    factory default delivery address used with Set_Slave_Address.
  * Up to 126 stations addressable on a network (with repeaters).
  * Up to 32 stations per RS-485 segment without a repeater.

11 Summary of Key Constants
===========================
  Standards            : IEC 61158 (Type 3), IEC 61784-1 (CPF 3),
                         former EN 50170 / DIN 19245
  Profiles             : PROFIBUS-DP, PROFIBUS-PA, PROFIBUS-FMS (legacy)
  PHY (DP)             : RS-485, differential 2-wire, 9.6 kbit/s .. 12 Mbit/s
  PHY (PA)             : MBP / IEC 61158-2, Manchester, 31.25 kbit/s,
                         bus-powered, intrinsically safe
  MAC                  : hybrid token-passing (masters) + master-slave
                         (slave polling), multi-master
  Start delimiters     : SD1 = 0x10, SD2 = 0x68, SD3 = 0xA2, SD4 = 0xDC
  Short ACK            : SC = 0xE5
  End delimiter        : ED = 0x16
  Telegram fields      : DA, SA, FC, DSAP, SSAP, DU, FCS (8-bit checksum)
  Service levels       : DPV0 (cyclic), DPV1 (acyclic + alarms),
                         DPV2 (isochronous + slave-to-slave DXB)
  Device description   : GSD (General Station Description) file
  Station addresses    : 0 .. 126 (127 = broadcast)
  Stations             : <= 32 per segment, <= 126 per network
