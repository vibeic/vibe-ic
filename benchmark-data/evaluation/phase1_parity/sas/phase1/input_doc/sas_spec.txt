Serial Attached SCSI (SAS) — Information Technology Standard
INCITS T10 Serial Attached SCSI (SAS-3 / SAS-4)

ABSTRACT

Serial Attached SCSI (SAS) is a point-to-point, full-duplex, serial storage
interconnect that carries SCSI commands, SATA traffic, and management traffic
over a single differential physical link (phy). SAS is standardized by the
INCITS T10 technical committee. It defines the SAS Serial SCSI Protocol (SSP)
for SCSI command transport, the SATA Tunneling Protocol (STP) for bridging
Serial ATA (SATA) devices, and the Serial Management Protocol (SMP) for
discovering and managing the topology of expanders. SAS phys are aggregated
into ports; multiple phys with the same SAS address form a wide port. Devices
and expanders are interconnected through a SAS domain.

1. OVERVIEW

SAS replaces the parallel SCSI (SPI) bus with a high-speed serial,
point-to-point, full-duplex differential link. Each connection between two
devices runs over one or more phys. A SAS phy is a single full-duplex
differential transmit/receive pair. The transmitter drives a differential
signal on TX+/TX-; the receiver recovers data on RX+/RX-.

SAS is a layered architecture:
  - Physical layer: differential signaling, out-of-band (OOB) signaling,
    spread-spectrum clocking, speed negotiation.
  - Phy layer: 8b10b encoding (1.5/3/6 Gbps), 128b150b forward error
    correction encoding (12 Gbps and 22.5 Gbps), running disparity, dword
    synchronization.
  - Link layer: primitives, address frames, connection management, rate
    matching, scrambling, CRC.
  - Port layer: wide-port aggregation of phys with the same SAS address.
  - Transport layer: SSP, STP, and SMP frames.
  - Application layer: SCSI, ATA, and management commands.

A SAS device contains one or more phys; each phy has a SAS address. A SAS port
is the set of phys in a device that have the same SAS address and attach to
another port with the same matching attached SAS address. A port with one phy
is a narrow port; a port with more than one phy is a wide port.

2. LINK RATES AND CODING

SAS defines the following physical link rates:
  - SAS-1: 1.5 Gbps and 3 Gbps
  - SAS-2: 6 Gbps
  - SAS-3: 12 Gbps
  - SAS-4: 22.5 Gbps

At 1.5, 3, and 6 Gbps SAS uses 8b10b encoding with running disparity. At
12 Gbps (SAS-3) and 22.5 Gbps (SAS-4) SAS uses 128b150b encoding with a
forward error correction (FEC) capability. Each 10-bit (8b10b) or 150-bit
(128b150b) symbol stream is organized into dwords (4 bytes / 40 bits in 8b10b).
Spread-spectrum clocking (SSC) may be applied to reduce electromagnetic
emissions.

3. SAS ADDRESS AND TOPOLOGY

Every SAS port has a 64-bit SAS address (a worldwide unique Name Address
Authority, NAA, identifier). The SAS address uniquely identifies the port in
the SAS domain. A SAS domain is the set of SAS devices and expander devices
that interconnect with one another.

Expander devices route connections between SAS phys and grow the SAS domain
beyond a direct point-to-point attachment. There are two expander types:
  - Edge expander device: connects end devices and may connect to a fanout
    expander; an edge expander set bounds a subtractive routing domain.
  - Fanout expander device: connects multiple edge expander devices to build
    large topologies.

Expanders contain an expander route table and perform table routing,
subtractive routing, and direct routing of connection requests. The Serial
Management Protocol (SMP) is used to discover the topology, read the expander
route table, and configure expander routing.

4. PORTS AND WIDE PORTS

A wide port bundles multiple phys that share the same SAS address into a single
logical port, increasing aggregate bandwidth and providing path redundancy. A
wide link is the set of phys connecting two wide ports. The number of phys in a
wide port is the port width. Connections from a wide port may be established on
any of the constituent phys.

5. TRANSPORT PROTOCOLS

SAS multiplexes three transport protocols over the phy:

5.1 SSP — Serial SCSI Protocol
SSP transports SCSI commands, task-management functions, data, and status
between a SAS initiator port and a SAS target port. SSP defines the following
frame types:
  - COMMAND frame: carries a SCSI Command Descriptor Block (CDB).
  - TASK frame: carries a task-management function.
  - XFER_RDY frame: target-to-initiator transfer-ready (flow control for
    write data).
  - DATA frame: carries read or write data.
  - RESPONSE frame: carries SCSI status and sense data.
Each SSP frame has a frame header, an information unit, and a 32-bit CRC.

5.2 STP — SATA Tunneling Protocol
STP tunnels Serial ATA (SATA) traffic across the SAS domain so that SATA
devices may be attached behind SAS expanders. STP carries SATA Frame
Information Structures (FIS) inside SAS connections. An STP initiator
communicates with a SATA target device through an STP/SATA bridge in an
expander (the STP target port).

5.3 SMP — Serial Management Protocol
SMP is a request/response management protocol used to discover and configure
the SAS topology. An SMP initiator port sends an SMP REQUEST frame to an SMP
target port (typically in an expander) and receives an SMP RESPONSE frame.
SMP functions include REPORT GENERAL, DISCOVER, REPORT PHY ERROR LOG, and
CONFIGURE ROUTE INFORMATION.

6. CONNECTION MANAGEMENT

SAS is connection-oriented at the link layer. Before SSP, STP, or SMP frames
flow, a connection is opened between two ports. The connection sequence uses
address frames and primitives:

  - The originating port transmits an OPEN address frame containing the
    initiator's source SAS address, the destination SAS address, the requested
    connection rate, the protocol (SSP/STP/SMP), and the arbitration wait time.
  - Expanders route the OPEN address frame toward the destination, replying
    with AIP (Arbitration In Progress) primitives while arbitration proceeds.
  - The destination replies with OPEN_ACCEPT to accept the connection or
    OPEN_REJECT to reject it.
  - Once open, the connection is a dedicated full-duplex path; frames flow in
    both directions until a CLOSE primitive closes the connection.
  - BREAK aborts a connection request or an open connection.

Arbitration uses the arbitration wait time (AWT) carried in the OPEN address
frame to resolve contention fairly across the SAS domain. Rate matching is
performed when the connection rate is slower than the physical link rate by
inserting ALIGN (and NOTIFY) primitives so the faster phy does not overrun the
slower path.

7. PRIMITIVES

SAS primitives are single dwords with special control characters used for link
management. Defined primitives include:
  - ALIGN: dword synchronization, rate matching, and clock skew management.
  - NOTIFY: signals events such as power loss expected.
  - SOF / EOF: Start of Frame / End of Frame delimiters for SSP/SMP frames.
  - SOAF / EOAF: Start / End of Address Frame.
  - RRDY: Receiver Ready — grants one frame of credit for flow control.
  - ACK / NAK: acknowledge / negative-acknowledge an SSP frame.
  - CREDIT_BLOCKED: no more credit available.
  - OPEN_ACCEPT / OPEN_REJECT: connection response.
  - AIP: Arbitration In Progress.
  - CLOSE: close an open connection.
  - BREAK: abort a connection or connection request.
  - DONE: end of the current connection's frame transmission.
  - HARD_RESET: reset the attached phy.

8. LINK LAYER: CODING, SCRAMBLING, CRC

The link layer scrambles the data dwords (excluding primitives) with a
linear-feedback scrambler to spread spectral energy and reduce EMI. Each SSP
and SMP frame is protected by a 32-bit CRC computed over the frame contents.
Running disparity is maintained across the 8b10b stream. Idle dwords (ALIGN /
idle) keep the link synchronized between frames. A frame is delimited by SOF
and EOF (or SOAF/EOAF for address frames).

9. SPEED NEGOTIATION AND OOB

Before normal operation, two attached phys perform out-of-band (OOB) signaling
and speed negotiation:
  - OOB signals: COMINIT/COMRESET, COMSAS, and COMWAKE are low-speed burst
    patterns used to detect attachment and distinguish SAS from SATA.
  - COMSAS identifies a SAS phy (a SATA device does not respond with COMSAS).
  - The Speed Negotiation Window (SNW) sequence negotiates the highest common
    supported link rate (1.5/3/6/12/22.5 Gbps) between the two phys.
After OOB and speed negotiation, the phys achieve dword synchronization and the
link is ready for connection requests.

10. PHY POWER MANAGEMENT

SAS defines partial and slumber phy power conditions, entered via the
NOTIFY (ENABLE SPINUP) and phy power management primitives, allowing a phy to
reduce power while remaining able to wake on activity.

11. SIGNALS

Each SAS phy presents a differential transmit pair (TX+ / TX-) and a
differential receive pair (RX+ / RX-). A SAS connector aggregates the phys of a
wide port plus power and sideband signals. There is no separate forwarded clock
wire; the receiver recovers the clock from the encoded serial stream
(8b10b or 128b150b).

12. INITIATOR, TARGET, AND EXPANDER DEVICES

  - SAS initiator device: originates SSP/STP/SMP connection requests and SCSI
    commands (e.g., a host bus adapter).
  - SAS target device: responds to commands (e.g., a SAS disk drive); it has an
    SSP target port and may contain logical units.
  - Expander device: routes connections among phys; contains SMP target
    function and the expander route table.
A device may contain initiator, target, and expander functions.

13. ERROR HANDLING

  - SSP frame CRC error: the frame is NAKed and retransmitted.
  - OPEN_REJECT: the connection request is rejected (no destination, pathway
    blocked, bad destination, retry).
  - BREAK: aborts a stalled connection.
  - Expander pathway recovery resolves blocked or deadlocked routing.
  - Running-disparity / 8b10b code violation: invalid dword, link error
    counted in the phy error log (readable via SMP REPORT PHY ERROR LOG).

14. COMPLIANCE SUMMARY

A compliant SAS port supports: point-to-point full-duplex serial differential
phys; 8b10b (<=6 Gbps) and 128b150b (12/22.5 Gbps) coding with FEC capability;
64-bit SAS addresses; wide-port aggregation; SSP, STP, and SMP transport
protocols; connection-oriented link layer with OPEN address frames, AIP,
OPEN_ACCEPT/OPEN_REJECT, arbitration wait time, and rate matching via ALIGN;
RRDY/ACK/NAK flow control; 32-bit CRC; scrambling; OOB (COMINIT/COMSAS/COMWAKE)
and Speed Negotiation Window; and expander-based topology managed by SMP.
