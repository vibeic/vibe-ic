IEEE Std 802.15.4 Low-Rate Wireless Personal Area Networks (LR-WPANs)
and the Zigbee Specification (Connectivity Standards Alliance)

Combined PHY / MAC / Network / Application Specification — Reconstructed
Technical Digest for a 2.4 GHz IEEE 802.15.4 + Zigbee Pro SoC

================================================================================
PART 0 — SCOPE AND DOCUMENT IDENTITY
================================================================================

This document specifies a low-power, low-data-rate wireless personal area
network (LR-WPAN) device built on IEEE Std 802.15.4 (Physical Layer and Medium
Access Control sublayer) and the Zigbee specification (Network layer,
Application Support sublayer, and Zigbee Device Object) maintained by the
Connectivity Standards Alliance (CSA, formerly the Zigbee Alliance).

  Standard family   : IEEE 802.15.4 (PHY + MAC); Zigbee (NWK + APS + ZDO + ZCL)
  Maintained by     : IEEE 802.15 Working Group; Connectivity Standards Alliance
  Frequency band    : 2.4 GHz ISM (2400-2483.5 MHz), 16 channels (channel 11-26)
  Also defined      : 902-928 MHz (915 MHz, North America); 868-868.6 MHz (Europe)
  Modulation        : O-QPSK with half-sine pulse shaping over DSSS
  Spreading         : Direct Sequence Spread Spectrum (DSSS), 32-chip PN sequence
  Data rate         : 250 kbps at 2.4 GHz; 40 kbps (915 MHz); 20 kbps (868 MHz)
  Channel access    : CSMA-CA (slotted in beacon-enabled, unslotted otherwise)
  Topologies        : star, peer-to-peer (mesh), cluster-tree
  Device roles      : 802.15.4 FFD / RFD; PAN Coordinator / Coordinator;
                      Zigbee Coordinator / Router / End Device
  Security          : AES-128 in CCM* (CCM star) mode; network key + link key

This SoC integrates the 802.15.4 PHY (O-QPSK/DSSS radio interface) and MAC
(CSMA-CA, superframe, GTS, addressing), the Zigbee NWK layer (mesh/tree/star
routing), the APS (Application Support sublayer), the ZDO (Zigbee Device
Object), and the Zigbee Cluster Library (ZCL) application framework.

================================================================================
PART 1 — PHYSICAL LAYER (PHY, IEEE 802.15.4 Clause 8/10/12)
================================================================================

1.1 Frequency bands and channels
---------------------------------
The 2.4 GHz O-QPSK PHY uses 16 channels numbered 11 through 26, spaced 5 MHz
apart. The channel center frequency Fc (MHz) is:

    Fc = 2405 + 5 * (k - 11)    for k = 11, 12, ..., 26

  Channel 11 = 2405 MHz ... Channel 26 = 2480 MHz.

The 868/915 MHz PHY defines channel 0 (868.3 MHz) and channels 1-10
(906 + 2*(k-1) MHz). The page/channel selection is held in the PHY PIB
attribute phyCurrentChannel and the channel page in phyCurrentPage.

1.2 Modulation and spreading (O-QPSK / DSSS)
--------------------------------------------
The 2.4 GHz PHY employs Offset Quadrature Phase-Shift Keying (O-QPSK) with
half-sine pulse shaping. Each data symbol (4 bits) is mapped to one of 16
nearly orthogonal 32-chip pseudo-random noise (PN) spreading sequences —
Direct Sequence Spread Spectrum (DSSS). The chip rate is 2.0 Mchip/s, giving a
symbol rate of 62.5 ksymbol/s and a data rate of 250 kbps (4 bits/symbol).

  - Modulation        : O-QPSK, half-sine pulse shaping (MSK-equivalent)
  - Spreading         : DSSS, 32 chips per symbol, 16 PN sequences
  - Chip rate         : 2.0 Mchip/s
  - Symbol rate       : 62.5 ksymbol/s
  - Bits per symbol   : 4
  - Data rate         : 250 kbps (2.4 GHz band)

1.3 PHY Protocol Data Unit (PPDU) frame format
----------------------------------------------
The PPDU has three components:

  SHR  Synchronization Header : Preamble (4 octets, all-zero) + SFD (1 octet,
                                Start-of-Frame Delimiter = 0xA7)
  PHR  PHY Header            : Frame Length field (7 bits), 1 reserved bit;
                              length 0-127 octets (aMaxPHYPacketSize = 127)
  PSDU PHY Service Data Unit : the MAC frame (MPDU), 0-127 octets

1.4 PHY constants and PIB attributes
------------------------------------
  aMaxPHYPacketSize        = 127 octets (max PSDU)
  aTurnaroundTime          = 12 symbols (Rx-to-Tx / Tx-to-Rx turnaround)
  phyCurrentChannel        : current channel (11-26 for 2.4 GHz)
  phyChannelsSupported     : bitmap of supported channels
  phyTransmitPower         : transmit power level
  phyCCAMode               : Clear Channel Assessment mode (1=energy, 2=carrier,
                            3=carrier+energy)
  ED (Energy Detection)    : receiver energy detection for channel scan
  LQI (Link Quality Indicator) : per-packet link quality measure (0x00-0xFF)
  RSSI                     : received signal strength indication

1.5 PHY services (PD-SAP / PLME-SAP)
------------------------------------
  PD-DATA            : transfer PSDU between MAC and PHY
  PLME-CCA           : Clear Channel Assessment request
  PLME-ED            : Energy Detection measurement
  PLME-SET-TRX-STATE : set transceiver state (RX_ON, TX_ON, TRX_OFF)
  PLME-GET / PLME-SET: PHY PIB attribute access
  PLME-SET-TRX-STATE turnaround governed by aTurnaroundTime = 12 symbols.

================================================================================
PART 2 — MAC SUBLAYER (IEEE 802.15.4 Clause 6/7)
================================================================================

2.1 MAC frame types
-------------------
The MAC sublayer defines four frame types, encoded in the Frame Type subfield
(bits 0-2) of the Frame Control field:

  0b000  Beacon frame          (transmitted by a coordinator)
  0b001  Data frame            (carries an MSDU)
  0b010  Acknowledgement frame (confirms reception of a frame whose AR bit set)
  0b011  MAC command frame     (association, disassociation, data request, etc.)

2.2 MAC General Frame Format (MPDU)
-----------------------------------
  MHR  MAC Header:
       Frame Control (2 octets), Sequence Number (1 octet), Addressing fields
       (Destination PAN ID, Destination Address, Source PAN ID, Source Address),
       Auxiliary Security Header (variable, if Security Enabled)
  MAC Payload (variable)
  MFR  MAC Footer: Frame Check Sequence (FCS, 2 octets, ITU-T CRC-16)

Frame Control field subfields:
  Frame Type (3 bits), Security Enabled (1), Frame Pending (1),
  Acknowledgment Request / AR (1), PAN ID Compression (1),
  Destination Addressing Mode (2), Frame Version (2),
  Source Addressing Mode (2).

2.3 Addressing
--------------
  PAN ID                 : 16-bit Personal Area Network identifier
  Short address          : 16-bit address, allocated on association
  Extended address       : 64-bit IEEE address (EUI-64), globally unique
  Broadcast short address: 0xFFFF
  Unallocated short addr : 0xFFFE
  Addressing modes (2-bit): 0=none, 2=16-bit short, 3=64-bit extended

2.4 Channel access — CSMA-CA
----------------------------
Carrier Sense Multiple Access with Collision Avoidance governs medium access.
Two variants:

  Slotted CSMA-CA   : used in beacon-enabled PANs; backoff aligned to the
                      superframe backoff-slot boundaries.
  Unslotted CSMA-CA : used in non-beacon-enabled PANs; free-running backoff.

CSMA-CA algorithm variables:
  NB  Number of Backoffs       (retried up to macMaxCSMABackoffs, default 4)
  BE  Backoff Exponent         (macMinBE default 3 ... aMaxBE default 5)
  CW  Contention Window length (slotted only, default 2)
  Backoff period = aUnitBackoffPeriod = 20 symbols.
A device waits a random (2^BE - 1) backoff periods, performs a CCA, and
transmits if the channel is idle; otherwise BE is incremented and NB retried.

2.5 Superframe structure (beacon-enabled mode)
----------------------------------------------
In a beacon-enabled PAN the PAN coordinator bounds the channel with a
superframe delimited by network beacons. The superframe is divided into 16
equally sized slots and has:

  Beacon                 : transmitted at the start of each superframe
  CAP  Contention Access Period   : slotted CSMA-CA contention
  CFP  Contention Free Period     : Guaranteed Time Slots (GTS), no contention
  Inactive period        : (optional) coordinator may sleep

Superframe timing:
  BI = aBaseSuperframeDuration * 2^BO   (Beacon Interval; BO = macBeaconOrder)
  SD = aBaseSuperframeDuration * 2^SO   (Superframe Duration; SO = macSuperframeOrder)
  aBaseSuperframeDuration = aBaseSlotDuration * aNumSuperframeSlots
  aBaseSlotDuration = 60 symbols; aNumSuperframeSlots = 16.
  0 <= macSuperframeOrder <= macBeaconOrder <= 14.

2.6 Guaranteed Time Slots (GTS)
-------------------------------
The PAN coordinator may allocate up to seven GTS in the CFP to provide
deterministic, contention-free bandwidth to devices with low-latency or
guaranteed-throughput needs. Each GTS is one or more contiguous superframe
slots, allocated via a GTS request MAC command and advertised in the beacon's
GTS descriptor list. GTS direction is transmit or receive relative to the
coordinator.

2.7 MAC command frames
----------------------
  0x01 Association request
  0x02 Association response
  0x03 Disassociation notification
  0x04 Data request
  0x05 PAN ID conflict notification
  0x06 Orphan notification
  0x07 Beacon request
  0x08 Coordinator realignment
  0x09 GTS request

2.8 Device types and roles (802.15.4)
-------------------------------------
  FFD  Full-Function Device   : implements the full MAC; can be a PAN
                                coordinator, a coordinator, or a device; can
                                relay frames and accept associations.
  RFD  Reduced-Function Device: minimal implementation; communicates only with
                                a single coordinator; cannot relay; typically a
                                low-cost, battery sensor/actuator end node.
  PAN Coordinator : the principal controller of a PAN; selects PAN ID, starts
                    the PAN, transmits beacons (beacon-enabled mode).
  Coordinator     : an FFD that can relay and manage associations but is not the
                    PAN coordinator.

2.9 Association / scanning
--------------------------
  Energy Detection (ED) scan  : measure channel energy for PAN start.
  Active scan                 : send Beacon Request, collect beacons.
  Passive scan                : listen for beacons (beacon-enabled).
  Orphan scan                 : relocate a coordinator after loss of sync.
A device joins by issuing an Association request MAC command and receiving a
short address in the Association response.

2.10 MAC PIB attributes (selected)
----------------------------------
  macPANId, macShortAddress, macExtendedAddress (aExtendedAddress / EUI-64),
  macBeaconOrder (BO), macSuperframeOrder (SO), macAssociationPermit,
  macMaxCSMABackoffs (4), macMinBE (3), macMaxBE / aMaxBE (5),
  macMaxFrameRetries (3), macAckWaitDuration, macGTSPermit.

================================================================================
PART 3 — ZIGBEE NETWORK LAYER (NWK)
================================================================================

3.1 NWK overview
----------------
The Zigbee Network layer (NWK) sits above the 802.15.4 MAC. It is responsible
for joining and leaving a network, applying security to frames, routing frames
to their destination, discovering and maintaining routes, and discovering and
maintaining one-hop neighbours. Zigbee supports star, tree, and mesh
topologies; Zigbee Pro uses mesh routing.

3.2 Zigbee device roles (NWK)
-----------------------------
  Zigbee Coordinator (ZC) : exactly one per network; forms the network,
                            selects the PAN ID and channel, is the Trust Center,
                            allocates the network key; an FFD; address 0x0000.
  Zigbee Router (ZR)      : an FFD that relays packets (extends mesh range),
                            permits other devices to join, and routes.
  Zigbee End Device (ZED) : a leaf node (RFD or FFD) that communicates only
                            through its parent (a router or the coordinator);
                            may sleep to save power (Sleepy End Device).

3.3 NWK addressing and routing
------------------------------
  Network (short) address : 16-bit, assigned at join time.
  Routing                 : mesh routing based on an AODV-derived (Ad hoc
                            On-demand Distance Vector) route discovery — Route
                            Request (RREQ) / Route Reply (RREP) broadcast/unicast;
                            also tree (Cskip distributed addressing) and source
                            routing for many-to-one (concentrator) flows.
  Neighbor table          : one-hop neighbours and their link costs.
  Routing table           : destination -> next-hop entries with status.
  Broadcast               : network-wide broadcast with passive acknowledgement.

3.4 NWK frame format
--------------------
  NWK Header: Frame Control (2 octets), Destination Address (16-bit),
              Source Address (16-bit), Radius, Sequence Number,
              optional Destination/Source IEEE address, Multicast control,
              Source Route subframe, optional NWK Auxiliary security header.
  NWK Payload.

================================================================================
PART 4 — APPLICATION SUPPORT SUBLAYER (APS) AND ZDO
================================================================================

4.1 APS (Application Support sublayer)
--------------------------------------
The APS provides the interface between the NWK layer and the application. It
maintains the binding table (links source endpoint/cluster to destination),
provides reliable end-to-end APS acknowledgements, fragments/reassembles long
ASDUs, and applies APS-level security (link keys). The APS multiplexes traffic
to/from application objects identified by an endpoint (1-240) and a cluster.

  APS frame types : Data, Command, Acknowledgement, Inter-PAN.
  Endpoints       : 1-240 application endpoints; endpoint 0 = ZDO; 255 = broadcast.
  Binding         : (source addr, source endpoint, cluster) -> (dest addr,
                    dest endpoint), held in the binding table.
  APS counters    : APS sequence number; APS retries; APS acknowledgement.

4.2 ZDO (Zigbee Device Object)
------------------------------
The Zigbee Device Object resides on endpoint 0 and provides device and service
discovery, network management, and binding management. ZDO services use the
Zigbee Device Profile (ZDP) cluster commands:

  Device discovery   : NWK_addr_req, IEEE_addr_req
  Service discovery  : Node_Desc_req, Simple_Desc_req, Active_EP_req,
                      Match_Desc_req
  Binding management : Bind_req, Unbind_req
  Network management : Mgmt_Lqi_req, Mgmt_Rtg_req, Mgmt_Permit_Joining_req,
                      Mgmt_Leave_req

4.3 ZCL (Zigbee Cluster Library) and profiles
---------------------------------------------
Application functionality is organized as clusters (e.g. On/Off, Level Control,
Color Control, Temperature Measurement, IAS Zone). Each cluster has a 16-bit
cluster identifier, attributes (with attribute IDs and data types), and
commands. The Zigbee Cluster Library (ZCL) defines the general command frame:

  ZCL Header : Frame Control, (Manufacturer Code), Transaction Sequence
               Number, Command Identifier.
  ZCL general commands : Read Attributes, Write Attributes, Configure Reporting,
               Report Attributes, Default Response, Discover Attributes.
  Profiles   : Home Automation (HA), and the unified Zigbee 3.0 application
               profile; profile identifier scopes the cluster semantics.
  Endpoint   : a Simple Descriptor declares the endpoint's profile id, device
               id, and input/output cluster lists.

================================================================================
PART 5 — SECURITY (AES-128-CCM*)
================================================================================

5.1 Security services
----------------------
Zigbee security uses AES-128 (128-bit Advanced Encryption Standard) operated in
CCM* (CCM star) mode, providing data confidentiality (encryption), data
integrity (Message Integrity Code, MIC), and replay protection (frame counter).
CCM* is a minor variation of CCM (Counter with CBC-MAC) that additionally
allows encryption-only and integrity-only operation.

  Cipher           : AES-128 block cipher
  Mode             : CCM* (combined CTR encryption + CBC-MAC authentication)
  MIC length       : 0, 32, 64, or 128 bits (security level dependent)
  Frame counter    : 32-bit, monotonically increasing, anti-replay
  Security levels  : 0x00 (none) .. 0x07 (ENC-MIC-128)

5.2 Keys and Trust Center
-------------------------
  Network key  : 128-bit symmetric key shared by all devices in the network;
                 used to secure NWK-layer frames; distributed by the Trust
                 Center; supports key rotation (Key sequence number).
  Link key     : 128-bit pairwise key for APS-layer end-to-end security between
                 two devices; trust-center link key or application link key.
  Trust Center : a single device (normally the Zigbee Coordinator) that
                 authenticates joining devices and distributes the network key;
                 manages key establishment.
  Install code : per-device pre-configured secret used to derive a unique
                 trust-center link key during commissioning (Zigbee 3.0).

================================================================================
PART 6 — INTEGRATION / REGISTER / IMPLEMENTATION NOTES
================================================================================

6.1 Stack layering (bottom to top)
-----------------------------------
  PHY (802.15.4)  -> MAC (802.15.4)  -> NWK (Zigbee)  -> APS (Zigbee)
  -> ZDO/ZCL (Zigbee application framework) -> Application objects (endpoints).

6.2 Host / SoC interface
------------------------
The SoC exposes the MAC/NWK/APS via SAP primitives (request/confirm/indication/
response). A typical SoC integrates: the O-QPSK/DSSS radio (RX/TX, ED, CCA, LQI/
RSSI), a MAC engine (CSMA-CA, superframe timer, GTS manager, FCS/CRC-16), an
AES-128-CCM* security engine, and the NWK/APS/ZDO/ZCL firmware. Control and
status are exposed through memory-mapped registers and the SAP message
interface; configuration includes channel, PAN ID, short/extended address,
beacon/superframe order, security keys, and the binding/neighbor/routing tables.

6.3 External RF pins
--------------------
  RF_P / RF_N  : differential 2.4 GHz RF port to the antenna balun/matching
  RF_BIAS      : RF bias
  VDD_RF, VSS  : RF supply and ground
  XTAL_P/XTAL_N: reference crystal (typically 16/32 MHz) for the synthesizer

6.4 Key numeric constants (summary)
-----------------------------------
  aMaxPHYPacketSize        = 127 octets
  aTurnaroundTime          = 12 symbols
  aUnitBackoffPeriod       = 20 symbols
  aBaseSlotDuration        = 60 symbols
  aNumSuperframeSlots      = 16
  aBaseSuperframeDuration  = 960 symbols (60 * 16)
  macMaxCSMABackoffs       = 4
  macMinBE                 = 3
  aMaxBE                   = 5
  macMaxFrameRetries       = 3
  Max GTS per superframe   = 7
  Broadcast short address  = 0xFFFF
  SFD (2.4 GHz O-QPSK)     = 0xA7
  Channels (2.4 GHz)       = 11..26 (16 channels)
  Data rate (2.4 GHz)      = 250 kbps
  Chip rate                = 2.0 Mchip/s
  Network/link key size    = 128 bits (AES-128)
  Frame counter            = 32-bit
