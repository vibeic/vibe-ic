GDDR6 SGRAM (Graphics Double Data Rate type 6 SDRAM) — JEDEC Standard
JEDEC JESD250 Graphics Double Data Rate 6 (GDDR6) SGRAM Standard

ABSTRACT

Graphics Double Data Rate type 6 Synchronous Graphics RAM (GDDR6 SGRAM) is a
high-bandwidth, point-to-point graphics memory device standardized by the JEDEC
Solid State Technology Association in document JESD250. GDDR6 is designed for
graphics processing units (GPUs), AI accelerators, network switches, and other
bandwidth-hungry applications that require very high per-pin data rates. A GDDR6
device is organized as TWO INDEPENDENT CHANNELS per device; each channel is a
16-bit (x16) interface with its own command/address (CA) bus, its own clock
(CK), its own write clock (WCK), and its own data (DQ) and error-detection (EDC)
pins. A pseudo-channel mode further splits each 16-bit channel into two 8-bit
pseudo-channels that share the same command/address bus but operate with
independent column commands. GDDR6 uses NRZ (non-return-to-zero) signaling and a
prefetch of 16n with a fixed burst length of BL16. Per-pin signaling rates reach
16 to 18 Gb/s. The interface is point-to-point (single rank, on-package or
on-board next to the GPU) and is NOT a DIMM/module memory.

This document specifies the GDDR6 SGRAM functional behavior, the two-channel
architecture, the WCK write-clock and WCK2CK alignment/training, the prefetch
16n / BL16 data organization, Data Bus Inversion (DBI), Command/Address Bus
Inversion (CABI), the read CRC and write CRC error-detection scheme on the EDC
pins, the bank-group architecture, the command set, the mode registers, the pin
list, the training flows, and the DC/AC operating conditions per JESD250.

NOTE — GDDR6 (this JESD250 standard) uses NRZ signaling. GDDR6X (a Micron
proprietary variant) uses PAM4 four-level signaling and is NOT part of JESD250.
This document specifies GDDR6 NRZ only.

1. OVERVIEW AND APPLICATION

GDDR6 is a graphics SGRAM (Synchronous Graphics RAM). It targets the graphics
memory subsystem of GPUs and accelerators where aggregate memory bandwidth, not
capacity per DIMM, is the dominant requirement. Each GDDR6 device sits adjacent
to the GPU as a point-to-point load — there is no DIMM, no module, no multi-rank
shared bus. Bandwidth is scaled by placing many GDDR6 devices around the GPU,
each contributing two independent 16-bit channels.

Key architectural features:
  - Two independent channels per device (Channel A and Channel B), each x16.
  - Optional pseudo-channel mode: each 16-bit channel is divided into two 8-bit
    pseudo-channels that share the CA bus but have independent column accesses.
  - Quarter-rate command clock CK with a separate higher-rate Write Clock WCK.
  - WCK runs at twice the CK data-rate so that WCK toggles once per transferred
    data bit pair; WCK2CK training aligns the WCK domain to the CK domain.
  - 16n prefetch architecture, fixed burst length BL16.
  - NRZ signaling at 16-18 Gb/s per pin.
  - Bank-group organization to hide tCCD timing and sustain back-to-back access.
  - Data Bus Inversion (DBI) on the DQ bus to limit simultaneous switching.
  - Command/Address Bus Inversion (CABI) on the CA bus.
  - Read CRC and Write CRC on a per-byte-lane basis, transferred on the EDC pins,
    for end-to-end data-integrity error detection.
  - Low-power states (self refresh, power down, hibernate self refresh).

2. SIGNAL DESCRIPTION (PER CHANNEL)

Each of the two channels exposes the following signal groups:

  Clock:
    CK_t, CK_c        Differential command clock (quarter-rate). All CA commands
                      are captured on CK. One CK pair per channel.
    WCK_t, WCK_c      Differential Write Clock. WCK runs at a higher rate than CK
                      (WCK = 2x CK data rate). One WCK pair per byte (per 8-bit
                      group / per pseudo-channel) so data can be captured at full
                      per-pin rate. WCK2CK alignment is trained before write/read.

  Command / Address:
    CA[9:0]           Command/Address bus, double-data-rate, captured on CK. Each
                      command occupies CA over two CK edges (CA rising/falling).
    CABI_n            Command/Address Bus Inversion strobe (active low). When the
                      Hamming weight of the CA word exceeds a threshold, the CA
                      word is inverted and CABI_n is asserted to cap the number of
                      driven-low CA lines.

  Data:
    DQ[15:0]          Bidirectional data bus (16 bits per channel). DDR on WCK.
    DBI_n[1:0]        Data Bus Inversion (active low), one per byte lane. When more
                      than half the bits of a byte would be driven low, the byte
                      is inverted and DBI_n asserted (DBIdc minimum-transition or
                      DBIac toggle-minimization mode, set by mode register).
    EDC[1:0]          Error Detection and Correction pins, one per byte lane. The
                      device drives the read CRC on EDC during reads; the
                      controller drives the write CRC on EDC during writes. Between
                      transfers the EDC pin drives the programmable EDC hold
                      pattern so the controller's DLL/CDR stays locked.

  Control:
    RESET_n           Asynchronous device reset (active low), common to the device.
    CKE / power-down  Clock-enable / power-down control via command.

  Supplies:
    VDD               Core supply, nominal 1.35 V.
    VDDQ              I/O supply, nominal 1.35 V.
    VPP               Wordline pump supply (e.g. 1.8 V).
    VREFC, VREFD      Reference voltages for CA and DQ receivers (internally
                      generated and trained via Vref training).

3. TWO-CHANNEL ARCHITECTURE

A GDDR6 device contains two channels that are fully independent: each has its own
CK, WCK, CA, DQ, DBI, EDC, mode-register set, bank groups, and command pipeline.
The two channels share only the package, RESET_n, and the power supplies. A
controller treats Channel A and Channel B as two separate 16-bit memories. This
two-independent-16-bit-channel structure is the defining organizational feature
of GDDR6 and distinguishes it from earlier single-channel x32 graphics DRAM
(GDDR5).

In pseudo-channel mode, each 16-bit channel is divided into two 8-bit pseudo-
channels (PC0 = DQ[7:0], PC1 = DQ[15:8]). Both pseudo-channels share the same CA
bus and the same row commands (ACTIVATE/PRECHARGE) but issue INDEPENDENT column
commands (READ/WRITE), which improves access concurrency for small-granularity
graphics traffic.

4. CLOCKING — CK, WCK, AND WCK2CK ALIGNMENT

GDDR6 uses two clock domains per channel:

  CK (command clock): quarter-rate relative to the data rate. CA commands are
  captured on CK_t/CK_c. Running CK at quarter rate reduces command-bus power.

  WCK (write clock): a separate, higher-rate forwarded clock used to capture and
  launch data on the DQ bus. WCK runs at twice the CK data rate; data is
  transferred on both edges of WCK (DDR), so DQ achieves the full per-pin rate
  (e.g. 16 Gb/s with WCK at 8 GHz). There is one WCK pair per byte group so the
  skew budget per byte is independent.

Because WCK and CK are separate forwarded clocks at different rates, their phase
relationship must be established before data transfers. The WCK2CK alignment
(training) procedure aligns the WCK rising edge to a defined CK edge per channel.
The controller issues the WCK2CK sync command; the device reports the captured
phase; the controller adjusts WCK phase until aligned. WCK2CK training is re-run
on rate changes and periodically to track drift.

5. TRAINING FLOWS

GDDR6 requires several training steps after reset and on rate change:
  - CA training (CAT): trains the command/address bus timing. The device captures
    a known CA pattern and reports it back on the DQ/EDC pins so the controller
    can center the CA eye.
  - WCK2CK training: aligns the WCK domain to the CK domain (Section 4).
  - Read training (read DQ/DBI deskew): centers the read data eye using a
    programmable read-training pattern from the mode registers.
  - Write training (write DQ/DBI deskew): centers the write data eye.
  - Vref training: trains the internal DQ and CA reference voltages (VREFD,
    VREFC) for the best receiver margin.

6. DATA ORGANIZATION — PREFETCH 16n, BURST LENGTH BL16

GDDR6 uses a 16n prefetch architecture: a single column command moves 16 bits per
DQ pin to/from the array, transferred as a burst of 16 (BL16) on the DQ bus. With
a 16-bit channel, one BL16 read or write moves 16 (bits) x 16 (DQ) = 256 bits =
32 bytes per channel per column access. In pseudo-channel mode each 8-bit pseudo-
channel transfers BL16 over 8 DQ = 16 bytes independently.

7. DATA BUS INVERSION (DBI) AND CA BUS INVERSION (CABI)

Data Bus Inversion (DBI) reduces simultaneous-switching noise and DC power on the
DQ bus. Two modes are selectable via mode register:
  - DBIdc (DC, minimum-driven-low): if more than 4 of the 8 bits in a byte would
    be driven low, the byte is inverted and DBI_n asserted, capping driven-low DQ.
  - DBIac (AC, transition-minimization): the byte is inverted when doing so
    reduces the number of transitions versus the previous byte.
Each byte lane has a dedicated DBI_n pin.

Command/Address Bus Inversion (CABI) applies the same principle to the CA bus:
when too many CA bits would be driven low, the CA word is inverted and CABI_n is
asserted. CABI is enabled/disabled by mode register.

8. ERROR DETECTION — READ CRC, WRITE CRC, AND THE EDC PINS

GDDR6 provides end-to-end data-integrity checking using an 8-bit CRC computed per
byte lane over the BL16 burst, transferred on the EDC pins:
  - Write CRC: the controller computes an 8-bit CRC over each byte lane's written
    BL16 data and transmits it to the device on the EDC pin. The device
    recomputes the CRC; on mismatch it flags a write-CRC error (and may set an
    error status / assert an alert), so the controller can replay the write.
  - Read CRC: the device computes the 8-bit CRC over each byte lane's read BL16
    data and transmits it to the controller on the EDC pin alongside the data. The
    controller recomputes and compares to detect a read error.
The CRC polynomial is an 8-bit polynomial applied per byte lane. CRC can be
enabled/disabled and its mode configured via the mode registers.

Between CRC/data transfers, each EDC pin drives a programmable EDC hold pattern.
The hold pattern keeps the controller's clock-data recovery and DLL locked on the
EDC lane during idle so the lane is ready for the next CRC transfer.

9. BANK GROUP ARCHITECTURE

Each channel's memory array is divided into bank groups, with multiple banks per
bank group. Consecutive column accesses to DIFFERENT bank groups can be issued
back-to-back at the short tCCD_S (CAS-to-CAS, short) timing, while accesses to
the SAME bank group must observe the longer tCCD_L. The bank-group structure lets
GDDR6 sustain its high data rate without stalling between column commands. Typical
organization: 4 bank groups x 4 banks = 16 banks per channel (density dependent).

10. COMMAND SET

GDDR6 commands are issued on the CA bus over two CK edges and include:
  ACTIVATE (ACT)        Open a row in a bank.
  PRECHARGE (PRE)       Close a row / all rows.
  READ (RD)             Column read, BL16.
  WRITE (WR)            Column write, BL16.
  REFRESH (REF)         All-bank or per-bank refresh.
  MODE REGISTER SET     Load a value into mode register MR0..MRx (via MRS).
  SELF REFRESH ENTRY/EXIT
  POWER DOWN ENTRY/EXIT
  WCK2CK SYNC           Initiate WCK-to-CK alignment.
  LOAD MODE / READ MODE Read/write of the mode-register space.
  NOP / Deselect

Key AC timing parameters (per JESD250): tRCD (ACT-to-READ/WRITE), tRP (PRECHARGE),
tRAS (row active), tRC (row cycle), tCCD_S / tCCD_L (CAS-to-CAS short/long),
tWTR (write-to-read), tFAW (four-activate window), tRFC (refresh cycle), tREFI
(refresh interval), CL (CAS latency), WL (write latency).

11. MODE REGISTERS

GDDR6 mode registers MR0 through MR15 (16 mode registers) configure device
operation. Representative assignments (JESD250):
  MR0   CAS latency (CL), WCK ratio.
  MR1   Write latency (WL), drive strength, termination.
  MR2   Option control: CABI enable, CRC enable (read/write), DBI mode (dc/ac),
        EDC hold pattern enable.
  MR3   Bank group / DRAM organization, data-mask / write-mask control.
  MR4   EDC hold pattern value, CRC write-latency adder, refresh management.
  MR5   Per-DRAM addressability, RDQS, PLL/DLL.
  MR6   VREFD training value (DQ reference).
  MR7   Low-frequency mode, WCK termination, hibernate self refresh, PLL bypass.
  MR8   Reference voltage range, CA reference (VREFC) control.
  MR9   Read/write training pattern.
  MR10  WCK2CK / WCK termination training control.
  MR11  Channel / pseudo-channel mode control.
  MR12-MR15  Vendor / training / Vref-fine / reserved.

12. POWER STATES

GDDR6 supports several reduced-power states:
  - Self Refresh: the device retains data with its internal refresh; the external
    clock can be stopped.
  - Hibernate Self Refresh: a deeper self-refresh with reduced internal regulation
    for long idle.
  - Power Down: CKE-controlled, fast-exit clock-gated state.
  - Low-frequency mode (MR7): lets the device run at reduced clock for low power.

13. DC / AC OPERATING CONDITIONS

  VDD  = 1.35 V nominal (core).
  VDDQ = 1.35 V nominal (I/O).
  VPP  = 1.8 V nominal (wordline pump).
  Per-pin data rate: 16 Gb/s to 18 Gb/s (NRZ).
  POD135 (Pseudo-Open-Drain) I/O referenced to VDDQ, with on-die termination.
  Signaling: NRZ (two-level). (GDDR6X PAM4 is out of scope of JESD250.)

14. INITIALIZATION SEQUENCE (SUMMARY)

  1. Apply power (VDD, VDDQ, VPP) in the specified order; hold RESET_n low.
  2. Release RESET_n; wait the reset-to-CKE-high time.
  3. Start CK; program mode registers (MR0..MR15) for both channels.
  4. Run CA training (CAT) on each channel.
  5. Start WCK; run WCK2CK alignment/training on each channel.
  6. Run read training and write training (DQ/DBI deskew).
  7. Run Vref training (VREFD, VREFC).
  8. Enable CRC / DBI / CABI as configured; device is ready for normal traffic.

15. APPLICATION CONTEXT AND POSITIONING

GDDR6 (JESD250) is the graphics-DRAM generation succeeding GDDR5/GDDR5X and
preceding GDDR6X (Micron PAM4, non-JEDEC) and GDDR7. It is distinct from:
  - DDR3/DDR4/DDR5 mainstream DRAM (JESD79-x): those are CK-only (no separate WCK),
    DIMM/module memories with a shared multi-rank command/data bus; they have no
    EDC pins, no per-byte read/write CRC on EDC, no WCK, and are not organized as
    two independent graphics channels.
  - LPDDR5 (JESD209-5): a low-power MOBILE DRAM that ALSO uses a WCK write clock,
    but it is a low-power/mobile device (not graphics), has no EDC error-detection
    pins, no CABI command/address bus inversion as GDDR6 defines it, and is not a
    JESD250 graphics SGRAM. The presence of WCK alone does NOT make a device
    GDDR6 — GDDR6 is distinguished by the graphics SGRAM context, the JESD250
    standard, the EDC read/write CRC pins, CABI, and the two-independent-16-bit-
    channel organization.
  - HBM3 (JESD238): a 3D TSV-stacked DRAM with a 1024-bit wide interface on a
    silicon interposer; HBM3 is stacked/on-interposer, not the point-to-point
    on-board/on-package x16 device GDDR6 is.
