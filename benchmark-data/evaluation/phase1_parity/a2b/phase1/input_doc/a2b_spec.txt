Automotive Audio Bus (A2B) — Transceiver Technical Specification
Analog Devices A2B (AD24xx family: AD2410 / AD2420 / AD2425 / AD242x)

ABSTRACT

The Automotive Audio Bus (A2B) is a high-bandwidth, bidirectional, digital
audio bus from Analog Devices that distributes multichannel digital audio,
control data, and power over a single unshielded twisted pair (UTP) cable in a
daisy-chain (line) topology. A2B is designed for automotive infotainment and
advanced driver-assistance system (ADAS) audio applications such as microphone
arrays, amplifiers, active noise cancellation (ANC), road-noise cancellation
(RNC), and remote speaker and microphone nodes. One A2B main node (master),
connected to a host processor or System-on-Chip (SoC), drives a daisy-chained
line of up to ten A2B sub nodes (slaves). Each A2B transceiver (for example the
AD2410 main/sub transceiver or the AD242x family) tunnels I2S/TDM digital audio
together with an I2C control channel, plus GPIO and interrupt signaling, over
the same twisted pair. A2B also delivers phantom power (bus power) to downstream
nodes over the very same twisted pair that carries the audio, eliminating
separate power wiring at remote nodes. Audio transport is organized into a
periodic superframe locked to the audio sample rate (for example 48 kHz),
providing deterministic, low, and constant latency (approximately two samples
end to end).

1. OVERVIEW

A2B replaces the bulky, heavy point-to-point analog and digital audio wiring
harnesses of a vehicle with a single twisted-pair daisy-chain. Where a
conventional automotive audio system runs many shielded cables from a head unit
to each microphone, amplifier, and speaker, A2B runs one unshielded twisted
pair from node to node in a line, carrying audio, control, interrupts, and power
together.

The bus is mastered by a single A2B main node (the A2B master). The main node
is connected to the vehicle host processor / SoC through a local I2S/TDM audio
port and a local I2C control port. The main node A2B transceiver converts the
host's local I2S/TDM audio frames and I2C register traffic into the A2B line
protocol and transmits them downstream over the twisted pair to the first sub
node. Each A2B sub node (A2B slave) is an A2B transceiver that recovers the bus
clock and data, extracts the audio slots and control data addressed to it,
re-times the downstream signal, and forwards it to the next sub node in the
daisy chain. Upstream data from the sub nodes (for example microphone audio)
flows back toward the main node in the same superframe.

A2B is fundamentally different from a flat shared bus: it is a synchronous,
clocked, line topology in which the main node is the single timing master and
every sub node is phase-locked to the bus. The combination of a single
twisted-pair daisy chain, a main/sub (master/slave) node hierarchy with node
discovery and addressing, a sample-rate-locked superframe with separate
downstream and upstream regions, phantom power over the bus, and tunneled
I2S/TDM audio plus I2C control is the defining structural signature of A2B and
is what distinguishes it from I2S, SoundWire, and S/PDIF.

A2B layered model:
  - Line / physical layer: single unshielded twisted pair (UTP), differential
    signaling, bus clock recovered from the line, phantom power (bus power)
    distribution over the same pair, low electromagnetic emissions.
  - Node layer: one A2B main node (master) and up to ten A2B sub nodes
    (slaves) in a daisy chain; node discovery, node addressing, per-node
    register space.
  - Superframe / data layer: a periodic superframe synchronous to the audio
    sample rate, divided into a downstream portion and an upstream portion,
    carrying audio slots, control, interrupts, and synchronization.
  - Tunneling layer: local I2S/TDM audio ports and a local I2C control port at
    each node are tunneled transparently over the bus; GPIO and interrupts are
    tunneled over distance.
  - Application layer: microphones, amplifiers, ANC/RNC, infotainment audio.

2. TOPOLOGY: DAISY-CHAIN OVER A SINGLE TWISTED PAIR

A2B uses a daisy-chain (line) topology. The main node connects to sub node 0
over one twisted pair; sub node 0 connects to sub node 1 over the next twisted
pair segment; and so on, up to sub node 9. There is exactly one A2B main node
(master) on the bus. The maximum chain length supported is up to ten sub nodes
(slaves) beyond the main node.

Each twisted-pair segment is point-to-point between two adjacent A2B
transceivers. The bus is therefore a chain of point-to-point links rather than a
single multidrop wire. Each transceiver has a B-side (toward the main node,
upstream) and an A-side (toward the next downstream sub node). The main node has
only an A-side (downstream); the last sub node may have only a B-side.

Cable: the medium is a single unshielded twisted pair (UTP), typically 100-ohm
characteristic impedance. The maximum distance between two adjacent nodes is on
the order of 15 meters, and the maximum total cable length across the daisy
chain is on the order of 40 meters, depending on cable and data rate. The use of
unshielded twisted pair (rather than coax or shielded cable) is a key cost and
weight advantage for automotive harnessing.

Because A2B carries audio, control, interrupts, and power over the same UTP, the
node-to-node wiring is reduced to two conductors, dramatically reducing harness
weight and cost relative to discrete I2S/TDM plus I2C plus power plus interrupt
wiring.

3. MAIN / SUB (MASTER / SLAVE) NODES AND THE TRANSCEIVER

Every A2B node is built around an A2B transceiver IC. The main node transceiver
and the sub node transceivers are typically the same silicon (for example the
AD2410), strapped or configured into main mode or sub mode.

Main node (A2B master):
  - Connected to the host SoC / processor via a local I2S/TDM audio port and a
    local I2C control port.
  - Acts as the bus timing master: generates the bus clock and the superframe
    sync, to which all sub nodes phase-lock.
  - Originates downstream transmission and collects upstream data.
  - The host configures the entire bus by reading and writing transceiver
    registers through the main node's I2C control port; register accesses to
    sub nodes are tunneled over the bus.

Sub node (A2B slave):
  - An A2B transceiver that recovers clock and data from its upstream (B-side)
    twisted pair, extracts the audio slots and control addressed to it, and
    forwards / re-times the stream to its downstream (A-side) neighbor.
  - Exposes a local I2S/TDM audio port (to a local codec, amplifier, ADC/DAC,
    or microphone) and a local I2C control port (to local peripherals).
  - Provides local GPIO pins whose state can be tunneled over the bus, and
    local interrupt sources that are reported upstream to the main node.

Transceiver register map: each A2B transceiver exposes a register space (for
example node configuration, slot control, I2S/TDM configuration, I2C passthrough
control, GPIO control, interrupt mask/status, phantom-power switch control). The
host reaches every node's registers over I2C through the main node; sub node
register accesses are tunneled in the control region of the superframe.

4. NODE DISCOVERY AND ADDRESSING

When the bus powers up, only the main node is configured. The bus is brought up
by a discovery process that enumerates the sub nodes one at a time, in order,
from the node nearest the main node outward:

  1. The host, through the main node, initiates discovery of the next undiscovered
     node on the chain.
  2. Phantom power (bus power) is switched on toward the next downstream segment,
     powering up the next sub node transceiver.
  3. The newly powered sub node achieves bus lock (phase-locks to the recovered
     bus clock and superframe sync) and announces itself.
  4. The main node assigns the sub node a node address (its position index in
     the chain, 0..9) and reads its node identification / vendor / product
     registers.
  5. The host configures the newly discovered node's audio slots, I2S/TDM
     format, I2C passthrough, GPIO, and interrupts by writing its registers
     (tunneled over the bus).
  6. Discovery repeats for the next downstream node until the whole chain is
     enumerated.

Node addressing: each sub node is identified by its node address, which equals
its position in the daisy chain (0 for the node nearest the main node, up to 9).
The main node addresses control and register traffic to a specific sub node by
node address; broadcast addressing to all nodes is also supported for common
configuration. Audio slots are mapped to nodes by configuration during/after
discovery.

Discovery is deterministic and ordered because phantom power is applied
segment-by-segment: a downstream node cannot be discovered until its upstream
neighbor has been discovered and instructed to switch power to the next segment.

5. SUPERFRAME: DOWNSTREAM AND UPSTREAM, SYNCHRONOUS TO THE SAMPLE RATE

A2B organizes all bus traffic into a periodic superframe. One superframe is
transmitted per audio sample period; the superframe rate equals the audio sample
rate (SYNC rate), for example 48 kHz. The superframe is the fundamental unit of
synchronization and is the reason A2B latency is deterministic and constant.

A superframe contains, in order:
  - A synchronization preamble / control region (the superframe SYNC), used by
    sub nodes to lock to the bus and to carry control and register-access data
    (the tunneled I2C, GPIO, interrupt, and discovery traffic).
  - A downstream portion: audio data and control flowing from the main node
    toward the sub nodes. Downstream audio slots carry, for example, playback /
    amplifier channels destined for sub nodes.
  - An upstream portion: audio data and status flowing from the sub nodes back
    toward the main node. Upstream audio slots carry, for example, microphone
    channels collected from sub nodes.

Each node consumes the downstream slots addressed to it and inserts its data into
the upstream slots assigned to it as the superframe passes. Because the
superframe is locked to the sample rate and the slot positions are fixed by
configuration, the end-to-end audio latency is deterministic and low —
approximately two audio samples (the order of tens of microseconds at 48 kHz)
from the main node's local I2S input to the farthest sub node's local I2S output.

Sample rates: the SYNC (superframe) rate is the system audio sample rate,
commonly 44.1 kHz or 48 kHz, with support for reduced and multiplied SYNC rates.
The number of audio channels (slots) the bus can carry depends on the data rate
and bit depth; A2B supports up to 32 upstream and 32 downstream audio channels
in aggregate at typical configurations (for example 32 channels of 16-bit or a
smaller number of 24-bit / 32-bit channels), tunneled as TDM slots.

6. PHANTOM POWER (BUS POWER) OVER THE TWISTED PAIR

A defining feature of A2B is phantom power: the main node (and, where configured,
intermediate sub nodes) supplies DC power to downstream nodes over the same
unshielded twisted pair that carries the audio and control. This is referred to
as bus power. A remote microphone or speaker node can therefore be powered
entirely from the A2B line with no local power supply and no separate power
wiring.

Phantom power is switched segment-by-segment during discovery: a node switches
power onto its downstream segment only when instructed, which both powers the
next node and gates the discovery sequence. Local-powered nodes (nodes with their
own supply) are also supported where the bus cannot deliver enough power.

Carrying audio, control, interrupts, and power over a single twisted pair is the
central value proposition of A2B and is a structural property not present in
I2S, SoundWire, or S/PDIF, none of which distribute power over the audio
medium.

7. TUNNELED I2S / TDM AUDIO, I2C CONTROL, GPIO, AND INTERRUPTS

A2B does not invent new local audio or control formats. Instead it tunnels the
familiar local interfaces transparently across the bus:

  - I2S / TDM audio tunneling: each A2B transceiver has a local I2S/TDM port
    (BCLK, SYNC/FSYNC/WS, DTX/DRX, with TDM slot framing). Audio presented to a
    node's local I2S/TDM input is mapped into A2B downstream or upstream slots,
    carried across the bus, and presented at the destination node's local
    I2S/TDM output. The local I2S/TDM clocks at each node are generated by the
    A2B transceiver and are synchronous to the bus, so all nodes' audio is
    sample-aligned.

  - I2C control tunneling: the host's I2C bus (connected to the main node's
    local I2C port) is tunneled over the A2B line so the host can read/write the
    registers of any sub node transceiver and any I2C peripheral local to a sub
    node, exactly as if it were on the host's local I2C bus. The sub node acts
    as an I2C controller (master) on its local I2C bus on behalf of the host.

  - GPIO over distance: a sub node's local GPIO pin states can be transported
    over the bus and reproduced at the main node (or another node), so a remote
    button, mute line, or status LED appears as a local GPIO. GPIO-over-distance
    is configured per pin.

  - Interrupts: each transceiver has interrupt sources (bus errors, GPIO events,
    I2C events, power faults). Sub node interrupts are tunneled upstream to the
    main node, which presents a single interrupt to the host; the host reads the
    interrupt status registers over the tunneled I2C to identify the source and
    node.

The local interfaces (I2S/TDM, I2C, GPIO, interrupt) are the SAME interfaces a
host or codec already uses; A2B's role is to carry them transparently over
distance on one twisted pair. This tunneling of I2S/TDM + I2C + GPIO + interrupt
over a daisy-chained twisted pair with bus power is the hallmark of A2B.

8. CLOCKING, LOCK, AND RE-TIMING

The main node is the timing master. It generates the bus clock and the
superframe SYNC. Each sub node recovers the bus clock from its upstream twisted
pair, phase-locks to it, and regenerates a clean, re-timed signal toward its
downstream neighbor. This node-by-node re-timing is what allows the chain to span
a long total cable length without accumulating jitter: each node restores the
signal.

All local I2S/TDM clocks (BCLK and SYNC/FSYNC) at every node are derived from the
recovered bus clock, so the entire system shares one audio time base. A node
reports a loss-of-lock condition as an interrupt to the main node.

Bus lock sequence at a node: detect activity on the B-side twisted pair →
recover clock → achieve superframe lock (align to SYNC) → respond to discovery →
become operational. Loss of lock at any node breaks the chain downstream of that
node and is reported upstream.

9. DATA INTEGRITY, ERRORS, AND DIAGNOSTICS

A2B is designed for the automotive environment and includes line diagnostics:
  - Per-node and per-line error detection (for example data decoding errors,
    CRC on the control/superframe structure, bus-lock errors).
  - Line fault diagnostics: detection of cable open, cable short to ground, short
    to battery, short across the pair, and reversed wiring on a given segment,
    reported through interrupt status registers.
  - Phantom-power fault detection (over-current / under-voltage) per segment.
  - Interrupt-driven reporting of all of the above upstream to the main node and
    then to the host.

These diagnostics let the host localize a fault to a specific segment / node,
which is essential for serviceability of a vehicle audio harness.

10. APPLICATION EXAMPLES

  - Microphone arrays: multiple remote microphone nodes (for hands-free, voice
    recognition, in-car communication, ANC/RNC) stream upstream audio to the
    head unit over one twisted pair, drawing phantom power from the bus.
  - Amplifiers / speakers: downstream audio channels are delivered to remote
    smart-amplifier nodes near the speakers, removing long analog speaker-level
    runs from the harness.
  - Active / road noise cancellation (ANC / RNC): the deterministic low latency
    and sample-aligned multichannel audio of A2B make it suitable for distributed
    ANC/RNC where reference microphones, error microphones, and anti-noise
    amplifiers are on different nodes.
  - Infotainment audio distribution: a head unit distributes multichannel audio
    to amplifiers and zones over the daisy chain.

11. KEY STRUCTURAL SIGNATURE (SUMMARY)

A document describes A2B when it exhibits ALL of the following structural
elements together:
  - A single unshielded twisted pair (UTP) carrying digital audio in a
    daisy-chain (line) topology.
  - One A2B main node (master) and multiple A2B sub nodes (slaves), with node
    discovery and node addressing (position-based, up to ten sub nodes).
  - A periodic superframe synchronous to the audio sample rate, divided into
    downstream and upstream portions, giving deterministic low latency
    (approximately two samples).
  - Phantom power (bus power) distributed to downstream nodes over the same
    twisted pair that carries the audio.
  - Tunneling of local I2S/TDM audio plus I2C control plus GPIO and interrupts
    over the bus.
  - An A2B transceiver (AD24xx family such as AD2410 / AD242x) at every node.

A2B is NOT the same as, and must be distinguished from:
  - I2S: a direct 3-wire local digital-audio link (SCK / WS / SD) between two
    chips on a board, with no daisy chain, no main/sub node discovery, no
    superframe, no power distribution, and no tunneling. I2S is what A2B TUNNELS;
    it is not A2B.
  - SoundWire (MIPI): a multidrop control + audio bus with SoundWire-specific
    framing, data ports, and a different physical layer; SoundWire does not use a
    twisted-pair daisy-chain with phantom power and AD24xx transceivers.
  - S/PDIF (IEC 60958): a single-direction biphase-mark-coded audio link over one
    coax or optical line; it has no node discovery, no superframe with separate
    upstream/downstream regions, no phantom power, and no I2C/GPIO tunneling.

12. TRANSCEIVER LOCAL PINS (REPRESENTATIVE)

A2B transceiver (per node) representative pin groups:
  - AP / AN (A-side positive / negative): downstream twisted-pair connection
    toward the next sub node.
  - BP / BN (B-side positive / negative): upstream twisted-pair connection
    toward the main node (absent on the main node's master side).
  - BCLK, SYNC (FSYNC / WS), DTX0/DTX1, DRX0/DRX1: local I2S/TDM audio port.
  - SDA, SCL: local I2C control port.
  - IO0..IO7 / GPIO: general-purpose I/O and interrupt pins (GPIO over distance).
  - IRQ / INT: interrupt output toward the host (main node) or local use.
  - VIN / SWGND / phantom-power switch pins: bus-power input and downstream
    power-switch control.

13. SUMMARY

A2B (Automotive Audio Bus, Analog Devices AD24xx) carries multichannel digital
audio, I2C control, GPIO, interrupts, AND phantom power over a single unshielded
twisted pair in a daisy chain of one main node (master) plus up to ten sub nodes
(slaves). It uses node discovery and addressing, a sample-rate-locked superframe
with downstream and upstream regions for deterministic low latency, and tunnels
the local I2S/TDM audio and I2C control of each node transparently across the
bus. Each node is an A2B transceiver such as the AD2410 or an AD242x device.
This combination — single-twisted-pair daisy chain, main/sub node discovery,
superframe, phantom power, and I2S/TDM + I2C tunneling — is the complete and
distinguishing structural definition of the Automotive Audio Bus.
