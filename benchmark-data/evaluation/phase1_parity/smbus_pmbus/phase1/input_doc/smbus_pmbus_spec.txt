--------------------------------------------------------------------------------
ABSTRACT
--------------------------------------------------------------------------------
The System Management Bus (SMBus) is a two-wire interface derived from the
Inter-Integrated Circuit (I2C) bus through which simple power-related and
system-management chips communicate with the rest of the system. It uses a
serial clock line (SMBCLK) and a serial data line (SMBDAT). SMBus is a control
bus for system and power management operations. A system may use SMBus to pass
messages to and from devices instead of toggling individual control lines.

SMBus extends I2C with system-management-specific structure: a defined set of
bus PROTOCOLS (Quick Command, Send Byte, Receive Byte, Write Byte/Word, Read
Byte/Word, Process Call, Block Write, Block Read, Block Write-Block Read Process
Call, Host Notify), an optional Packet Error Code (PEC) byte computed as a CRC-8
over the whole transaction for error detection, an out-of-band SMBALERT#
interrupt line with an Alert Response Address (ARA), and an Address Resolution
Protocol (ARP) for dynamic, plug-and-play address assignment using a 128-bit
Unique Device Identifier (UDID). SMBus also defines bus timeouts so a hung
device cannot lock the bus indefinitely (a feature absent in base I2C).

The Power Management Bus (PMBus) is an open standard power-management protocol
that builds an APPLICATION LAYER on top of SMBus. PMBus defines a standard
command language - a set of COMMAND CODES such as OPERATION, ON_OFF_CONFIG,
VOUT_COMMAND, VOUT_MODE, PAGE, STATUS_WORD, STATUS_BYTE, READ_VIN, READ_VOUT,
READ_IOUT, READ_TEMPERATURE_1 - through which a host configures, controls, and
monitors power-conversion devices (DC/DC converters, point-of-load regulators,
power supplies). PMBus standardizes numeric data formats (LINEAR11, LINEAR16 /
ULINEAR16, DIRECT, and VID), a CONTROL hardware pin, the SMBALERT# fault line, a
WRITE_PROTECT mechanism, multi-rail PAGE addressing, and group/zone command
protocols so multi-vendor power systems are interoperable.

--------------------------------------------------------------------------------
1. SMBus PHYSICAL LAYER AND ADDRESSING
--------------------------------------------------------------------------------
1.1 Wires
SMBus is a two-wire bus:
  - SMBCLK : serial clock line, driven by the bus master / host.
  - SMBDAT : bidirectional serial data line.
Both lines are open-drain (open-collector) and pulled up to VDD through pull-up
resistors, allowing wired-AND multi-device operation - exactly as on I2C.

1.2 Bus speed
  - SMBus 1.0/2.0 : 10 kHz (minimum) to 100 kHz (maximum) clock.
  - SMBus 3.0/3.1 : adds a high-speed mode of up to 1 MHz (1000 kHz).
The minimum clock frequency of 10 kHz, together with clock-low and clock-high
timeouts, is what lets SMBus detect a stuck device - this differs from I2C,
which has no minimum clock and no timeout.

1.3 Timeouts and clock stretching
SMBus defines:
  - TIMEOUT (Ttimeout) : 25 ms to 35 ms maximum clock-low time before a device
    must reset its interface; a master must abort and a slave must release the
    bus. This guards against a hung transaction.
  - Tlow:sext : cumulative clock-low extend time by a slave (<= 25 ms).
  - Tlow:mext : cumulative clock-low extend time by a master per byte
    (<= 10 ms).
Clock low extending (clock stretching) is permitted within these limits.

1.4 Device addressing
  - SMBus devices use 7-bit slave addresses (the address byte is the 7-bit
    address followed by a Read/Write direction bit), identical to I2C 7-bit
    addressing.
  - A small set of addresses is reserved by SMBus, including the Alert Response
    Address (ARA) used by the SMBALERT# mechanism and the SMBus Device Default
    Address used by ARP.

1.5 Roles
  - Host : a specialized master that manages the bus, may handle the SMBALERT#
    interrupt and Host Notify, and typically runs ARP. There is at most one
    host.
  - Master : a device that initiates transactions (drives SMBCLK, issues
    START/STOP and the address). The host is a master.
  - Slave / Device : a device that responds to its address.

--------------------------------------------------------------------------------
2. SMBus PROTOCOLS (BUS TRANSACTION ELEMENTS)
--------------------------------------------------------------------------------
SMBus carries data using a fixed set of protocols. Each transaction begins with
a START condition and the slave address+direction byte, and ends with a STOP
condition. An optional Packet Error Code (PEC) byte may be appended.

2.1 Quick Command
  Format : START, Address+RW, STOP. The single Read/Write bit conveys the entire
  message (e.g. turn a device on/off). No data byte, no PEC.

2.2 Send Byte
  Format : START, Address+Wr, Data byte, [PEC], STOP. Sends one command/data
  byte to the device.

2.3 Receive Byte
  Format : START, Address+Rd, Data byte (from slave), [PEC], STOP. Reads one
  byte from the device (no command code).

2.4 Write Byte / Write Word
  Format : START, Address+Wr, Command code, Data byte (Write Byte) or Data low +
  Data high (Write Word), [PEC], STOP.

2.5 Read Byte / Read Word
  Format : START, Address+Wr, Command code, repeated START, Address+Rd, Data
  byte (Read Byte) or Data low + Data high (Read Word), [PEC], STOP.

2.6 Process Call
  Format : START, Address+Wr, Command code, Data low, Data high, repeated START,
  Address+Rd, Data low, Data high, [PEC], STOP. A write-then-read in one
  transaction (a 16-bit "call").

2.7 Block Write
  Format : START, Address+Wr, Command code, Byte count N, Data 1 .. Data N,
  [PEC], STOP. The Byte Count field (1..255) tells the slave how many data
  bytes follow.

2.8 Block Read
  Format : START, Address+Wr, Command code, repeated START, Address+Rd, Byte
  count N, Data 1 .. Data N, [PEC], STOP. The slave returns a Byte Count and
  that many data bytes.

2.9 Block Write - Block Read Process Call
  Format : a Block Write followed (without releasing the bus) by a Block Read,
  used for variable-length call-and-response.

2.10 Host Notify
  Format : the slave device acts as a master and writes to the reserved SMBus
  Host Notify address (0001 000), sending its own device address plus a 16-bit
  data value. This is how a device asynchronously notifies the host of an event
  without using SMBALERT#.

--------------------------------------------------------------------------------
3. PACKET ERROR CODE (PEC)
--------------------------------------------------------------------------------
SMBus defines an optional Packet Error Code (PEC) to improve reliability. The
PEC is a single byte appended at the end of a transaction (before STOP). It is
an 8-bit Cyclic Redundancy Check (CRC-8) computed over ALL of the bytes in the
transaction including address, command, and data bytes (every byte that is
sent, in both write and read phases, including the address bytes with their
Read/Write bits).

  - CRC type        : CRC-8
  - Generator poly  : x^8 + x^2 + x^1 + 1  (i.e. 0x07, "CRC-8-ATM/SMBus")
  - Initial value   : 0x00
  - Coverage        : the complete message (slave address byte(s), command code,
                      and all data bytes)
  - Result          : an 8-bit PEC byte placed immediately before STOP.

A receiver that detects a PEC mismatch must NACK / discard the transaction. PEC
is negotiated/known per device; both ends must agree to use it. PEC is what
gives SMBus end-to-end data integrity that base I2C lacks.

--------------------------------------------------------------------------------
4. SMBALERT# AND THE ALERT RESPONSE ADDRESS
--------------------------------------------------------------------------------
SMBALERT# is an optional, active-low, open-drain interrupt line shared by
multiple slave devices (wired-OR). A device pulls SMBALERT# low to signal that
it needs attention.

Alert Response protocol:
  - On seeing SMBALERT# low, the host issues a Receive Byte to the reserved
    Alert Response Address (ARA = 0001 100).
  - Alerting devices arbitrate on SMBDAT (lowest address wins, exactly like I2C
    address arbitration); the winner returns its own 7-bit address on the data
    byte.
  - The host then services that device (e.g. reads its STATUS) and the device
    releases SMBALERT#. The host repeats until SMBALERT# is released by all.

This is an out-of-band, low-pin-count interrupt scheme that lets the host
discover WHICH device asserted the alert.

--------------------------------------------------------------------------------
5. ADDRESS RESOLUTION PROTOCOL (ARP)
--------------------------------------------------------------------------------
SMBus ARP provides dynamic, plug-and-play address assignment so devices do not
need hard-wired addresses.

  - Each ARP-capable device has a 128-bit Unique Device Identifier (UDID)
    containing a device capabilities field, version/revision, vendor ID,
    device ID, interface, subsystem fields, and a unique number.
  - The ARP master (usually the host) issues ARP commands to the reserved SMBus
    Device Default Address (1100 001):
      * Prepare to ARP
      * Reset Device (general or directed)
      * Get UDID (general or directed) - the device returns its 128-bit UDID
        plus its current address (Device Slave Address byte).
      * Assign Address - the master writes a UDID + a new 7-bit address; the
        device with the matching UDID adopts the assigned address.
  - Arbitration during Get UDID uses the UDID itself (the lowest UDID wins),
    allowing the master to enumerate all devices.

ARP makes SMBus a self-describing, dynamically addressable bus.

--------------------------------------------------------------------------------
6. PMBus OVERVIEW (APPLICATION LAYER ON SMBus)
--------------------------------------------------------------------------------
PMBus is an open-standard digital power-management protocol. The PMBus transport
(Part I) IS SMBus (with a few PMBus-specific extensions); the PMBus command
language (Part II) defines the meaning of each command code.

PMBus extends SMBus with:
  - A CONTROL pin : a hardware input on the power device that, in combination
    with the OPERATION command, turns the converter output on or off and selects
    margining.
  - The SMBALERT# fault line and the Alert Response Address, used to flag faults
    (over-current, over-temperature, over/under-voltage).
  - Standard COMMAND CODES (the command code byte of the SMBus Write/Read
    Byte/Word/Block transactions) with standardized meaning.
  - Numeric DATA FORMATS (LINEAR11, LINEAR16/ULINEAR16, DIRECT, VID) so reported
    voltages, currents, temperatures, and limits are interpreted uniformly.
  - PAGE-based addressing of multiple outputs (rails) within one device.
  - GROUP and ZONE command protocols for coordinating many devices.

PMBus bus speed is up to 400 kHz (PMBus 1.x) with optional 1 MHz, consistent
with SMBus.

--------------------------------------------------------------------------------
7. PMBus STANDARD COMMAND SET (SELECTED)
--------------------------------------------------------------------------------
PMBus assigns a command code (the SMBus command byte) to each standardized
function. Selected commands (command code in hex):

  0x00 PAGE              : selects which output/rail (page) subsequent commands
                           apply to in a multi-rail device. 0xFF = all pages.
  0x01 OPERATION         : turns the output on/off and selects margin state
                           (margin high/low), in combination with the CONTROL
                           pin and ON_OFF_CONFIG.
  0x02 ON_OFF_CONFIG     : configures how OPERATION and the CONTROL pin combine
                           to enable the output (which source controls on/off,
                           polarity, and turn-off behavior).
  0x10 WRITE_PROTECT     : controls which commands may be written, protecting the
                           device against accidental or malicious writes.
  0x20 VOUT_MODE         : reports the data format (LINEAR16 exponent, or DIRECT,
                           or VID mode/code) used by the voltage-related commands.
  0x21 VOUT_COMMAND      : sets the commanded (nominal) output voltage, in the
                           ULINEAR16 (VOUT) format scaled by the VOUT_MODE
                           exponent.
  0x24 VOUT_MAX          : sets the upper limit on commanded output voltage.
  0x35 VIN_ON            : input voltage at which the unit starts converting.
  0x40 VOUT_OV_FAULT_LIMIT : output overvoltage fault threshold.
  0x46 IOUT_OC_FAULT_LIMIT : output overcurrent fault threshold.
  0x4F OT_FAULT_LIMIT    : overtemperature fault threshold.
  0x78 STATUS_BYTE       : an 8-bit summary status (one byte).
  0x79 STATUS_WORD       : a 16-bit summary status; bits flag VOUT, IOUT, INPUT,
                           TEMPERATURE, CML (communication/memory/logic), and
                           other fault/warning groups, plus an OFF bit.
  0x7A STATUS_VOUT       : detailed output-voltage fault/warning bits.
  0x7B STATUS_IOUT       : detailed output-current fault/warning bits.
  0x7D STATUS_TEMPERATURE: detailed temperature fault/warning bits.
  0x88 READ_VIN          : measured input voltage (LINEAR11).
  0x8B READ_VOUT         : measured output voltage (ULINEAR16, per VOUT_MODE).
  0x8C READ_IOUT         : measured output current (LINEAR11).
  0x8D READ_TEMPERATURE_1: measured temperature (LINEAR11).
  0x98 PMBUS_REVISION    : the PMBus revision the device complies with.
  0x99 MFR_ID            : manufacturer ID (Block Read).
  0x9A MFR_MODEL         : manufacturer model (Block Read).

Read commands such as READ_VOUT/READ_IOUT/READ_TEMPERATURE_1 are implemented as
SMBus Read Word (or Read Byte) transactions; STATUS_WORD is a Read Word;
configuration commands such as VOUT_COMMAND are SMBus Write Word; MFR_ID is a
Block Read.

--------------------------------------------------------------------------------
8. PMBus DATA FORMATS
--------------------------------------------------------------------------------
8.1 LINEAR11 (Linear data format, "Linear-11")
  A two-byte value carrying a real number: a 5-bit signed (two's complement)
  EXPONENT N in the upper 5 bits and an 11-bit signed (two's complement)
  MANTISSA Y in the lower 11 bits. The value is:
      X = Y * 2^N
  Used for currents, temperatures, input voltage, time, and most non-VOUT
  parameters.

8.2 LINEAR16 / ULINEAR16 (VOUT mode)
  Output voltage uses a 16-bit UNSIGNED MANTISSA whose exponent is NOT in the
  data word but is a 5-bit two's-complement exponent reported by VOUT_MODE. The
  value is:
      VOUT = V * 2^(VOUT_MODE exponent)
  This gives high voltage resolution. VOUT_COMMAND and READ_VOUT use this
  format.

8.3 DIRECT
  A linear coordinate transform configured by three coefficients m (slope), b
  (offset), and R (scaling exponent). The real-world value is:
      Y = (1/m) * (X * 10^(-R) - b)
  where X is the two-byte value on the bus. DIRECT lets a device report raw
  ADC-friendly integers that the host converts using device-supplied m/b/R.

8.4 VID (Voltage Identification)
  An output voltage encoded as a VID code per a named VID table (e.g. Intel VR
  or AMD SVI codes). VOUT_MODE indicates VID mode and which VID code set is in
  use.

--------------------------------------------------------------------------------
9. PMBus CONTROL PIN, WRITE_PROTECT, FAULTS
--------------------------------------------------------------------------------
9.1 CONTROL pin
  A hardware enable input on the converter. ON_OFF_CONFIG selects whether the
  output is controlled by the CONTROL pin, by the OPERATION command, by both,
  or by neither, and sets CONTROL polarity and turn-off (immediate vs sequenced)
  behavior.

9.2 WRITE_PROTECT
  Restricts which commands may be written, ranging from "all writes allowed" to
  "only WRITE_PROTECT/PAGE/OPERATION allowed" to "no writes allowed", guarding
  the converter configuration.

9.3 Faults and warnings
  The device monitors VOUT, IOUT, VIN, IIN, and temperature against programmable
  fault and warning limits. On a fault the device sets the relevant STATUS bits,
  asserts SMBALERT#, and takes the configured action (shut down, retry, or
  continue). The host reads STATUS_WORD then the detailed STATUS_VOUT /
  STATUS_IOUT / STATUS_TEMPERATURE registers to localize the fault.

--------------------------------------------------------------------------------
10. PMBus GROUP AND ZONE COMMANDS
--------------------------------------------------------------------------------
10.1 Group command protocol
  A Group Command Protocol lets a host send a sequence of commands to several
  devices within a single packet, with one STOP at the end, so that all targeted
  devices act on the new commands simultaneously (e.g. a coordinated voltage
  change or simultaneous turn-on of several rails).

10.2 Zone read/write (PMBus 1.3)
  PMBus 1.3 adds Zone Read and Zone Write. Zones group devices that share a Zone
  Address; a Zone Write broadcasts a command to all devices in a zone, and a
  Zone Read gathers a summarized response from a zone, enabling scalable control
  of large multi-device power systems with fewer transactions.

--------------------------------------------------------------------------------
11. STATE / OPERATION BEHAVIOR
--------------------------------------------------------------------------------
A PMBus power device combines the SMBus transaction engine with a converter
control state machine:
  - IDLE      : output off; bus interface listening for its address.
  - ADDRESSED : the device has been addressed; it decodes the command code.
  - WRITE     : a Write Byte/Word/Block updates a configuration command (e.g.
    VOUT_COMMAND); WRITE_PROTECT may reject it.
  - READ      : a Read Byte/Word/Block returns measurement or status data.
  - ON / REGULATING : the output is enabled (per OPERATION + CONTROL pin +
    ON_OFF_CONFIG) and the converter regulates to the commanded VOUT.
  - FAULT     : a monitored quantity crossed a fault limit; STATUS bits set,
    SMBALERT# asserted, configured fault response taken.
The PEC engine validates each transaction; an ARP master may (re)assign the
device address; the CONTROL pin can enable/disable the output independent of the
bus.

--------------------------------------------------------------------------------
12. VERSION / COMPLIANCE NOTES
--------------------------------------------------------------------------------
  - SMBus 1.0 (1995), 2.0 (2000) : 100 kHz; defined PEC, ARP, SMBALERT#,
    Host Notify, the protocol set, and timeouts.
  - SMBus 3.0 (2014) / 3.1 (2018) : add a 1 MHz high-speed mode, 64-byte (and
    larger) block transfers clarified, and additional electrical options.
  - PMBus 1.0-1.2 : established the command language, LINEAR/DIRECT/VID formats,
    OPERATION/ON_OFF_CONFIG/CONTROL, STATUS registers, PAGE.
  - PMBus 1.3 (2015) : adds Zone Read/Write, additional commands, and AVSBus
    references.
A compliant SMBus device implements the relevant subset of the protocols, the
timeouts, and (where claimed) PEC, SMBALERT#/ARA, and ARP. A compliant PMBus
device implements the mandatory command subset, the declared data formats
(reported via VOUT_MODE / PMBUS_REVISION), STATUS reporting, and SMBALERT#
fault signaling.
