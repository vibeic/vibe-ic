AFDX / ARINC 664 Part 7
Avionics Full-Duplex Switched Ethernet (AFDX)
Aircraft Data Network, Part 7 — Avionics Full-Duplex Switched Ethernet Network
ARINC Specification 664P7
Aeronautical Radio, Inc. (ARINC) — Airlines Electronic Engineering Committee (AEEC)

This document describes Avionics Full-Duplex Switched Ethernet (AFDX), the
deterministic profiled Ethernet data network standardized as ARINC 664
Part 7 (Aircraft Data Network, Part 7). AFDX is the avionics data backbone
of modern commercial aircraft such as the Airbus A380, Airbus A350, and
Boeing 787; it provides a deterministic, redundant, switched network for
carrying avionics data between line-replaceable units (LRUs).


1. Scope and Purpose

AFDX is built on top of standard IEEE 802.3 full-duplex switched Ethernet
but profiles and constrains that base technology to make it deterministic
and suitable for safety-critical avionics. Commercial off-the-shelf
Ethernet is non-deterministic: collisions, best-effort delivery, and
unbounded latency are unacceptable for aircraft control and display data.
AFDX adds a set of mechanisms on top of 802.3 — Virtual Links, Bandwidth
Allocation Gap, traffic shaping and policing, dual-network redundancy, and
Redundancy Management with Integrity Checking — that together turn
best-effort Ethernet into a deterministic, fault-tolerant network with
guaranteed bandwidth and bounded latency and jitter.

AFDX defines two principal component classes:
  - End Systems (ES): the network interface that connects an avionics
    subsystem (LRU / host) to the AFDX network. The End System provides the
    deterministic services (Virtual Link traffic shaping, redundancy
    management, integrity checking) to the avionics application.
  - AFDX Switches: store-and-forward switches that interconnect End Systems
    and enforce per-Virtual-Link policing (traffic filtering and policing).

AFDX is built on IEEE 802.3 full-duplex switched Ethernet. There is no
shared medium and there are no collisions: every link is a point-to-point
full-duplex 10/100 Mbit/s (typically 100BASE-TX) connection between an End
System and a Switch, or between two Switches. CSMA/CD is not used. Frames
are standard Ethernet frames (IEEE 802.3) carried over this switched fabric.


2. Determinism Built on Switched Ethernet

The base layer is IEEE 802.3 full-duplex switched Ethernet. AFDX preserves
the standard Ethernet frame format (destination MAC address, source MAC
address, EtherType/length, payload, Frame Check Sequence (FCS)) so that
commercial Ethernet silicon and tooling can be reused, while adding the
deterministic profile on top.

Determinism is achieved through:
  - Virtual Links (VL) that segregate traffic into independent logical
    pipes with guaranteed bandwidth.
  - Bandwidth Allocation Gap (BAG) traffic shaping that bounds the rate of
    each Virtual Link.
  - Jitter bounds at the End System transmit port.
  - Deterministic store-and-forward switching with per-VL policing in the
    switches.
  - Dual redundant networks (Network A and Network B) with Redundancy
    Management and Integrity Checking at the receiver.


3. Virtual Links (VL)

The central concept of AFDX is the Virtual Link (VL). A Virtual Link is a
unidirectional logical connection from one source End System to one or more
destination End Systems. A Virtual Link defines a logical unidirectional
path with a single source and one or more destinations (a point-to-point or
point-to-multipoint / multicast path). All traffic on a Virtual Link flows
in one direction only.

Each Virtual Link is identified by a 16-bit Virtual Link Identifier
(VL ID). The VL ID is carried in the Ethernet destination MAC address. AFDX
uses a structured (constant + VL ID) destination MAC address: the upper
bytes of the destination MAC address are a fixed constant field
(0x03:00:00:00 — a locally-administered multicast prefix) and the lower
16 bits carry the Virtual Link Identifier. The destination MAC address of
an AFDX frame therefore has the form:

    Constant Field (32 bits)  |  Virtual Link Identifier (16 bits)
    0000 0011 0000 0000 0000 0000 0000 0000 | VL ID (16 bits)

Because the VL ID is embedded in the destination MAC address, AFDX switches
forward frames purely on the basis of the Virtual Link Identifier: the
switch's static forwarding/configuration table maps each VL ID to the set
of output ports for that Virtual Link. The forwarding tables are configured
offline (statically) during network design; AFDX does not use dynamic MAC
learning or spanning tree.

Sub-Virtual Links (Sub-VLs):
A Virtual Link may be subdivided into up to four Sub-Virtual Links
(Sub-VLs). Each Sub-VL has its own First-In-First-Out (FIFO) queue at the
transmit End System. Frames from the Sub-VL FIFOs are read in round-robin
order and multiplexed into the single Virtual Link traffic shaper. Sub-VLs
do NOT have their own Bandwidth Allocation Gap; they share the bandwidth of
the parent Virtual Link. Sub-VLs do not appear on the wire — the VL ID in
the frame is the parent Virtual Link's identifier; the Sub-VL structure is
purely a transmit-side queuing mechanism.


4. Bandwidth Allocation Gap (BAG) and Traffic Shaping

Each Virtual Link is allocated a guaranteed, bounded share of bandwidth by
its Bandwidth Allocation Gap (BAG). The Bandwidth Allocation Gap is the
minimum time interval between the first bits of two consecutive Ethernet
frames transmitted on the same Virtual Link. The BAG is a power of two in
the range 1 to 128 milliseconds:

    BAG ∈ { 1, 2, 4, 8, 16, 32, 64, 128 } ms      (BAG = 2^k ms, k = 0..7)

The BAG guarantees a minimum spacing between frames on a Virtual Link, so
the maximum frame rate on a Virtual Link is 1/BAG frames per second. This
is the fundamental traffic-shaping (rate-limiting) mechanism: the End System
transmit scheduler ensures that no two frames of the same Virtual Link are
sent closer together than the BAG.

Maximum frame size (Lmax) and minimum frame size (Lmin):
Each Virtual Link also defines a maximum frame size Lmax (and a minimum
frame size Lmin) in bytes. The maximum bandwidth consumed by a Virtual Link
is therefore bounded by Lmax / BAG. The Lmax for a Virtual Link lies within
the AFDX-allowed Ethernet frame size range; the AFDX payload ranges from a
minimum of 17 bytes to a maximum of 1471 bytes (so that the total Ethernet
frame, including headers and FCS, stays within the standard 64..1518 byte
range).

Jitter:
The End System must bound the transmit Jitter on each Virtual Link. Jitter
is the allowed variation in the time at which a frame is presented to the
network relative to the ideal BAG-spaced instant. The maximum allowed
jitter at the End System output is bounded as a function of the Virtual
Links sharing the physical port. The specification bounds the maximum jitter
(typically the allowed jitter must not exceed 500 microseconds, and is
computed from the set of Lmax values and the link rate of the VLs sharing
the port). Bounding jitter keeps the network deterministic even when many
Virtual Links contend for one physical Ethernet port.

Traffic shaping and traffic policing:
  - Traffic shaping is performed at the transmitting End System: the End
    System regulates (shapes) each Virtual Link so it respects its BAG and
    jitter allocation before frames enter the network.
  - Traffic policing is performed at the AFDX Switch: each switch ingress
    port polices every Virtual Link against its configured BAG and Lmax
    using a token-bucket / leaky-bucket algorithm, and drops frames from a
    Virtual Link that exceeds its allocated bandwidth (a babbling or
    misbehaving source). Policing protects the rest of the network from a
    faulty End System.


5. Redundancy — Network A and Network B

AFDX provides fault tolerance through dual redundancy. Two completely
independent networks are deployed: Network A and Network B. Each AFDX End
System is connected to both networks. By default every frame transmitted on
a Virtual Link is sent on BOTH Network A and Network B simultaneously (the
frame is replicated onto the two redundant networks). The two copies travel
over physically separate switches and cabling so that a single network
failure (a cut cable, a failed switch, a failed port) does not lose data.

Redundancy Management (RM) and Integrity Checking (IC):
At the receiving End System, the two redundant copies of each frame must be
reconciled. AFDX uses a 1-byte Sequence Number (SN) carried in each frame
to do this:

  - Sequence Number (SN): a one-octet (8-bit) sequence number is appended to
    the payload of every AFDX frame, immediately before the Ethernet Frame
    Check Sequence. The Sequence Number increments by one for each
    successive frame sent on a given Virtual Link, wrapping from 255 back to
    1 (the value 0 is reserved to indicate a reset / first frame after
    initialization, so the normal range is 1..255).

  - Integrity Checking (IC): on each network (A and B) the receiver checks
    that the Sequence Number of each arriving frame is within an expected
    window relative to the previously accepted Sequence Number for that
    Virtual Link. Frames whose Sequence Number is out of the valid range are
    rejected as integrity errors. Integrity Checking is performed
    independently on Network A and on Network B.

  - Redundancy Management (RM): after Integrity Checking, the Redundancy
    Management function merges the two redundant streams using a
    "first valid frame wins" rule. For a given Virtual Link, the first
    correctly received copy (from either Network A or Network B) of a frame
    with a given Sequence Number is delivered to the application; the
    redundant second copy (the later-arriving duplicate with the same
    Sequence Number) is discarded. This makes the redundancy transparent to
    the application and tolerates the loss of one network.

Redundancy Management can be enabled or disabled per Virtual Link. When
disabled, frames are not de-duplicated and both copies are passed up.


6. End Systems and Switches

End System (ES):
The AFDX End System is the avionics network interface. It implements:
  - The MAC and physical layer (IEEE 802.3 full-duplex, typically
    100BASE-TX, 10/100 Mbit/s).
  - The Virtual Link transmit scheduler: per-VL traffic shaping enforcing
    the BAG and jitter, Sub-VL round-robin multiplexing, and the Virtual
    Link regulator.
  - Sequence Number insertion on transmit.
  - On the receive side: Integrity Checking per network and Redundancy
    Management (first-valid-wins de-duplication).
  - Replication of every transmitted frame onto Network A and Network B.

The avionics application communicates with the End System through
communication ports. AFDX defines two kinds of communication ports built on
UDP/IP:
  - Sampling ports: a sampling port holds a single message; a newly received
    message overwrites the previous one (no queue). The application always
    reads the most recent value. A freshness / validity indication (a "fresh"
    bit and a timeout) tells the application whether the data is current.
  - Queuing ports: a queuing port has a FIFO queue that buffers multiple
    messages; messages are delivered to the application in order without
    overwriting. Used when no message may be lost.

AFDX Switch:
The AFDX Switch is a deterministic store-and-forward switch. It:
  - Forwards frames based on the Virtual Link Identifier using a static
    configuration table (VL ID → set of output ports); no dynamic learning,
    no spanning tree.
  - Polices each Virtual Link (traffic filtering and policing) against its
    configured BAG and Lmax, dropping non-conformant frames.
  - Provides full-duplex point-to-point links to End Systems and other
    switches.
  - Has bounded, deterministic forwarding latency and finite output buffers
    sized so that, given the BAG/Lmax contract of all Virtual Links, no
    frame is dropped due to congestion under the agreed traffic budget.


7. Protocol Stack — UDP/IP over the Virtual Link

AFDX carries IP over the Virtual Link, and UDP over IP. The avionics
application data is encapsulated as:

    Ethernet (AFDX) | IP | UDP | AFDX payload | Sequence Number | FCS

  - IP: standard IPv4 is used. IP fragmentation is supported so that an AFDX
    message larger than the Virtual Link Lmax can be split across several
    Ethernet frames and reassembled at the destination.
  - UDP: User Datagram Protocol provides the source/destination port numbers
    that identify the communication ports (sampling / queuing) within an End
    System. UDP is connectionless and has no retransmission — determinism
    and redundancy, not TCP-style retransmission, provide reliability.
  - The UDP/IP source and destination addresses/ports map to the
    application's communication ports. The combination of the Virtual Link
    (carrying the frame deterministically) and the UDP port (identifying the
    port within the destination End System) routes data from the source
    application to the destination application.


8. AFDX Frame Format

An AFDX frame is a standard IEEE 802.3 Ethernet frame, profiled as follows:

  - Destination MAC address (6 bytes): Constant Field (32 bits,
    0x03:00:00:00) + Virtual Link Identifier (16 bits). This is how the
    Virtual Link is carried on the wire and how switches forward.
  - Source MAC address (6 bytes): identifies the transmitting End System;
    structured as a constant field plus the network/equipment identifier of
    the source End System.
  - EtherType / Length (2 bytes): IP (0x0800).
  - Payload: IP header + UDP header + AFDX application payload. The AFDX
    application payload is 17 to 1471 bytes.
  - Sequence Number (1 byte): the AFDX redundancy Sequence Number, located
    after the payload and before the FCS. Range 1..255 (0 reserved).
  - Frame Check Sequence / FCS (4 bytes): standard Ethernet CRC-32.

Frame size: the complete Ethernet frame respects the standard 64-byte
minimum and 1518-byte maximum (excluding preamble/SFD). Frames shorter than
the 64-byte minimum are padded.


9. Determinism Properties Summary

  - Guaranteed bandwidth per Virtual Link via the BAG (1..128 ms,
    power of two) and bounded Lmax: max bandwidth = Lmax / BAG.
  - Bounded latency: switches are store-and-forward with deterministic,
    bounded forwarding latency; the network is dimensioned offline so that
    worst-case end-to-end latency is bounded for every Virtual Link.
  - Bounded jitter at the End System output (e.g. ≤ 500 µs).
  - No congestion loss under the agreed traffic budget, enforced by transmit
    shaping (End System) and ingress policing (Switch).
  - Fault tolerance via dual networks (A/B), Sequence Number Integrity
    Checking, and first-valid-wins Redundancy Management.

These properties make AFDX a deterministic, redundant, profiled-Ethernet
avionics data network — ARINC 664 Part 7.


10. Configuration

An AFDX network is statically configured offline. The configuration defines,
for every Virtual Link:
  - VL ID (16-bit Virtual Link Identifier).
  - BAG (1, 2, 4, 8, 16, 32, 64, or 128 ms).
  - Lmax and Lmin (maximum / minimum frame size).
  - The number of Sub-VLs (1 to 4).
  - The set of source and destination End Systems (the multicast tree).
  - The switch forwarding-table entries (VL ID → output ports) and the
    per-VL policing parameters at each switch.
  - Whether Redundancy Management is enabled for the Virtual Link.

This static configuration, together with the deterministic mechanisms above,
yields a network whose timing and bandwidth behaviour can be verified
offline for certification.
