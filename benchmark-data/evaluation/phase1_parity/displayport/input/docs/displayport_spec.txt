VESA DisplayPort (DP) Standard
Version 1.4a / 2.0 / 2.1 (consolidated digital-display interface reference)

Video Electronics Standards Association (VESA)
DisplayPort Standard — Embedded and External Digital Display Interface

================================================================================
1. OVERVIEW
================================================================================

DisplayPort (DP) is a VESA digital display interface standard that carries
isochronous video and audio from a Source device (e.g. a GPU) to a Sink device
(e.g. a monitor or panel) over a small number of high-speed differential pairs.
A DisplayPort connection comprises three functional channels:

  * Main Link  — a uni-directional, high-bandwidth, isochronous channel that
                 carries the video stream (and optional audio + secondary data)
                 from Source to Sink. The Main Link is made of 1, 2, or 4 lanes,
                 each a self-clocked AC-coupled differential pair.
  * AUX CH     — a bidirectional, half-duplex, low-bandwidth auxiliary channel
                 used for link management: reading and writing the sink's
                 DisplayPort Configuration Data (DPCD) register space, link
                 training control, EDID retrieval via I2C-over-AUX, MST sideband
                 messaging, and HDCP/content-protection handshakes.
  * HPD        — Hot Plug Detect, a sideband signal driven by the Sink to inform
                 the Source of connection presence and of downstream interrupt
                 events (IRQ_HPD) such as link-status change or CP (content
                 protection) events.

DisplayPort is a packet-based ("micro-packet") interface. The pixel data,
audio, and link/stream attributes are carried as a stream of micro-packets over
the Main Link, scrambled and (for the legacy rates) 8b/10b channel-coded so the
receiver can recover the clock from the embedded transitions. There is no
separate dedicated clock lane on the Main Link — the link clock is embedded in
the data and recovered by the Sink during link training.

DisplayPort replaces legacy interfaces (VGA, DVI, LVDS) and is the basis of the
Embedded DisplayPort (eDP) interface used inside notebooks and all-in-one
systems.

================================================================================
2. MAIN LINK — LANES, RATES, AND CHANNEL CODING
================================================================================

2.1 Lane count
The Main Link is configurable to 1, 2, or 4 lanes. The negotiated lane count is
written to the LANE_COUNT_SET field of the DPCD. A typical external DisplayPort
connector exposes 4 Main Link lanes (ML_Lane0..ML_Lane3), each a differential
pair (ML_Lane0+/ML_Lane0- ... ML_Lane3+/ML_Lane3-).

2.2 Link rates (link symbol rates per lane)
The Main Link operates at one of a set of standardized link rates. Each lane
runs at the selected rate; the selected rate is written to the LINK_BW_SET field
of the DPCD (or, for UHBR, the LINK_RATE_SET indexing the supported-rates list).

  RBR  (Reduced Bit Rate) ........ 1.62 Gbps/lane   (8b/10b)
  HBR  (High Bit Rate) ........... 2.70 Gbps/lane   (8b/10b)
  HBR2 (High Bit Rate 2) ......... 5.40 Gbps/lane   (8b/10b)
  HBR3 (High Bit Rate 3) ......... 8.10 Gbps/lane   (8b/10b)

DisplayPort 2.0/2.1 adds the Ultra High Bit Rate (UHBR) tier, which uses 128b/
132b channel coding (replacing 8b/10b) together with Forward Error Correction:

  UHBR10   .... 10.0 Gbps/lane    (128b/132b)
  UHBR13.5 .... 13.5 Gbps/lane    (128b/132b)
  UHBR20   .... 20.0 Gbps/lane    (128b/132b)

2.3 Channel coding
For RBR/HBR/HBR2/HBR3 the Main Link uses ANSI 8b/10b coding: each 8-bit
character is encoded into a 10-bit symbol that is DC-balanced and transition-
rich so the Sink can recover the embedded link clock. The effective data
efficiency of 8b/10b is 80% (8 useful bits per 10 transmitted bits). The data is
also scrambled with an LFSR (reset by the SR / scrambler-reset symbol) to spread
the spectrum. For UHBR the link uses 128b/132b coding (a 4-byte sync per 128-bit
block) which is ~96.97% efficient and mandates FEC.

2.4 Symbols and control characters
8b/10b control (K) symbols frame the stream: BS (Blanking Start), BE (Blanking
End), SR (Scrambler Reset), SS/SE (Secondary-data Start/End), FS/FE (Fill
Start/End), and the training pattern symbols. The blanking period between active
video lines carries the Main Stream Attributes (MSA) and secondary-data packets.

================================================================================
3. LINK TRAINING
================================================================================

Before video can be transmitted the Source must train the Main Link so that the
Sink reliably recovers the data on every active lane. Link training is performed
over the AUX channel by writing the TRAINING_PATTERN_SET DPCD register and
reading back the LANE0_1_STATUS / LANE2_3_STATUS / LANE_ALIGN_STATUS_UPDATED
registers. Link training proceeds in two phases:

3.1 Clock Recovery (CR) phase
The Source transmits Training Pattern 1 (TPS1) on the Main Link and adjusts each
lane's transmit VOLTAGE SWING level and PRE-EMPHASIS level based on the
ADJUST_REQUEST values the Sink reports in DPCD. The phase succeeds when every
active lane reports CR_DONE (clock recovery locked). DisplayPort defines 4
voltage-swing levels (Level 0..3) and 4 pre-emphasis levels (Level 0..3), with
the constraint that swing+preemphasis combinations are bounded.

3.2 Channel Equalization (EQ) phase
The Source transmits Training Pattern 2/3/4 (TPS2/TPS3 for 8b/10b rates, TPS4
for HBR3; UHBR uses 128b/132b training patterns) and the Sink reports
CHANNEL_EQ_DONE, SYMBOL_LOCKED, and INTERLANE_ALIGN_DONE. When all three are set
on all active lanes, EQ succeeds and the link is trained.

If training fails at the requested rate/lane-count, the Source falls back to a
lower link rate and/or fewer lanes and retries, per the link-training fallback
procedure. The trained configuration (rate, lane count, drive settings) is
written to LANE_COUNT_SET, LINK_BW_SET, and the per-lane
TRAINING_LANE0_SET..TRAINING_LANE3_SET registers.

================================================================================
4. AUX CHANNEL
================================================================================

4.1 Electrical and coding
The AUX channel is a single bidirectional, half-duplex differential pair
(AUX+/AUX-). It is AC-coupled and uses Manchester-II bi-phase encoding at a
nominal 1 Mbps. A request/reply transaction model is used: the Source (AUX
master) issues a request; the Sink (AUX slave) returns a reply. Each transaction
begins with a SYNC pattern (a preamble of consecutive zeros) and a START/STOP
condition delimiting the Manchester-coded payload.

4.2 Native AUX transactions
Native AUX transactions read or write the sink's DPCD address space. The request
carries:
  * a 4-bit command (AUX command): native Read (1001b) / native Write (1000b),
    and I2C-over-AUX Read/Write/MOT variants;
  * a 20-bit address into the DPCD / I2C address space;
  * a length field (number of bytes minus one, 0..15 -> 1..16 bytes per
    transaction).
The reply carries a 4-bit AUX reply command: ACK / NACK / DEFER (and the
I2C-over-AUX equivalents I2C_ACK / I2C_NACK / I2C_DEFER).

4.3 DPCD — DisplayPort Configuration Data
DPCD is the Sink's configuration/status register space, accessed by native AUX
read/write. Key DPCD regions:
  * Receiver Capability field (base address 00000h): DPCD_REV, MAX_LINK_RATE,
    MAX_LANE_COUNT, MAX_DOWNSPREAD, supported training patterns, FEC/DSC caps.
  * Link Configuration field (base address 00100h): LINK_BW_SET, LANE_COUNT_SET,
    TRAINING_PATTERN_SET, TRAINING_LANE0_SET..LANE3_SET, DOWNSPREAD_CTRL.
  * Link/Sink Status field (base address 00200h): SINK_COUNT, LANE0_1_STATUS,
    LANE2_3_STATUS, LANE_ALIGN_STATUS_UPDATED, ADJUST_REQUEST_LANE0_1/2_3.
  * Device Service IRQ Vector, content-protection (HDCP) registers, and the MST
    sideband-message buffers (DOWN_REQ / UP_REP / DOWN_REP / UP_REQ).

4.4 I2C-over-AUX and EDID
The Sink's EDID (Extended Display Identification Data) and other legacy I2C
peripherals (e.g. an HDCP port) are reached by tunneling I2C transactions over
AUX. The Source issues I2C-over-AUX read/write transactions (with the MOT —
Middle-Of-Transaction — bit to chain a multi-byte I2C burst) addressed to the
I2C slave address (EDID is at I2C address A0h/A1h). The 128-byte (or extended)
EDID block describes the Sink's supported timings and capabilities.

================================================================================
5. MAIN STREAM ATTRIBUTES, TRANSFER UNITS, AND THE MICRO-PACKET STREAM
================================================================================

5.1 Main Stream Attributes (MSA)
The MSA is a packet, transmitted once per video frame in the vertical blanking
interval, that describes the video stream to the Sink: Mvid and Nvid (the time-
stamp pair used by asynchronous clocking to regenerate the pixel clock from the
link clock), Htotal/Vtotal, HSP/HSW (sync polarity/width), active width/height,
MISC0/MISC1 (color format, bit depth, dynamic range, colorimetry, YCbCr vs RGB).

5.2 Transfer Units (TU)
The active video data of each scan line is packed into Transfer Units. A TU is a
fixed number of link symbols (typically 32 or 64 symbols per lane); within each
TU only as many symbols as required by the ratio of pixel rate to link rate are
filled with active data, and the remainder is stuffed (Fill). This is the
mechanism by which an arbitrary pixel clock is mapped onto a fixed link rate.

5.3 Micro-packet framing
Active line data is delimited by BS (Blanking Start) and BE (Blanking End)
control symbols. Secondary-data packets (audio sample packets, audio
time-stamps, MSA, VSC SDP / extended InfoFrames) are carried in the blanking
intervals delimited by SS/SE.

================================================================================
6. MULTI-STREAM TRANSPORT (MST)
================================================================================

DisplayPort MST allows a single physical DisplayPort output to carry multiple
independent video streams to multiple Sinks through a daisy-chain or a
DisplayPort branch device (hub). Each stream is assigned a Virtual Channel (VC)
and is allocated a number of time slots in the MST time-slot table (a 64-slot
allocation across the Main Link). Branch devices route streams using a Sideband
MSG channel (the DOWN_REQ / UP_REP / DOWN_REP / UP_REQ message transactions over
AUX) implementing LINK_ADDRESS, ENUM_PATH_RESOURCES, ALLOCATE_PAYLOAD, and
related messages. Single-Stream Transport (SST) is the default single-display
mode; MST is negotiated via the MSTM_CTRL DPCD register.

================================================================================
7. CONTENT PROTECTION, FEC, AND DSC
================================================================================

7.1 HDCP
DisplayPort carries HDCP (High-bandwidth Digital Content Protection) versions
1.3 and 2.2/2.3 for protected content. HDCP authentication and key exchange use
the AUX channel (HDCP registers in the DPCD / I2C-over-AUX HDCP port), and the
cipher encrypts the Main Link stream. CP_IRQ events are signaled via the Device
Service IRQ Vector and IRQ_HPD.

7.2 FEC — Forward Error Correction
Forward Error Correction is a Reed-Solomon-based correction layer that is
REQUIRED whenever Display Stream Compression (DSC) is used over the Main Link
(and mandatory for UHBR). FEC is enabled via the FEC_CONFIGURATION DPCD register
and adds parity symbols to allow the Sink to correct symbol errors that would
otherwise corrupt compressed video.

7.3 DSC — Display Stream Compression
DSC (VESA Display Stream Compression) is a visually-lossless codec that
compresses the video to fit high resolutions/refresh rates within the available
Main Link bandwidth. DSC capability and configuration live in the DPCD; when DSC
is active, FEC must be enabled.

================================================================================
8. PINS / CONNECTOR
================================================================================

A standard DisplayPort connector exposes:
  * ML_Lane0(+/-), ML_Lane1(+/-), ML_Lane2(+/-), ML_Lane3(+/-) — four Main Link
    differential pairs (AC-coupled, self-clocked, embedded clock).
  * AUX_CH(+/-) — one bidirectional half-duplex differential pair (Manchester-II,
    1 Mbps) for DPCD / link-training / I2C-over-AUX / MST-sideband / HDCP.
  * HPD — Hot Plug Detect, a single-ended sideband input to the Source.
  * CONFIG1 / CONFIG2 — connector configuration / cable-orientation pins.
  * DP_PWR (3.3 V), GND — auxiliary power and ground.

================================================================================
9. STATE / LINK-POLICY SUMMARY
================================================================================

The Source link-policy maker drives the Main Link through:
  RESET/POWER_ON  -> HPD asserted by Sink (plug detected)
  CAPABILITY_READ -> read DPCD Receiver Capability (MAX_LINK_RATE/MAX_LANE_COUNT)
  EDID_READ       -> read EDID via I2C-over-AUX
  LINK_TRAINING   -> CR phase (TPS1, swing/pre-emphasis) then EQ phase (TPS2/3/4)
  ACTIVE          -> stream video as micro-packets / Transfer Units; MSA per frame
  IRQ_HPD         -> on a short HPD pulse, re-read status, re-train if needed
  POWER_DOWN      -> SET_POWER DPCD to D3; Main Link idle

The Sink reports link status (CR_DONE, CHANNEL_EQ_DONE, SYMBOL_LOCKED,
INTERLANE_ALIGN_DONE) in DPCD; the Source re-trains on loss of lock.
