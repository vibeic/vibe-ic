InfiniBand Architecture Specification
(InfiniBand Trade Association, IBTA)

Volume 1 — Core Architecture (Release 1.x)
Volume 2 — Physical Specification

Property of the InfiniBand Trade Association (IBTA).
InfiniBand is a switched-fabric I/O interconnect for high-performance
computing (HPC), data-center clustering, and storage.


================================================================
1. Overview
================================================================

InfiniBand (IB) is an open, switched-fabric, channel-based, serial
point-to-point interconnect standardized by the InfiniBand Trade
Association (IBTA). It connects processor nodes and I/O nodes through a
fabric of switches and routers, providing high bandwidth, low latency,
and Remote Direct Memory Access (RDMA). The architecture is organized as
a layered stack: Physical Layer, Link Layer, Network Layer, Transport
Layer, and Upper Layers (the verbs / consumer interface).

End nodes attach to the fabric through Channel Adapters (CAs):
  * Host Channel Adapter (HCA) — the channel adapter in a processor node.
    It implements the verbs interface that the host software (consumer)
    uses to post Work Requests.
  * Target Channel Adapter (TCA) — the channel adapter in an I/O node
    (for example a storage controller). It typically presents a
    device-specific I/O Controller interface rather than verbs.

The fabric itself is built from:
  * Switches — forward packets within a single subnet using the Local
    Identifier (LID) in the Local Route Header (LRH).
  * Routers — forward packets between subnets using the Global
    Identifier (GID) in the Global Route Header (GRH).

A subnet is managed by a Subnet Manager (SM). The Subnet Manager
discovers the topology, assigns each port a 16-bit Local Identifier
(LID), programs the switch forwarding tables, and establishes paths.
Subnet Management Packets (SMPs) carried on the management Virtual Lane
(VL15) are used by the SM and the Subnet Management Agents (SMAs) in
each node.


================================================================
2. Layered Architecture
================================================================

  Upper Layers (Consumer)        — verbs API, ULPs (IPoIB, SRP, iSER, MPI)
  Transport Layer                — Queue Pairs, BTH, end-to-end reliability
  Network Layer                  — GRH (GID), inter-subnet routing
  Link Layer                     — LRH (LID, SL, VL), flow control, CRC
  Physical Layer                 — lanes, 8b/10b or 64b/66b, link training

Each layer adds its own header to the packet. A complete IB data packet
is composed of:
  LRH | (GRH) | BTH | (extended transport headers) | Payload | ICRC | VCRC

  * LRH  = Local Route Header (8 bytes) — always present.
  * GRH  = Global Route Header (40 bytes) — present only for packets that
           cross subnets (routed by GID).
  * BTH  = Base Transport Header (12 bytes) — present for IBA transport.
  * ICRC = Invariant CRC (32-bit) — covers the fields that do not change
           hop to hop.
  * VCRC = Variant CRC (16-bit) — recomputed at every hop.


================================================================
3. Physical Layer
================================================================

InfiniBand is a serial, differential, point-to-point physical link.
Links are built from a number of lanes and run at standardized
signaling rates. The per-lane signaling rates (link speeds) are:

  SDR  Single Data Rate     2.5  Gbps per lane   (8b/10b encoding)
  DDR  Double Data Rate     5    Gbps per lane   (8b/10b encoding)
  QDR  Quad Data Rate       10   Gbps per lane   (8b/10b encoding)
  FDR  Fourteen Data Rate   14   Gbps per lane   (64b/66b encoding)
  EDR  Enhanced Data Rate   25   Gbps per lane   (64b/66b encoding)
  HDR  High Data Rate       50   Gbps per lane   (PAM4, 64b/66b framing)
  NDR  Next Data Rate       100  Gbps per lane   (PAM4)

Link widths aggregate lanes: 1x (one lane), 4x (four lanes), and 12x
(twelve lanes). For example a 4x QDR link runs at 4 x 10 = 40 Gbps
(32 Gbps data after 8b/10b). Line codes are 8b/10b for SDR/DDR/QDR and
64b/66b for FDR and above; HDR/NDR use PAM4 modulation.

The Physical Layer performs link training and brings the link up
through link states (Down, Polling, Configuration, LinkUp). It defines
the electrical signaling, lane de-skew, and the symbol encoding.


================================================================
4. Link Layer
================================================================

The Link Layer moves packets across a single subnet, hop by hop between
ports, and is responsible for addressing within the subnet, packet
framing, Virtual Lanes, flow control, and per-hop error checking.

4.1 Local Route Header (LRH)
The Local Route Header is 8 bytes and is present on every packet. Its
significant fields are:
  * SLID  — Source Local Identifier (16-bit): the LID of the source port.
  * DLID  — Destination Local Identifier (16-bit): the LID of the
            destination port; switches forward on the DLID.
  * SL    — Service Level (4-bit): the class of service requested. The
            SL is mapped to a Virtual Lane by the SL-to-VL mapping table.
  * VL    — Virtual Lane (4-bit): the link-level virtual lane the packet
            travels on.
  * LVer  — Link Version.
  * LNH   — Link Next Header (selects whether a GRH and/or BTH follows).
  * PktLen— Packet Length.

The 16-bit LID gives a subnet up to 48K unicast LIDs plus multicast
LIDs. LIDs are assigned by the Subnet Manager.

4.2 Virtual Lanes (VL)
Each physical link is divided into multiple Virtual Lanes (VLs). A port
supports VL0 through VL14 for data plus VL15, which is reserved
exclusively for subnet-management traffic (SMPs) and is never flow
controlled. An implementation may support 1, 2, 4, 8, or 15 data VLs.
Virtual Lanes provide independent buffering so that traffic of different
service levels does not block one another (deadlock avoidance and
quality of service). The Service Level (SL) in the LRH selects a VL
through the SL-to-VL mapping.

VL arbitration governs how the data VLs share the physical link
bandwidth. Each port has a VL Arbitration Table with a high-priority
table, a low-priority table, and a Limit-of-High-Priority counter so
that weighted round-robin scheduling can be enforced across VLs.

4.3 Credit-Based Flow Control
The Link Layer uses absolute, credit-based flow control on a per-VL
basis. The receiver advertises, in Flow Control Packets, the total
amount of data it is prepared to receive on each VL (an absolute credit
count, the Flow Control Total Blocks Sent / Flow Control Credit Limit).
A transmitter may send on a VL only while it has credits for that VL.
Because the credit value is absolute (cumulative) rather than
incremental, a lost flow-control packet self-corrects on the next
update. VL15 (management) is not flow controlled.

4.4 Link-Layer CRC
Each packet carries a 16-bit Variant CRC (VCRC) that is recomputed at
every hop and covers all fields, and (for transport packets) a 32-bit
Invariant CRC (ICRC) computed by the source and checked by the
destination, covering only the fields that are invariant across the
fabric.


================================================================
5. Network Layer
================================================================

The Network Layer routes packets between subnets. When a packet must
leave its local subnet it carries a Global Route Header (GRH), 40 bytes,
modeled on the IPv6 header. The GRH carries:
  * SGID — Source Global Identifier (128-bit).
  * DGID — Destination Global Identifier (128-bit).
  * Traffic Class, Flow Label, Hop Limit, Next Header.

A Global Identifier (GID) is a 128-bit address formed from a 64-bit
subnet prefix plus a 64-bit Globally Unique Identifier (GUID), in the
same style as an IPv6 address. Routers examine the DGID to forward a
packet from one subnet to the next; within a subnet, switches continue
to forward on the LID in the LRH.


================================================================
6. Transport Layer
================================================================

The Transport Layer delivers messages end to end between Channel
Adapters. The fundamental transport object is the Queue Pair (QP).

6.1 Queue Pairs and Completion Queues
A Queue Pair (QP) is the pairing of a Send Queue and a Receive Queue.
The consumer posts Work Requests (WRs) as Work Queue Elements (WQEs)
onto the Send or Receive Queue through the verbs interface. When the
hardware finishes a WQE it places a Completion Queue Entry (CQE) on the
associated Completion Queue (CQ). Each QP is identified by a 24-bit
Queue Pair Number (QPN). QP0 and QP1 are well known: QP0 carries Subnet
Management traffic and QP1 carries General Management (GSI) traffic.

6.2 Verbs
Verbs are the abstract interface (not an API binding) by which a
consumer interacts with a Host Channel Adapter — creating QPs, CQs,
registering Memory Regions, posting Send/Receive/RDMA Work Requests,
and reaping completions. The verbs define the semantics of the
host-to-HCA interface.

6.3 Service (Transport) Types
InfiniBand defines four transport service types, selected per QP:
  * RC — Reliable Connected: a connection between two QPs with
         hardware-guaranteed, in-order, acknowledged delivery.
  * UC — Unreliable Connected: a connection without acknowledgement.
  * UD — Unreliable Datagram: connectionless; one QP can send to many
         (used by management and multicast); message size limited to one
         MTU.
  * RD — Reliable Datagram: reliable delivery without a dedicated
         connection per peer (uses an End-to-End Context, EEC).

6.4 Operations
The supported operations are SEND / RECEIVE (channel semantics) and the
RDMA operations RDMA WRITE and RDMA READ (memory semantics, where the
remote side is not notified per operation), plus Atomic operations
(Compare-and-Swap, Fetch-and-Add). RDMA lets one node read or write the
memory of a remote node directly, bypassing the remote CPU.

6.5 Base Transport Header (BTH)
The Base Transport Header (12 bytes) is present on IBA transport
packets. Its significant fields are:
  * OpCode — operation code (selects transport type + operation, e.g.
             RC SEND First/Middle/Last, RDMA WRITE, RDMA READ Request).
  * Destination QP — the 24-bit destination Queue Pair Number.
  * PSN — Packet Sequence Number (24-bit): orders packets within a
          message and drives the reliable-delivery acknowledgement /
          retransmission protocol.
  * P_Key — Partition Key: enforces fabric partitioning (membership).
  * Solicited Event, MigReq, Pad Count, Transport Header Version.

For reliable service the receiver returns Acknowledge (ACK) and Negative
Acknowledge (NAK) packets carrying the AETH (ACK Extended Transport
Header); the PSN drives retransmission of lost or rejected packets.


================================================================
7. Management
================================================================

Management is performed with Management Datagrams (MADs), 256-byte
packets sent on the management QPs:
  * Subnet Management — the Subnet Manager (SM) and Subnet Management
    Agents (SMAs) exchange Subnet Management Packets (SMPs) on QP0 over
    VL15 to discover the fabric, assign LIDs, program switch forwarding
    tables, and configure ports.
  * General Services — General Management Packets (GMPs) on QP1 handle
    performance counters, communication management (connection setup),
    device management, and the Subnet Administration (SA) query service.

A Partition (P_Key) defines a group of ports allowed to communicate; a
port can be a full or limited member of a partition.


================================================================
8. MTU and Packet Sizes
================================================================

The data payload Maximum Transmission Unit (MTU) of an IB packet is one
of 256, 512, 1024, 2048, or 4096 bytes. Path MTU is negotiated and a
message larger than the MTU is segmented by the sending HCA into
multiple packets (First / Middle / Last / Only) and reassembled at the
receiver. The PSN sequences the packets of the message.


================================================================
9. Compliance Summary
================================================================

A compliant InfiniBand implementation must:
  * Attach end nodes as Channel Adapters (HCA in a host, TCA in an I/O
    node) and build the fabric from switches and routers.
  * Be managed by a Subnet Manager that assigns 16-bit LIDs and programs
    forwarding tables; carry SMPs on VL15 / QP0.
  * Provide the Local Route Header (LRH) with SLID, DLID, SL, and VL on
    every packet, and the Global Route Header (GRH) with 128-bit GIDs
    for inter-subnet routing.
  * Implement Virtual Lanes (VL0..VL14 data, VL15 management) with an SL
    to VL mapping and VL arbitration, and absolute credit-based flow
    control per VL.
  * Implement the Transport Layer with Queue Pairs (Send + Receive
    Queues), Completion Queues, the verbs interface, the four service
    types (RC / UC / UD / RD), SEND/RECEIVE and RDMA READ/WRITE plus
    Atomics, and the Base Transport Header with a 24-bit Packet Sequence
    Number for reliable delivery.
  * Support a per-lane signaling rate from the SDR/DDR/QDR/FDR/EDR/HDR/
    NDR set, link widths of 1x/4x/12x, the matching 8b/10b or 64b/66b
    line code, and a path MTU from {256, 512, 1024, 2048, 4096} bytes.
  * Protect packets with the 16-bit VCRC (per hop) and 32-bit ICRC
    (end to end).
