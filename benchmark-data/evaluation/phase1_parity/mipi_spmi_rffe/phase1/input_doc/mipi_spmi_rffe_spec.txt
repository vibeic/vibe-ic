--------------------------------------------------------------------------------
ABSTRACT
--------------------------------------------------------------------------------
This document specifies two related MIPI Alliance low-power two-wire control
buses that share a common electrical and framing model: the System Power
Management Interface (SPMI) and the RF Front-End Control Interface (RFFE). Both
buses use a single serial clock line (SCLK) and a single bidirectional serial
data line (SDATA) to carry chip-to-chip control of power-management and RF
front-end components. Both buses frame every transaction with a Sequence Start
Condition (SSC), carry parity-protected command frames, and address devices with
4-bit identifiers. They are deliberately distinct from I2C (which uses SDA/SCL
open-drain lines, 7-bit addressing, and START/STOP conditions) and from SPI
(which uses a 4-wire MOSI/MISO/SCLK/SS arrangement).

SPMI is a multi-master, multi-slave bus for system power management. Up to 4
masters and up to 16 slaves share the bus. Each transaction names a 4-bit
MASTER_ID and a 4-bit SLAVE_ID. SPMI supports bus arbitration between masters
and a slave-initiated Request capability. Its command set covers Register
Read/Write, Extended (Long) Register Read/Write, Register 0 Write (a short, very
efficient write to register address 0), Authenticated commands, Master
Read/Write, Device Descriptor Block (DDB) Master/Slave Read, Transfer Bus
Ownership, and the power-state commands Reset, Sleep, Shutdown, and Wakeup.

RFFE is a single-master, multi-slave bus for RF front-end control. One RFFE bus
master controls up to 15 RFFE slaves such as power amplifiers (PA), low-noise
amplifiers (LNA), antenna/band switches, antenna tuners, and power-management ICs
(PMIC) used in the RF front-end. Each RFFE slave has a 4-bit Unique Slave ID
(USID) and may belong to a 4-bit Group Slave ID (GSID). RFFE's command set covers
Register Write, Register Read, Extended Register Write/Read (Long, with a byte
count), Register 0 Write, Masked Write, Interrupt Read / Identification and
Clearing, Timed/Triggered access through trigger registers (used to schedule RF
state changes precisely, e.g. for power-management triggers), and Mapped Register
Write.

--------------------------------------------------------------------------------
1. COMMON TWO-WIRE PHYSICAL AND FRAMING MODEL (SPMI + RFFE)
--------------------------------------------------------------------------------
1.1 Wires
Both SPMI and RFFE are two-wire buses:
  - SCLK  : serial clock line, driven by the (active) bus master.
  - SDATA : bidirectional serial data line, driven by master or slave during
            their respective phases of a frame.
Both lines are point-to-point/multi-drop CMOS push-pull-capable signaling
(NOT I2C open-drain SDA/SCL, and NOT a 4-wire SPI MOSI/MISO/SS arrangement).
The bus idles with SCLK low and SDATA low.

1.2 Sequence Start Condition (SSC)
Every transaction on both buses begins with a Sequence Start Condition (SSC).
The SSC is a defined pulse pattern on SDATA while SCLK is held low (a single
SDATA pulse that the bus can detect even when otherwise idle), used by all
devices to detect the start of a new command sequence and to synchronize.
The SSC is what frames a transaction; there is NO I2C-style START condition
(SDA falling while SCL high) and NO I2C-style STOP condition.

1.3 Bit order, parity, and frame structure
Data is transmitted MSB-first. Every command frame, address frame, and data
frame is protected by a single odd parity bit appended to the frame. A parity
error causes the receiver to ignore the frame. A generic transaction is:

   SSC -> Command Frame (+ parity) -> [Address Frame (+ parity)] ->
          [Data Frame(s) (+ parity)] -> Bus Park Cycle

The Command Frame carries the slave identifier (SLAVE_ID for SPMI, USID for
RFFE) in its top bits and the command opcode in its lower bits. A Bus Park
Cycle ends the transaction and returns the bus to idle.

1.4 4-bit identifiers
Both buses use 4-bit device identifiers:
  - SPMI : 4-bit MASTER_ID (which master) + 4-bit SLAVE_ID (which slave).
  - RFFE : 4-bit USID (Unique Slave ID) per slave + 4-bit GSID (Group Slave ID)
           for broadcasting to a group of slaves.
4 address bits give up to 16 slave identities; RFFE reserves some encodings and
practically supports up to 15 slaves on a bus.

1.5 Clock rate
SPMI operates at clock rates up to 26 MHz. RFFE operates up to 26 MHz (RFFE
v1.x/v2.x) and up to 52 MHz in RFFE v3.0. The clock is supplied by the master;
there is no embedded/recovered clock and no source-synchronous forwarded-clock
strobe beyond SCLK itself.

--------------------------------------------------------------------------------
2. SPMI - SYSTEM POWER MANAGEMENT INTERFACE
--------------------------------------------------------------------------------
2.1 Roles and topology
SPMI is a multi-master, multi-slave bus. Up to 4 masters and up to 16 slaves can
share one SPMI bus. A device may implement a Master role, a Slave role, or both.
At any time exactly one master owns the bus; ownership can be transferred via the
Transfer Bus Ownership command. Masters arbitrate for the bus using a priority
mechanism keyed on MASTER_ID and command priority. Slaves can asynchronously
signal a need for service using the Request capability (a slave pulls a Request
during the arbitration window so a master will address it).

2.2 SPMI command set
The SPMI command frame encodes one of the following commands. The command frame
contains the 4-bit SLAVE_ID and the opcode; some commands also carry a register
address and/or a byte count.

  - Register Write           : write one data byte to a register (address in the
                               command/address frame).
  - Register Read            : read one data byte from a register.
  - Extended Register Write  : "Long" write of up to 16 data bytes to a register
                               address (8-bit register address + byte count).
  - Extended Register Read   : "Long" read of up to 16 data bytes.
  - Extended Register Write Long  : extends the register address space to 16 bits.
  - Extended Register Read Long   : 16-bit register address read.
  - Register 0 Write         : a very short, efficient write of 7 data bits to
                               register address 0 (single-frame; lowest overhead).
  - Authenticated commands   : commands that carry an authentication payload for
                               protected register access.
  - Master Write             : a master writes to another master's register space.
  - Master Read              : a master reads another master's register space.
  - Device Descriptor Block Master Read : read the DDB of a master.
  - Device Descriptor Block Slave Read  : read the DDB of a slave (capabilities,
                               revision, manufacturer/product identity).
  - Transfer Bus Ownership   : hand bus ownership from one master to another.
  - Reset                    : command a slave (or group) to reset.
  - Sleep                    : command a slave (or group) into a low-power sleep.
  - Shutdown                 : command a slave (or group) to shut down its output.
  - Wakeup                   : wake a slave (or group) from Sleep/Shutdown.

Group Sub-ID and broadcast: SPMI supports addressing groups of slaves so that a
single Sleep/Shutdown/Wakeup can be applied to many slaves at once.

2.3 SPMI arbitration
Multiple masters contend for the bus. Arbitration uses the command priority and
the 4-bit MASTER_ID: a higher-priority command and/or a lower MASTER_ID wins.
The Request capability lets a slave raise its need for service during the
arbitration window. Arbitration is resolved before the SSC of the winning
master's transaction.

2.4 SPMI Device Descriptor Block (DDB)
Each SPMI device exposes a Device Descriptor Block giving its manufacturer ID,
product ID, revision, and the function/capability of the device. The DDB is read
with Device Descriptor Block Master Read / Slave Read commands and is used for
discovery and enumeration.

2.5 SPMI power-state commands
Reset, Sleep, Shutdown, and Wakeup are first-class SPMI commands so that the
power-management controller can place individual slaves or groups of slaves into
defined power states with a single bus transaction. This is the core
"system power management" purpose of SPMI.

--------------------------------------------------------------------------------
3. RFFE - RF FRONT-END CONTROL INTERFACE
--------------------------------------------------------------------------------
3.1 Roles and topology
RFFE is a single-master, multi-slave bus. There is exactly one RFFE master
(usually integrated in the modem/transceiver), which controls up to 15 RFFE
slaves. Typical RFFE slaves are RF front-end components:
  - PA   : power amplifier
  - LNA  : low-noise amplifier
  - switch : antenna / band-select switch
  - tuner  : antenna tuner / aperture tuner
  - PMIC   : power-management IC for the RF front-end
Because there is a single master, RFFE has no multi-master arbitration; the
master fully controls bus timing.

3.2 RFFE identifiers
Each RFFE slave has a 4-bit Unique Slave ID (USID). Slaves may also be assigned a
4-bit Group Slave ID (GSID) so the master can write to a group of slaves at once
(e.g. simultaneously updating several front-end devices). A broadcast USID
addresses all slaves.

3.3 RFFE command set
The RFFE command frame carries the 4-bit USID (or GSID for group writes) and
the command opcode:

  - Register Write            : write one data byte to an 8-bit register address.
  - Register Read             : read one data byte from an 8-bit register address.
  - Extended Register Write   : "Long" write of N data bytes (byte count field)
                                to an 8-bit register address.
  - Extended Register Read    : "Long" read of N data bytes.
  - Extended Register Write Long : 16-bit register address, multi-byte write.
  - Extended Register Read Long  : 16-bit register address, multi-byte read.
  - Register 0 Write          : single-frame write of 7 data bits to register 0
                                (lowest-latency write, e.g. for fast PA control).
  - Masked Write              : write only the bits selected by a mask, leaving
                                the other bits of the register unchanged.
  - Interrupt Read / Interrupt Identification and Clearing : read which slave(s)
                                raised an interrupt and clear the interrupt.
  - Timed / Triggered access  : write a value into a trigger register so the new
                                value is applied at a precisely scheduled time
                                (a Trigger event); used for power-management (PM)
                                triggers and coordinated RF state changes.
  - Mapped Register Write     : write through a register mapping that translates a
                                logical address to a physical register.

3.4 RFFE triggers and timing
RFFE defines trigger registers and a Trigger mechanism so that several slaves can
be pre-loaded with new settings and then change state simultaneously on a single
trigger event. This is essential for fast, glitch-free RF front-end
re-configuration (band switching, PA bias changes) synchronized to the radio
timeline. PM (power-management) triggers coordinate front-end power state with
the modem.

3.5 RFFE interrupts
RFFE slaves can signal interrupts; the master discovers and clears them with the
Interrupt Read / Interrupt Identification and Clearing commands. There is no
dedicated interrupt wire beyond the two-wire bus.

--------------------------------------------------------------------------------
4. COMMON COMMAND-FRAME ENCODING
--------------------------------------------------------------------------------
4.1 Command frame
A command frame is a fixed-width frame (typically a slave-identifier field plus a
command opcode field) sent MSB-first and terminated by an odd parity bit. The top
bits select the slave (SLAVE_ID for SPMI, USID/GSID for RFFE); the remaining bits
select the command (and, for Register 0 Write, carry 7 data bits directly).

4.2 Address frame
For register-addressed commands, an Address Frame carries the register address
(8-bit for standard, 16-bit for the Long variants), MSB-first, with its own odd
parity bit.

4.3 Data frame
Each data byte is its own frame: 8 data bits MSB-first plus one odd parity bit.
Extended (Long) commands carry a byte-count field so the number of data frames is
explicit.

4.4 Bus Park Cycle
A Bus Park Cycle (a defined idle period with SCLK toggling and SDATA released)
terminates each transaction and returns the bus to its idle state, ready for the
next SSC.

--------------------------------------------------------------------------------
5. DISTINCTION FROM I2C AND SPI
--------------------------------------------------------------------------------
5.1 Not I2C
SPMI/RFFE name their wires SCLK and SDATA, NOT SDA/SCL. They frame transactions
with a Sequence Start Condition (SSC) and a Bus Park Cycle, NOT an I2C START
(SDA falling while SCL high) and STOP condition. They use 4-bit device IDs
(MASTER_ID/SLAVE_ID/USID/GSID), NOT 7-bit I2C slave addresses. Every frame is
odd-parity protected, which I2C frames are not.

5.2 Not SPI
SPMI/RFFE are two-wire (SCLK + SDATA), NOT the 4-wire SPI arrangement
(MOSI + MISO + SCLK + SS). There is no MOSI or MISO; the single SDATA line is
bidirectional and turned around within a transaction. There is no SPI chip-select
(SS); slaves are selected by their 4-bit ID inside the command frame.

--------------------------------------------------------------------------------
6. ELECTRICAL AND TIMING (SUMMARY)
--------------------------------------------------------------------------------
- Signaling: CMOS push-pull two-wire (SCLK + SDATA); SDATA bidirectional.
- Idle state: SCLK low, SDATA low.
- Bit rate: SPMI up to 26 MHz; RFFE up to 26 MHz (v1/v2), up to 52 MHz (v3.0).
- Bit order: MSB-first.
- Integrity: per-frame odd parity (command, address, and data frames).
- Framing: Sequence Start Condition (SSC) starts a transaction; a Bus Park Cycle
  ends it.
- Master-supplied clock; no clock recovery; no separate forwarded-clock lane.

--------------------------------------------------------------------------------
7. REGISTER MODEL
--------------------------------------------------------------------------------
Both buses expose a register space inside each slave:
  - Register address: 8-bit (standard) or 16-bit (Extended Long).
  - Register 0: a special low-overhead register; Register 0 Write carries 7 data
    bits in the command frame itself.
  - Data: 8-bit register data bytes.
  - RFFE Masked Write updates only masked bits of a register.
  - RFFE Mapped Register Write goes through an address-mapping function.
  - SPMI Authenticated commands protect access to selected registers.
The Device Descriptor Block (SPMI) and the slave's product/manufacturer ID
registers (RFFE) provide identity and capability discovery.

--------------------------------------------------------------------------------
8. TYPICAL SLAVES AND USE CASES
--------------------------------------------------------------------------------
- SPMI: system PMIC, power-management controller, sub-PMICs, sensors that need
  coordinated Sleep/Shutdown/Wakeup, and any device whose power state the
  platform power controller manages.
- RFFE: PA, LNA, antenna/band switch, antenna tuner, RF PMIC, controlled by the
  modem/transceiver RFFE master with precise triggered timing.
Both buses coexist in a smartphone/modem platform: SPMI handles system power
management; RFFE handles the RF front-end. They share the same two-wire
SCLK/SDATA + SSC + parity + 4-bit-ID design philosophy, which is why they are
specified here as one combined control-bus class.

--------------------------------------------------------------------------------
9. DETAILED FRAME ENCODING
--------------------------------------------------------------------------------
9.1 Sequence Start Condition (SSC) timing
The SSC is generated by the active master. With SCLK held low, the master drives
a single defined pulse on SDATA: SDATA is raised high for one clock-equivalent
period and then lowered, after which SCLK begins toggling. Every device on the
bus monitors SDATA while SCLK is low so that all devices detect the SSC and
arm their frame receivers simultaneously. Because the SSC is detected during the
SCLK-low idle, no separate frame-sync wire is needed. This replaces the I2C
START condition and is the unique framing primitive of the MIPI control buses.

9.2 Command Frame field layout
The Command Frame is sent MSB-first. Conceptually its fields are:
  - Slave identifier field : the 4-bit SLAVE_ID (SPMI) or 4-bit USID/GSID (RFFE)
                             that selects the target device or group.
  - Command/opcode field   : selects the command (Register Read, Register Write,
                             Extended, Register 0 Write, Masked Write, etc.).
  - Embedded data (Register 0 Write only) : 7 data bits carried directly in the
                             command frame for the lowest-overhead write.
  - Parity bit             : one odd parity bit closing the frame.
The exact field widths depend on the bus and command; the structural invariant
is "identifier in the top bits, opcode below, odd parity last".

9.3 Address Frame
Register-addressed commands send an Address Frame after the Command Frame:
  - Standard commands       : an 8-bit register address (0x00 to 0xFF).
  - Extended Register (Long): a 16-bit register address spanning two frames.
Each address frame ends with its own odd parity bit. Register 0 is addressed
implicitly by Register 0 Write and needs no Address Frame.

9.4 Data Frame and byte count
Each data byte is sent as an 8-bit Data Frame, MSB-first, with one odd parity
bit. For the Extended (Long) commands a byte-count field declares how many Data
Frames follow, so a receiver knows exactly when the payload ends. Standard
Extended Register Write/Read transfer up to 16 data bytes; the Long variants
extend the register address to 16 bits and carry multi-byte payloads.

9.5 Bus Park Cycle
After the last frame the master drives a Bus Park Cycle: SCLK completes a final
defined toggle while SDATA is released, signalling end-of-transaction and
returning the bus to its idle state (SCLK low, SDATA low) ready for the next SSC.
The Bus Park guarantees a clean turnaround when SDATA ownership passes between
master and slave (e.g. at the end of a read).

--------------------------------------------------------------------------------
10. SPMI COMMAND DETAIL
--------------------------------------------------------------------------------
10.1 Register and Extended Register access
Register Write and Register Read move a single data byte to/from an 8-bit
register address. Extended Register Write and Extended Register Read carry a byte
count and transfer up to 16 bytes. Extended Register Write Long and Extended
Register Read Long widen the register address to 16 bits for devices with large
register maps.

10.2 Register 0 Write
Register 0 Write is a single-frame command that carries 7 data bits inside the
Command Frame and targets register address 0. It is the most bandwidth-efficient
write on the bus and is used for frequently-updated control bits.

10.3 Master Read / Master Write
Because SPMI is multi-master, a master can read or write another master's
register space using Master Read and Master Write, enabling inter-master
coordination.

10.4 Device Descriptor Block (DDB)
Device Descriptor Block Master Read and Device Descriptor Block Slave Read return
a device's manufacturer ID, product ID, revision, and function/capability fields.
A controller uses the DDB to discover and enumerate the devices present on the
bus before normal operation.

10.5 Transfer Bus Ownership
A master that currently owns the bus can hand ownership to another master with
Transfer Bus Ownership, so the next transaction can begin without a full
arbitration round.

10.6 Power-state commands
Reset, Sleep, Shutdown, and Wakeup are first-class SPMI commands. They can target
a single SLAVE_ID or a group of slaves selected by a Group Sub-ID, so the power
controller can change the power state of many devices with one transaction. This
is the central system-power-management purpose of SPMI.

10.7 Authenticated commands
Authenticated commands carry an authentication payload that a device checks
before granting access to protected registers, providing in-protocol access
control on selected registers.

--------------------------------------------------------------------------------
11. RFFE COMMAND DETAIL
--------------------------------------------------------------------------------
11.1 Register and Extended Register access
RFFE Register Write and Register Read access a single byte at an 8-bit register
address. Extended Register Write and Extended Register Read add a byte count for
multi-byte transfers; the Long variants extend the address to 16 bits.

11.2 Register 0 Write
As on SPMI, RFFE Register 0 Write is a single-frame, 7-data-bit write to register
0 - used for the lowest-latency front-end control updates (for example a fast PA
enable bit).

11.3 Masked Write
Masked Write writes a value together with a mask so that only the mask-selected
bits of the target register change; the unmasked bits keep their previous value.
This lets the master update a few control bits without a read-modify-write.

11.4 Mapped Register Write
Mapped Register Write goes through a register-mapping function that translates a
logical register address to the slave's physical register, simplifying control of
devices with non-contiguous register maps.

11.5 Timed / Triggered access
RFFE defines trigger registers and a Trigger mechanism. The master pre-loads new
values into the trigger registers of one or more slaves, then issues a single
Trigger event; all pre-loaded slaves apply their new values simultaneously. This
allows glitch-free, precisely-timed RF front-end re-configuration (band switching,
PA bias changes) and power-management (PM) triggers aligned to the radio
timeline.

11.6 Interrupt handling
A slave can raise an interrupt to request service. The master discovers which
slave(s) interrupted, and clears the interrupt, using Interrupt Read / Interrupt
Identification and Clearing - all over the same two-wire bus, with no dedicated
interrupt wire.

--------------------------------------------------------------------------------
12. ELECTRICAL AND TIMING DETAIL
--------------------------------------------------------------------------------
12.1 Signaling
SCLK and SDATA are CMOS signals referenced to the interface supply VIO. SCLK is
driven by the active master; SDATA is driven by whichever device owns the data
phase. The bus idles with both lines low. Drivers are capable of push-pull
operation for the high clock rates the buses target.

12.2 Clock rate
SPMI supports clock rates up to 26 MHz. RFFE supports up to 26 MHz in v1.x/v2.x
and up to 52 MHz in v3.0. The clock is always supplied by the master; there is no
clock-data-recovery and no separately-routed forwarded-clock strobe beyond SCLK.

12.3 Bit timing
Data is launched and sampled relative to defined SCLK edges; setup and hold times
are specified against SCLK so that a receiver reliably captures each MSB-first
bit. Each frame is followed by its odd parity bit on the next clock.

12.4 Integrity
The sole in-band integrity mechanism is the per-frame odd parity bit on every
command, address, and data frame. A parity mismatch causes the receiver to ignore
the frame; there is no whole-transaction checksum.

--------------------------------------------------------------------------------
13. GLOSSARY
--------------------------------------------------------------------------------
- SCLK   : serial clock line (master-driven).
- SDATA  : bidirectional serial data line.
- SSC    : Sequence Start Condition - the start-of-transaction pulse.
- SPMI   : System Power Management Interface (multi-master).
- RFFE   : RF Front-End Control Interface (single-master).
- MASTER_ID : 4-bit SPMI master identifier.
- SLAVE_ID  : 4-bit SPMI slave identifier.
- USID   : 4-bit RFFE Unique Slave ID.
- GSID   : 4-bit RFFE Group Slave ID (for group writes).
- DDB    : Device Descriptor Block (SPMI discovery/identity).
- PA / LNA / switch / tuner / PMIC : typical RFFE front-end slaves.
- Bus Park Cycle : end-of-transaction idle that returns the bus to idle.
- Trigger : RFFE event that applies pre-loaded trigger-register values at once.

14. VERSIONING
--------------------------------------------------------------------------------
- SPMI v1.0 -> v2.0: multi-master arbitration, DDB, Authenticated commands, and

- RFFE v1.0 -> v2.0 -> v3.0: added Extended Register Long, Masked Write, Mapped
