## IC Expert DB — relevant design-class knowledge (advisory)
Proven design-craft for similar designs. Apply the algorithm / interface / latency insight; the deterministic gates still decide PASS.

- **[serial-line-encoder-mux]** In a mode-selected line-code encoder, every encoder variant must be computed as its own independently-registered signal every cycle (running state like alternating-invert toggle, running parity, and prev-sample edge detectors keep advancing regardless of which mode is selected) and the mode selector must be a purely combinational mux over those registered outputs — do NOT gate the per-encoder update logic by mode, or stateful encoders lose history when temporarily unselected. Also detect x/z on the serial input with the 4-state case-equality operator (===, not ==) since == against x/z yields x and would never flag an error, and place enable/output-disable gating in the final combinational mux (forcing serial_out=0) rather than freezing the internal state registers.
- **[integer-clock-divider]** Integer clock divider: divided-clock outputs described as 'toggled'/'reset-initialized' are REGISTERS, not a combinational decode of the current count. The CANONICAL odd-divisor 50%-duty divider is the OR of a posedge half-rate LEVEL and a negedge half-rate LEVEL: use one counter cnt1 on posedge and cnt2 on negedge, each counting 0..NUM_DIV-1, and register each level as `clk_div_k <= (cnt_k < NUM_DIV/2)` (a LEVEL that is high for the first floor(NUM_DIV/2) counts, NOT a single toggle-at-a-point — a lone toggle every NUM_DIV counts would divide by 2*NUM_DIV, not NUM_DIV). The reset value of each clk_div_k is DERIVED, not guessed: cnt resets to 0 and 0 < NUM_DIV/2, so the level is 1 at reset — reset clk_div_k to 1'b1 to match its own cnt==0 level. Combine with `clk_div = clk_div1 | clk_div2`. A combinational `assign clk_div=(cnt<LIMIT)` or a toggle-on-limit form shifts the phase and fails a cycle-accurate check even when the average ratio is right.
- **[axi4lite-register-slave]** An AXI4-Lite slave register file must implement each channel as an independent, self-clearing handshake FSM: assert *ready only until the corresponding *valid fires (one-shot, then de-assert), latch the address into a holding register at accept time, and hold bvalid/rvalid asserted until the master's bready/rready acknowledges before dropping it — otherwise responses are lost or the bus double-fires. Decode on the LATCHED address (not the live bus), honor write-strobe semantics (full-strobe = update, partial = ack-without-modify), and always return an error response (SLVERR) for writes to read-only or undefined offsets rather than silently completing OKAY.
- **[axi-stream-datawidth-upsizer]** For an AXI-Stream width upsizer with format/sign-extension, keep the widen logic purely combinational and place exactly ONE register stage on the payload+valid path so m_axis_valid/m_axis_data appear the cycle AFTER s_axis_valid (1-cycle latency); pass s_axis_ready straight through from m_axis_ready combinationally so a slave transfer is accepted only in cycles the downstream can absorb the pipelined result. The subtle trap is bit assembly when format-enabled: the carried/sign bit REPLACES the original MSB and drives the upper fill, so the output is {fill[N], carry_bit, data[MSB-1:0]} — do NOT blindly zero-extend or concatenate the full source word, and gate the type/sign options behind the enable so disabled mode is a plain zero-extend.
- **[axi-stream image-frame processor]** When an AXI-Stream stage changes pixel cardinality (resize drops pixels, border adds a 1-pixel ring so the frame grows to (W+2)x(H+2)), do NOT try to pass-through the stream combinationally — decouple input and output with a full-frame buffer RAM and two separate FSM phases: a RECEIVE phase that asserts s_axis_tready only while filling (tready = resetn & receiving) and writes on tvalid&&tready, then an EMIT phase that advances output x/y counters ONLY on (m_axis_tvalid && m_axis_tready) and reads the buffer with an explicit computed index (downsample: src=(i/NX)*SY*W_IN+(i%NX)*SX; border: inner=(oy-1)*W+(ox-1), forcing BORDER_COLOR when ox/oy hit the 0 or W+1/H+1 edges). This store-and-forward decoupling is what keeps rate mismatch, backpressure stalls, and tlast/tuser (end-of-row / start-of-frame) alignment correct — a naive streaming author gets index off-by-one and stalls wrong because in/out counts differ.
