# Vibe-IC — Open-Source EDA Fork & Enhance Roadmap

## 1. Executive Summary

This roadmap consolidates **51 distinct, evidence-backed tool limitations** discovered while driving real ICs (sha256, subservient, spm, Ibex, OpenTitan-AES, Caravel) and benchmarks (RTLLM, CVDP, VerilogEval) through the full open-source Vibe-IC flow. Each is a place where a commercial tool (Innovus/ICC2, Design Compiler/Genus, Calibre, Formality/Conformal, VCS/Xcelium, Spectre/HSPICE) does something the OSS stack cannot, and the plugin currently papers over it with a workaround.

### Counts by tool

| Tool | Role | Distinct limitations |
|---|---|---|
| OpenROAD | place / route / CTS / resize / STA / PDN / antenna / IR-drop | 9 |
| yosys + abc | synthesis / tech-mapping / optimization | 10 |
| klayout + magic | DRC / layout-edit / GDS streamout / extraction | 10 |
| netgen | LVS | 7 |
| iverilog + Verilator | RTL simulation | 7 |
| ngspice + xschem | analog / mixed-signal SPICE | 8 |
| **Total** | | **51** |

### Counts by feasibility class

| Feasibility | Count | Meaning |
|---|---|---|
| `bug-fix-easy` | 14 | Localized crash-guard / severity-reclassification / packaging fix |
| `feature-add-medium` | 22 | New pass or path in a known subsystem |
| `algorithm-hard` | 12 | Requires porting published algorithm work |
| `fundamental-or-external` | 3 | Not a fork target (PDK models, foundry decks) |

### Single highest-leverage fork

**Fix the OpenROAD resizer (RSZ) Signal-11 segfault on post-detailed-route, SPEF-annotated designs, and enable a guarded post-route `repair_design`/`repair_timing` + incremental-reroute ECO loop.** This is the *only* gap that blocks timing signoff on sha256 (−62 ns) and subservient (−98 ns): long detailed-route wires driven by weak cells (e.g. sha256 net `_03068_` off a `sky130_fd_sc_hd__o311ai_0` at 24.7 ns slew, SS corner) only materialize post-route, pre-route RC estimates them as short and skips them, and the segfault forces the plugin's post-route stage to be **measure-only** (`_post_route_spef_repair_tcl` extracts SPEF but issues no repair). Commercial resizers do this routinely. Everything else raises quality or unblocks a single benchmark class; this one converts two ICs from FAIL to timing-clean.

## 3. Prioritized Fork Roadmap

Ranked by (silicon/benchmark-closure value ÷ effort). P0 is fixed by directive; the rest follow leverage.

### P0 — OpenROAD post-route RSZ segfault + post-route slew-repair ECO loop
- **Fork:** OpenROAD `src/rsz` (Resizer) + `src/grt`/`src/drt`.
- **Concrete change:** Root-cause the null-deref in the UnbufferMove/BufferMove/CloneMove/SplitLoadMove RC-lookup family that dereferences post-route SPEF parasitics on a detailed-routed ODB (Signal 11). Add null/guard checking, enable a guarded post-route `repair_design`/`repair_timing -setup`, then a bounded incremental detailed-route ECO (fix RSZ-0074 so new buffers invalidate only affected nets' guides instead of aborting). Rewire `phase3_one_shot_runner._post_route_spef_repair_tcl` from measure-only to actually repair. The complementary `buffer_ports` before `repair_design` for high-fanout primary ports (reset_n) is already implemented and proven this session (7893→0 DRV violators standalone).
- **Payoff:** Directly unblocks **sha256 (−62 ns)** and **subservient (−98 ns)** timing signoff — long post-route wires driven by weak cells (e.g. sha256 `_03068_` off `o311ai_0`, 24.7 ns slew SS) are only visible post-route and currently unrepairable. Also re-enables ECO pass-2 across all ICs.
- **Risk:** Highest technical risk (algorithm-hard); a robust post-route repair may need incremental-reroute convergence that the OSS router does not do idempotently. Mitigate by staging: (a) crash-guard the repair-move family first (turns the crash into a diagnosable no-op), (b) enable buffering-only repair with rip-up of just the repaired nets, (c) full incremental ECO last.

### P1 — yosys transparent-latch + tri-state mapping (netlist correctness at the synth→PnR boundary)
- **Fork:** abc Liberty reader (`sclLiberty.c`) + mapper; yosys `abc.cc` integration.
- **Concrete change:** Recognize `latch()` Liberty groups and synthesize a `$_DLATCH_*_`→cell mapping from the enable expression (or a native `latchmap` pass); preserve tri-state driver fanin so `$_TBUF_` isn't dropped, making `tribuf -logic` implicit in `synth`.
- **Payoff:** Removes two whole classes of "generic latch/tri-state survives → OpenROAD STA-0164 reject" — unblocks cv32e40p-class clock-gate latch designs and any inout-port IP without the plugin's hand-written techmap glue. High reuse across every clock-gated CPU-class IC.
- **Risk:** Latch mapping is algorithm-hard (transparency modeling); a wrong enable-sense mapping is a functional bug — must gate on the plugin's existing re-techmap defence-in-depth + equiv check.

### P2 — KLayout streamout hardening: merge-abutting + manufacturing-grid snap + foundry layer-map
- **Fork:** KLayout `src db` LEFDEFReader + GDS writer.
- **Concrete change:** (a) union same-layer polygons touching across instance boundaries at stream-out (`merge-abutting` option); (b) honor tech-LEF MANUFACTURINGGRID, snapping instance-placement displacements + generated via/enclosure coords; (c) auto-discover/apply the PDK foundry LEF/DEF layer-map instead of compact 10..14 fallback.
- **Payoff:** Eliminates the two largest false-DRC populations measured on real silicon — Ibex m1.2 boundary FPs (~3,019/26%) and the 46,614/76% OFFGRID wall — plus fixes the LVS-breaking compact-layer GDS. Makes KLayout streamout DRC-equivalent to Magic/Calibre without the plugin's flatten+merge+grid-snap shims. Very high value ÷ medium effort (three localized importer/writer changes).
- **Risk:** Low correctness risk (geometry-preserving); merge must be per-layer and hierarchy-aware to avoid runtime blowup on CPU-class GDS.

### P3 — netgen + Magic power/port fidelity for LVS signoff
- **Fork:** Magic extract/ext2spice + netgen `lvs.c`.
- **Concrete change:** In Magic, propagate SPECIALNET power names onto extracted substrate/well/stripe nodes (no VSUBS/leaf-port collapse) and make `port makeall` the default for the top cell; recognize DEF NDR vias so CTS segments aren't dropped. In netgen, make the `Final result:` line reflect property errors, refuse a portless "match", and add connectivity-based (not name-only) global correspondence.
- **Payoff:** Converts spm (36 disconnected boundary nets) and sha256/subservient power-LVS residuals from "disclosed interop artifact" to a genuine net-level MATCH; kills the silent false-PASS class (portless vacuous match, property-error-hidden verdict) that is more dangerous than a fail.
- **Risk:** Connectivity-based global matching is algorithm-hard; the verdict/port fixes are bug-fix-easy and should ship first as safety improvements independent of the harder matcher.

### P4 — OpenROAD easy crash-guards (RSZ-0089, DPL-0033, repair_design re-run) + DRT-0305 tie tolerance
- **Fork:** OpenROAD `src/rsz`, `src/dpl`, `src/drt`.
- **Concrete change:** RSZ-0089 → estimate per-layer RC from tech-LEF and warn instead of abort; DPL-0033 → accumulate/report placement violations non-fatally; guard `repair_design` against already-buffered topology; DRT-0305 → warn-and-auto-tie an unmapped constant PG net instead of aborting all routing.
- **Payoff:** Removes four flow-killing aborts that the plugin currently `catch`-wraps or pre-empts with forced recipes — makes the OSS PnR flow robust on custom/non-sky130 PDKs and eliminates several compliance-gate crutches.
- **Risk:** Low; these are severity-reclassifications and guards, each with a clear regression fixture.

### P5 — iverilog SV-testbench coverage (array-pattern, break/continue, package ordering, elab/codegen parity)
- **Fork:** iverilog `elaborate.cc`/`elab_expr.cc` + vvp emit; Verilator `V3Width`.
- **Concrete change:** Implement full-array assignment-pattern codegen; lower break/continue to jump targets; comp-unit-wide two-pass package resolution; reconcile `-t null` with vvp codegen; downgrade Verilator BLKLOOPINIT-class %Errors to suppressible warnings.
- **Payoff:** Retires the "VCS→iverilog substitution FLOOR-D" class in RTLLM/CVDP (`ring_counter`, `asyn_fifo`, package-ordered TBs) — benchmark-score lift with no silicon dependency.
- **Risk:** Low-to-medium; event-driven timing parity (the algorithm-hard part) is deferred — these are the tractable frontend/codegen fixes.

### P6 — ngspice batch-honesty + native Monte-Carlo + PATH packaging
- **Fork:** ngspice `outitf.c`/`control.c`/`com_let`; iic-osic-tools image.
- **Concrete change:** Propagate non-zero exit on any sub-analysis error + machine-readable per-.measure status; expand `.param` in control-mode analysis args; treat scalar `$&` as length-1 vector; add a native `.mc` card; put ngspice on the container PATH.
- **Payoff:** Removes the analog corner-sweep log-scraping heuristics and the "decorative A4 gate", making analog results trustworthy without N-times external wrapping.
- **Risk:** Low for the batch/PATH/param fixes; native MC is feature-add-medium and can follow.

## 4. Honest Boundary — Forkable vs Truly External

### Genuinely FORKABLE (a fork closes these — 48 of 51)
All `bug-fix-easy` (14), `feature-add-medium` (22), and `algorithm-hard` (12) findings are real OSS tool bugs or missing features we can add:
- **Crash-guards / severity reclassification (14):** RSZ-0089, DPL-0033, repair_design re-run, yosys-slang duplicate-module, KLayout OFFGRID, Magic power-collapse/NDR-via/vacuous-GDS, netgen vacuous-match/property-verdict, iverilog elab-codegen, Verilator lint severity, ngspice `$&`-scalar + PATH. These are the highest value ÷ effort and carry low correctness risk.
- **New passes/paths (22):** merge-abutting streamout, foundry layer-map, `ext2spice` port promotion, metal-density fill, GDS antenna deck, netgen `-auto-global`/black-box mode, iverilog array-pattern/break/package, ngspice batch-honesty/param-expand/native-MC, yosys tri-state/readmemh/unpacked-ports.
- **Algorithm ports (12):** post-route RSZ ECO (P0), transient PDNSim, DRT-0302 multi-bterm merge, abc latch/prefix-adder mapping, yosys `equiv` SEC closure, netgen connectivity-based matching, iverilog/Verilator event-region scheduling, ngspice DC homotopy, AMS co-sim bridge. Real engineering, but published techniques exist and the subsystem is identified.

### Truly EXTERNAL (a fork CANNOT solve these — 3 of 51, do not over-promise)
- **No public ngspice device models for the real tapeout node** (`analog_real_corner_sweep:160-166`) — a PDK-availability gap. No ngspice fork produces foundry-characterized `.scs/.lib` corners; the honest ceiling is the sky130/gf180 substitute + a disclosure header.
- **Signoff-grade PEX / foundry-qualified rule decks** (`spef_extraction_check:45-49`, and the same root behind detailed-router "no rule files" and Magic "no `.tech`") — the *engine* is forkable (derive R/C from LEF, wire OpenRCX), but StarRC/QRC-grade accuracy is tied to encrypted foundry ITF/nxtgrd data a fork cannot ship.
- **Full SV-2017 elaboration as a native yosys frontend** (`phase3:2181-2188`) — classed `fundamental-or-external` not because it's unsolvable but because the honest path is *adopting the external slang project* (yosys-slang) as the default frontend and upstreaming it, not re-implementing an SV-2017 elaborator inside `read_verilog`. This one is external-by-integration, and correctly subsumes the cross-file-import and StateEnumT findings.

**Bottom line:** 48/51 gaps are inside our reach as a fork; the 3 external ones bottom out at licensed foundry data (PDK models, encrypted RC decks) and golden GDS — none of which a tool fork can manufacture. The roadmap above commits only to the 48.
