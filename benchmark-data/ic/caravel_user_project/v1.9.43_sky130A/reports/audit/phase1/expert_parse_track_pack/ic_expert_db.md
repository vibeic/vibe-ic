## IC Expert DB — relevant design-class knowledge (advisory)
Proven design-craft for similar designs. Apply the algorithm / interface / latency insight; the deterministic gates still decide PASS.

- **[priority-interrupt-controller]** In a request/ack interrupt (or arbiter) controller, the bit cleared on ack must be the selection the CPU actually SAMPLED, not the current combinational winner. Because the CPU reads interrupt_idx just after a clock edge (the pre-edge value), you must register the selected index/eligibility (idx_clear_q/elig_clear_q) one cycle and clear THAT indexed pending bit — clearing the live sel_idx races the arbiter and can drop the wrong source. Sequence the pending update as: clear-acked-bit FIRST, THEN OR-in the freshly synchronized new requests, so a same-cycle re-request is never lost; combine this with a registered request synchronizer plus a one-cycle rise delay and post-ack recovery cycle to give the deterministic >=2-cycle request-to-interrupt latency such handshakes need.
- **[cdc-mux-synchronizer]** When a control/handshake signal crosses into a SLOWER clock domain through a 2-flop synchronizer, it must be driven as a LEVEL held until acknowledged — never a single-cycle pulse. A one-cycle pulse in the source domain can fall entirely between two active edges of the slower capture clock and be missed. Correct pattern: set the level when the event fires, hold it, and clear it only after the far-domain response (re-synchronized request/ack) confirms the transfer, forming a full four-phase handshake robust to any clock-frequency ratio.
- **[mmio-register-controlled-counter]** For a threshold/overflow flag on a synchronous counter, compare the NEXT value (COUNTER + 1), not the current COUNTER, against the limit inside the same clocked block — a nonblocking COUNTER<=COUNTER+1 has not yet updated, so testing the old value latches overflow one cycle late (off-by-one). Also, in a single-phase MMIO decode the write address/data and the counter increment are evaluated in the same always block using the current registered enable, and read data (HRDATA) must be purely combinational off the address so the bus master samples the live register value with no wait state.
- **[priority-interrupt-controller]** A priority interrupt controller must arbitrate over the *effective* pending set (pending AND mask) with a fully-initialized best-priority accumulator (best_pri=all-ones, lowest value wins, ties to lowest index) so masking and priority both bind; and it must clear on ack the interrupt that was actually *presented* to the CPU (a registered serviced index), not the currently-arbitrated one, so a higher-priority request arriving on the ack edge cannot cause the wrong bit to be cleared. Synchronize async requests through a flop before OR-ing into the pending register, and derive cpu_interrupt from a registered "effective-pending exists" flag gated off during ack (and one cycle after) to produce clean idle→pending edges and a gap between back-to-back services.
- **[glitch-free-clock-mux]** A glitch-free clock mux must NOT combinationally decode `sel` onto the output. Instead cross-couple two per-clock enable registers so each clock's enable depends on the OTHER clock's enable being deasserted (clk1_en <= f(sel) & ~clk2_en, clk2_en <= f(sel) & ~clk1_en). This break-before-make handshake guarantees the two enables are never high at once, and each enable is retimed into its own clock domain so the AND-gate mask (clk & clk_en) only ever toggles while its clock is at the safe (idle) level — preventing runt/glitch pulses on clkout during the switch. Also route the async reset to force clkout low, and honor the spec's chosen sampling edge (posedge here vs the textbook negedge second stage) since the checker samples at exact edges.
