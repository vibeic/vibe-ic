## IC Expert DB — relevant design-class knowledge (advisory)
Proven design-craft for similar designs. Apply the algorithm / interface / latency insight; the deterministic gates still decide PASS.

- **[integer-clock-divider]** For memory-mapped / AXI-Lite register reads, make the read-data mux COMBINATIONAL (zero-latency, keyed on the address) so a read reflects the live register value in the same cycle it is addressed. A registered/pipelined axi_rdata adds one cycle of latency and returns STALE data, failing read-after-write and live-counter read-back checks. Verified: replacing the draft's `always@(posedge clk)` read block with a combinational `always@(*)` mux makes the case PASS.
- **[priority-interrupt-controller]** In a request/ack interrupt (or arbiter) controller, the bit cleared on ack must be the selection the CPU actually SAMPLED, not the current combinational winner. Because the CPU reads interrupt_idx just after a clock edge (the pre-edge value), you must register the selected index/eligibility (idx_clear_q/elig_clear_q) one cycle and clear THAT indexed pending bit — clearing the live sel_idx races the arbiter and can drop the wrong source. Sequence the pending update as: clear-acked-bit FIRST, THEN OR-in the freshly synchronized new requests, so a same-cycle re-request is never lost; combine this with a registered request synchronizer plus a one-cycle rise delay and post-ack recovery cycle to give the deterministic >=2-cycle request-to-interrupt latency such handshakes need.
- **[spi-serializer-fsm]** In a serial-shift-out FSM, enforce a strict priority ladder inside the clocked block — clear (return-to-idle) OVER fault (enter-error) OVER the normal state case — so override controls beat any per-state transition regardless of current state. Make single-cycle status pulses (o_done) self-clearing by assigning a default 0 at the top of the else-branch and setting 1 only on the completing transition, never a combinational level. And keep the shift register and bit-counter updated in the SAME cycle you drive the data bit (decrement/shift as you emit MSB), so the external clock-toggle state latches data that is already stable rather than sampling a value that lags by one cycle.
- **[integer-clock-divider]** Integer clock divider: divided-clock outputs described as 'toggled'/'reset-initialized' are REGISTERS, not a combinational decode of the current count. The CANONICAL odd-divisor 50%-duty divider is the OR of a posedge half-rate LEVEL and a negedge half-rate LEVEL: use one counter cnt1 on posedge and cnt2 on negedge, each counting 0..NUM_DIV-1, and register each level as `clk_div_k <= (cnt_k < NUM_DIV/2)` (a LEVEL that is high for the first floor(NUM_DIV/2) counts, NOT a single toggle-at-a-point — a lone toggle every NUM_DIV counts would divide by 2*NUM_DIV, not NUM_DIV). The reset value of each clk_div_k is DERIVED, not guessed: cnt resets to 0 and 0 < NUM_DIV/2, so the level is 1 at reset — reset clk_div_k to 1'b1 to match its own cnt==0 level. Combine with `clk_div = clk_div1 | clk_div2`. A combinational `assign clk_div=(cnt<LIMIT)` or a toggle-on-limit form shifts the phase and fails a cycle-accurate check even when the average ratio is right.
- **[serial-line-encoder-mux]** In a mode-selected line-code encoder, every encoder variant must be computed as its own independently-registered signal every cycle (running state like alternating-invert toggle, running parity, and prev-sample edge detectors keep advancing regardless of which mode is selected) and the mode selector must be a purely combinational mux over those registered outputs — do NOT gate the per-encoder update logic by mode, or stateful encoders lose history when temporarily unselected. Also detect x/z on the serial input with the 4-state case-equality operator (===, not ==) since == against x/z yields x and would never flag an error, and place enable/output-disable gating in the final combinational mux (forcing serial_out=0) rather than freezing the internal state registers.
