## IC Expert DB — relevant design-class knowledge (advisory)
Proven design-craft for similar designs. Apply the algorithm / interface / latency insight; the deterministic gates still decide PASS.

- **[integer-clock-divider]** For memory-mapped / AXI-Lite register reads, make the read-data mux COMBINATIONAL (zero-latency, keyed on the address) so a read reflects the live register value in the same cycle it is addressed. A registered/pipelined axi_rdata adds one cycle of latency and returns STALE data, failing read-after-write and live-counter read-back checks. Verified: replacing the draft's `always@(posedge clk)` read block with a combinational `always@(*)` mux makes the case PASS.
- **[axi-stream image-frame processor]** When an AXI-Stream stage changes pixel cardinality (resize drops pixels, border adds a 1-pixel ring so the frame grows to (W+2)x(H+2)), do NOT try to pass-through the stream combinationally — decouple input and output with a full-frame buffer RAM and two separate FSM phases: a RECEIVE phase that asserts s_axis_tready only while filling (tready = resetn & receiving) and writes on tvalid&&tready, then an EMIT phase that advances output x/y counters ONLY on (m_axis_tvalid && m_axis_tready) and reads the buffer with an explicit computed index (downsample: src=(i/NX)*SY*W_IN+(i%NX)*SX; border: inner=(oy-1)*W+(ox-1), forcing BORDER_COLOR when ox/oy hit the 0 or W+1/H+1 edges). This store-and-forward decoupling is what keeps rate mismatch, backpressure stalls, and tlast/tuser (end-of-row / start-of-frame) alignment correct — a naive streaming author gets index off-by-one and stalls wrong because in/out counts differ.
- **[apb-csr-shift-register]** When a spec says a register "updates on the rising edge of <signal>", model that signal as an actual clock (`always @(posedge signal or negedge presetn)`) rather than sampling it in the main clock domain — the checker drives that signal as a clock edge, so a synchronizer/edge-detector approach would miss updates. Correspondingly, implement glitch-free clock gating by latching the enable on the OPPOSITE (negedge) clock edge before ANDing with the clock (`gated_clk = pclk & enable_latched_on_negedge`), and give misprediction-restore strict priority over the normal LSB shift-in. For the APB CSR wrapper: register-map reads must zero-extend reserved bits, read-only registers must silently ignore writes, and pslverr must assert only on invalid addresses during a qualified (pselx && penable) access with zero wait states (pready held high).
- **[serial-link-serdes]** In a source-synchronous serializer/deserializer, transmit a gated data-valid strobe alongside the serial line (serial_clk active ONLY while a real bit is on the wire) and have the RX shift/capture bits only when that strobe is high — this keeps both ends in one clock domain and avoids gated-clock sampling races. Critically, because the last serial bit is written into the RX register on a clock edge, its value is not visible until the NEXT cycle: assert 'done' and latch the assembled parallel word one cycle AFTER the final bit is captured (pipeline a last_bit flag), or a checker sampling data_out coincident with the last-bit strobe reads a stale/incomplete word. Also size bit counters to the max width (here 7 bits for up to 64) but index the storage array with only the needed low bits.
- **[axi4lite-register-slave]** An AXI4-Lite slave register file must implement each channel as an independent, self-clearing handshake FSM: assert *ready only until the corresponding *valid fires (one-shot, then de-assert), latch the address into a holding register at accept time, and hold bvalid/rvalid asserted until the master's bready/rready acknowledges before dropping it — otherwise responses are lost or the bus double-fires. Decode on the LATCHED address (not the live bus), honor write-strobe semantics (full-strobe = update, partial = ack-without-modify), and always return an error response (SLVERR) for writes to read-only or undefined offsets rather than silently completing OKAY.
