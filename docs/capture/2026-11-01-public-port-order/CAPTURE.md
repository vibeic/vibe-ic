Two neutral requests were exercised through the real product emit chain and
direct registry entry. The counter producer emitted `clk,reset,enable,q` for a
declared `clk,enable,reset,q` interface. The gate producer grouped inputs before
outputs despite a declared interleaved interface.

positional consumers failed: counter named=1/positional=0 and gate named=10/
positional=zx. Moving only the generated declaration clauses restored both
consumers. Before any product edit, four permanent registry/chain consumer
tests reproduced those failures; `control_substance_check` credited 4/4 as
observed values, not missing APIs.

## Bounded implementation

No supplied RTL header leaves the generated bytes unchanged. Complete bodies,
multiple/unbounded headers, reference modules and headers naming another target
also preserve existing producer behavior; their ordinary source gates remain
responsible for admission. The normalizer applies only to a unique matching
HEADER_ONLY. Its port declarations must be unambiguous, nonempty and unique,
with a matching generated port set. When order differs, each generated clause must
independently declare its direction so moving it cannot change inherited
direction/type/width. Unsupported or ambiguous cases use the existing
`(None,None)` registry decline contract and normal fallback; this adds no gate.

The splice changes only the generated port-list contents. Parameters and body
remain byte-identical, and supported comments move with their generated clause.
The result is reparsed to verify its port order and supported discovery. The
supplied header is never copied over generated declarations. Width, direction,
type and signedness defects stay visible and the existing exact-header
validator still refuses them. The validator's syntax expectations are unchanged.
