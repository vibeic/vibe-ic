    origin/main                RED
        PAD_ROTATION_HORIZONTAL: ours drives [N, S], upstream defines it for [E, W]

READ THE SECOND LINE OF THE SECOND BLOCK. The fix did not route the variable to
the sides it belongs to. It pinned the west and east orientation to a measured
constant, which REMOVES the variable's effect altogether -- and it did that
because it had concluded the variable was inert, which it is not: it is
misrouted by us, and it drives the north and south sides in the tool.

So after the fix:
  * the horizontal-named variable still drives the wrong two sides, unguarded;
  * the vertical-named variable drives nothing at all, and a run that declares
    it is refused rc 2 -- a refusal of a declaration the tool would have
    honoured;
  * and the sides it should have driven, north and south, are driven by the
    other variable.

This is not a criticism of the work that found the site-view defect, which is
real and which this capture confirms. It is what happens when a fix is built on
a premise that was never checked against the contract it re-implements: every
line of it is careful, and the thing it is careful ABOUT is wrong.
