## 2026-08-05 — vibeic-eda:0.2.64 → 0.2.67

The 05:30 round did not complete on 2026-07-31 or 2026-08-05, and both failures
rendered as the same one-line log entry. Four separate defects; the round now
runs to completion. Everything below was measured, not inferred.

**Fleet state at the end of the day: `sync 0 · release 0` across all 36 forks,
and 0 commits of ours past any pin.**

### Merged upstream

- **MERGED** yosys `600df9049 → 2ae1ec0ce` — 11 upstream commits on the SAT/eqbits
  path (ezsat budget API, eqbits `drop_all`, constbit gather, `SatEffortBudget`,
  modwalker-once). The fork was **diverged**, not merely behind: `merge_base` was
  `7a2bd64c93`, not the upstream tip. We carry 61 patches on yosys, so every path
  the merge touched was classified by blob against merge-base / ours / theirs /
  merged — all 8 are THEIRS-TAKEN on files we have never touched, none is
  OURS-KEPT-then-reverted, none is BLENDED. Cross-checked from the other side:
  our 61 commits touch `kernel/register.cc`, `passes/opt/CMakeLists.txt` and
  `passes/opt/operand_isolate.cc` — zero overlap with the six files upstream
  changed.
- **MERGED** OpenROAD-flow-scripts `ab244fc3d → f4b9d7dbe` — 8 upstream commits.
  A pure mirror (`upstream/master..origin/master` is empty), so this was a
  fast-forward rather than a merge.

### Our own work that had landed on a fork but reached no image

- OpenROAD `f396ce8ee` — the DRC `verifyRoute` gate. Landed, reviewed, and the
  pin sat one commit behind it, so **no image would ever have contained it**.
  TritonRoute's in-loop "0 violations" is a convergence residual, not a DRC
  verdict; the whole-die GC re-run now ships. Measured cost 1.1–8.7%.
- OpenROAD `3118725b4b` — **27 of our own tests were registered in CMakeLists
  only and invisible to the bazel build that produces the shipped binary**
  (dpl 3, drt 2, fin 8, grt 1, ppl 1, psm 10, rsz 1, tap 1, out of 1400 checked).
  Now wired, and `etc/check_test_registration_parity.py` finally has a runner —
  it existed and could go red, and nothing invoked it.
- OpenROAD `b64a496b9` — `drt:top_level_term2`'s goldens regenerated. They had
  been permanently red because **our** min-area repair changed the routed DEF of
  a test **upstream owns**. Generated by the repo's own `save_defok`/`save_ok`
  against the stock shipped binary, then re-confirmed against the bazel binary
  inside the published 0.2.65: "No differences found", rc=0.
- pyuvm `b3a4d47` — the missing user-front-door gate, plus a correction to the
  commit that added it: its stated premise ("`uvm_reg` rejects bit-overlapping
  fields") is false — `_add_field` logs an error and keeps both fields.
  Exhaustive enumeration of all 278,784 (field, sibling) pairs in a 32-bit
  register: 0 of 92,752 well-formed pairs reach the deleted loop, but 3,920 of
  186,032 malformed pairs do. The deletion stands as a garbage-in decision, but
  it is a decision, and now reads as one.

### Why the round could not complete — four defects, each proved able to go red

1. **Six pinned tool tags existed only in the local image store.** A registry
   compose died on `eda-tool-iverilog:26933e0-5b8871: not found`; a local compose
   worked. All six were verified against `/vibeic/provenance/<tool>.json` read
   out of the image and pushed. `tools/install-hooks.sh` had never been run in
   this clone, so **no pre-push gate had ever run on any push** — installed.
2. **`daily_release` published the recipe digests BEFORE moving the pins**, and a
   pin lives inside the file whose hash the digest is. Every pin-moving release
   therefore named an artefact `bake` would not publish. Fixed by re-publishing
   after the move.
3. **The publish path unpacked two values from a three-value `_sh`**, crashing
   *after* a successful compose — an image was built, exported and pushed, and no
   version was cut. It sat on the one path that executes only when everything
   else has already gone right.
4. **The manifest-refresh files were not in the build context** — `.dockerignore`
   excludes everything under `tools/` except `tools/pdk`.

### Also corrected in the shipped image

`/foss/pdks/versions.txt` is the base image's list and we replace several of the
tools it names. Every image we had published told users the wrong version:

| tool | said | actually ships |
|---|---|---|
| ngspice | 43 | **46** |

| klayout | 0.30.5 | **0.30.10** |

Corrected at compose time by **probing the binaries**, never from a recorded
table — a recorded version is a claim that goes stale on the next pin move,
which is exactly how the defect arose.
