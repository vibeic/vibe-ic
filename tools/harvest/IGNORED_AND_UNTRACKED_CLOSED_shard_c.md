# The 11 rows that rested on an input nobody had measured — and the one below it

`jharv3`, 2026-08-22, on host .108.

Shard C shipped complete at 110 rows with a disclosure attached to 11 of its 19
deletion-bound rows:

> UNTRACKED NOT EXAMINED — READ BEFORE DELETING. The measurement behind this row
> used `git status --porcelain -uno`, which EXCLUDES untracked files, and host .112
> could not be re-reached from .108 to check them.

That was the honest thing to write and it was still a gap: 11 rows authorising
deletion over a domain that could not contain the thing deletion destroys. This
closes it, and finds a second, deeper instance of the same shape one level down.

## The route

`.112` and `.121` refuse a direct `ssh` from `.108` (`Permission denied
(publickey,password)`). `.102` is authorised on both:

    ssh reyerchu@192.168.1.102 "ssh reyerchu@192.168.1.<H> 'bash -s -- <paths>'" < probe.sh

Three read-only probes were piped in over stdin. Nothing was written on either
host — no file, no index, no ref, no fetch.

## The same defect one level down: `-uall` cannot see ignored files either

`--untracked-files=all` was the fix for `-uno`. It reports untracked files. It does
**not** report ignored ones, and `rm -rf` has never read `.gitignore`. So "0
untracked, 0 modified" is, again, a universal over a domain that cannot contain the
thing it is being used to rule out.

Measured: **121 ignored entries** across those 19 directories, present in 17 of
them, and examined by nothing before this. Two of them are not caches:

    vibe-ic-marketplace/scratch_geom_signoff_tests/     30 files, 229433 B  (_smrg_priv/smrg_base)
    …/programs/tests/fixtures/synthetic_benchmark_phase1/  56 files, 197123 B  (wt-j63x8c)

Neither is on main and neither would survive the directory. What makes them safe is
not that they "look generated" — it is that `origin/main`'s own `.gitignore` says
what they are and names what makes them:

| rule on main | main's own words |
|---|---|
| `__pycache__/`, `.pytest_cache/` | bytecode and pytest cache |
| `**/tests/fixtures/synthetic_benchmark_phase1/` | "Test-generated synthetic fixtures (rebuilt by build_synthetic_benchmark_phase1)" |
| `vibe-ic-marketplace/plugins/vibe-ic/reports/` | "Plugin audit reports (generated by plugin_full_audit.py)" |
| `scratch_geom_signoff_tests/` | "session scratch, never committed (ORGANIC #720)" — written by `programs/tests/test_gds_geometry_signoff_wiring.py:280` |
| `docs/reports/` | generated report output |

`bin_jharv3/ignored_accounted.py` asks **git**, not itself: it builds a skeleton from
main's own `.gitignore` files and runs `git check-ignore -v`, so the attribution is
main's. 121 of 121 attributed, 0 unaccounted. Anything outside the table is RED —
"probably a cache" is not a finding, it is a guess.

`--self-test` shows all five guarantees going red on a violating row and green on the
real one: undeclared class, entry main does not actually ignore, deletion-bound row
with no measurement, measured row that is dirty, and the table drifting from main.

## One row's evidence was wrong, and the correction makes the verdict stronger

`/home/reyerchu/wt-j63x8c` (ABANDON) said its twin `jf-63x8-work/base-mml` "is kept"
and that **both** working trees are clean. Measured here:

- the twin is **not clean**: 1640 tracked modifications, 10 untracked files;
- the twin is **in no shard and has no verdict anywhere** — "is kept" was an
  assumption about a path nobody had decided.

The ABANDON stands, on a ground that needs no twin: this directory is clean, so its
whole content *is* its HEAD tree `a9f2edf43` = commit `3ab7fc723e49`, which is
reachable from the live origin branch `jmatrix/63x8-main-reds`.

And the twin turns out to be nothing at all. Its full working state — all 1640
modifications **and** all 10 untracked files together — hashes to tree
`7840974874537d10`, which is exactly the tree of commit `867de428920c`, an ancestor
of `origin/main`. The "untracked" files are old main files main has since deleted.
By name they read as six new tests and a 64 KB new tool; by content they are main's
own history. No rescue ref was needed and none was made.

That is the brief's rule paying for itself: judge by CONTENT.

## A third domain, below both: files the tree HOLDS that main's tip does not

`-uno` misses untracked. `-uall` misses ignored. Both of those are about files git is
not tracking. The third gap is about files it **is** tracking.

The L0 rule behind every LANDED row compares the files the branch OWNS — its diff
against its merge-base. That scope is right, and it is the scope a peer got wrong in
the other direction by walking all 5,256 files and counting main moving on as
unlanded work. But it cannot see a path the worktree holds that main's tip does not
have at all: such a path is in neither the owned set nor the untracked set nor the
ignored set, and `rm -rf` takes it with everything else.

**17 of the 19 deletion-bound rows hold at least one. 17472 paths in total.**

    17471   byte-identical to the same path at the row's merge-base with main
        1   in no commit main contains

The 17471 are main's own content: files that were on main at the merge-base and that
main deleted afterwards. Fifteen rows hold the same ten — `.image-version-ignore`,
`tools/vibeic-eda/sync_image_version.py`, six tests — and `_v1126` holds 17331,
a vendored IP tree main has since dropped. All of it is reachable from origin
forever; deleting those directories loses none of it.

The one exception is `wt-j63x8c`'s `RESULT.md`, which exists at no point in main's
history. It survives the directory only because the whole HEAD commit `3ab7fc723e4`
is contained by the live origin branch `jmatrix/63x8-main-reds` — which is what makes
that row's survivability claim load-bearing rather than decorative. If that branch is
ever deleted, that row stops being safe, and `absent_from_main_accounted.py` goes red
saying so.

`bin_jharv3/absent_from_main_accounted.py`, four guarantees, each shown red:
a version of a main-deleted path that main never had, a HEAD commit missing from the
object store, a deletion-bound row with no measurement, and the clean arm.

Raw: `raw_absent_from_main_shard_c_jharv3.tsv`.

## What this does not cover

- Shards A and B were not measured for ignored content. The same `-uall` blind spot
  applies to their deletion-bound rows and nobody has looked. `ignored_accounted.py`
  is scoped to what was measured and says so rather than passing them quietly.
- `--ignored=matching` lists ignored entries, collapsing a directory to one line. The
  file counts and byte counts here come from walking each of those directories.
